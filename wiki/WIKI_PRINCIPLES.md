# Wiki知识管理原则

> Wiki知识库的构建与维护准则
>
> **定位**: Wiki健康走查机制的核心理论基础
> **维护者**: 尼克·弗瑞
> **基于**: Karpathy LLM Wiki Pattern + Simon Willison Anti-patterns + MECE原则

---

## 一、核心原则（4大支柱）

### 1.1 MECE原则

**Mutually Exclusive（相互独立）** + **Collectively Exhaustive（完全穷尽）**

| 维度 | 说明 | 实践 |
|------|------|------|
| **相互独立** | 同一内容只出现在一个专题 | 不重复归类 |
| **完全穷尽** | 所有内容都有归属 | 无"其他"类模糊分类 |

**检查清单**：
- [ ] 同一内容是否只出现在一个专题？
- [ ] 专题之间是否有明显重叠？
- [ ] 是否有内容无法归入任何专题？
- [ ] 是否有"其他"或"杂项"专题？（应避免）

### 1.2 Surgical Changes原则

**精准修改，只改必要的**

| 维度 | 说明 | 实践 |
|------|------|------|
| **精准归类** | 内容归入最合适的专题 | 不贪多 |
| **就近引用** | 相关内容就近引用 | 不过度链接 |
| **最小变更** | 每次更新只改必要的 | 不"顺便优化"无关内容 |

**检查清单**：
- [ ] 新内容是否归入了最合适的专题？
- [ ] 引用是否足够而非过度？
- [ ] 更新是否只涉及必要的文件？

### 1.3 Goal-Driven原则

**目标驱动，有目的的沉淀**

| 维度 | 说明 | 实践 |
|------|------|------|
| **知识复利** | Wiki是持久复利的知识制品 | 不是每次查询重新发现 |
| **目的明确** | 每个页面的存在都有目的 | 不是为写而写 |
| **可验证** | 页面价值可验证 | 有读者、有引用 |

**检查清单**：
- [ ] 这个页面的读者是谁？
- [ ] 页面解决了什么问题？
- [ ] 如何验证页面的价值？

### 1.4 活文档原则

**文档与知识同步更新**

| 维度 | 说明 | 实践 |
|------|------|------|
| **时效性** | 内容保持最新 | 过期内容标记或归档 |
| **可追溯** | 记录变更历史 | log.md记录维护 |
| **有生命** | 内容持续迭代 | 不是一次性写完就完 |

**检查清单**：
- [ ] 内容是否在3个月内更新过？
- [ ] 是否有过期内容未处理？
- [ ] 是否有孤岛页面（无引用）？

## 二、内容构建原则

### 2.1 页面类型定义

| 类型 | 说明 | 示例 | 归类原则 |
|------|------|------|----------|
| **Entity** | 实体（公司/人/产品） | `nvidia.md` | 客观事实描述 |
| **Concept** | 概念（方法论/理论） | `rag.md` | 抽象理解 |
| **Topic** | 主题（一级分类） | `fintech/` | 按领域划分 |
| **Insight** | 洞察（分析报告） | `insight-20260428-*.md` | 按时间+主题 |
| **Process** | 流程（规范/SOP） | `doc-code-review-mechanism.md` | 可执行性 |
| **Template** | 文档模板 | `templates/PD-产品域说明文档.md` | 可复用文档结构 |
| **Code Example** | 代码样例 | `code-examples/subagent-patterns/` | 可运行代码实现 |
| **Tool** | 工具原型 | `tools/wiki_lint.py` | 实际工作工具 |

### 2.2 页面命名规范

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| **Entity** | `小写-横线.md` | `openai.md` |
| **Concept** | `描述性名称.md` | `rag.md` |
| **Topic** | ` kebab-case/` | `ai-programming/` |
| **Insight** | `insight-YYYYMMDD-关键词.md` | `insight-20260428-simon-willison.md` |
| **Process** | `动名词-名称.md` | `doc-code-review-mechanism.md` |
| **Template** | `{分类代码}-{名称}.md` | `PD-产品域说明文档.md` |
| **Code Example** | `{category}/example-name.py` | `multi-agent-routing/router.py` |
| **Tool** | `{category}/tool-name.py` | `wiki-maintenance/wiki_lint.py` |

### 2.3 归类决策树

```
新内容到达
    │
    ▼
是实体（公司/人/产品）？
    │
    ├─ 是 → 归入 entities/
    │
    └─ 否 → 是概念（方法论/理论）？
              │
              ├─ 是 → 归入 concepts/
              │
              └─ 否 → 是主题（一级领域）？
                        │
                        ├─ 是 → 归入 topics/对应专题/
                        │
                        └─ 否 → 是洞察（分析报告/案例）？
                                  │
                                  ├─ 是 → 归入 insights/
                                  │
                                  └─ 否 → 是流程/规范？
                                            │
                                            └─ 是 → 归入 process/
```

## 三、内容质量原则

### 3.1 内容质量标准

| 标准 | 说明 | 最低要求 |
|------|------|----------|
| **完整性** | 核心要素齐全 | 有摘要、有来源、有关联 |
| **准确性** | 信息真实可靠 | 来源可查证 |
| **可用性** | 读者能理解 | 有实例、有链接 |
| **新鲜度** | 内容保持最新 | 3个月内有更新 |

### 3.2 页面模板

```markdown
# 标题

> 一句话概括核心内容

## 元信息
- **创建时间**: YYYY-MM-DD
- **更新时间**: YYYY-MM-DD
- **类型**: entity/concept/topic/insight/process
- **标签**: #tag1, #tag2

## 摘要
一两句话概括核心内容。

## 详细内容

## 相关页面
- [[相关页面]] - 关联说明

## 来源引用
- [source](url) - 引用说明
```

### 3.3 禁止事项

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| 创建无人访问的页面 | 先有需求再创建 |
| 内容从不更新 | 定期审核和更新 |
| 过度引用（一个页面引用10+其他） | 控制在5个以内 |
| "其他"类模糊分类 | 明确分类或创建新专题 |
| 重复内容 | 合并或删除重复 |

## 四、结构维护原则

### 4.1 目录结构规范

```
Wiki/
├── entities/           ← 实体页（公司/人/产品）
├── concepts/          ← 概念页（方法论）
├── topics/            ← 主题页（一级分类）
│   ├── fintech/
│   ├── ai-native/
│   └── product-management/
├── insights/          ← 洞察页（分析报告）
├── process/            ← 流程页（SOP/规范）
├── code-examples/       ← 代码示例库（可运行代码）
│   ├── concepts/       ← 从Insights转化
│   ├── products/       ← Tony贡献
│   └── backend/       ← Zhongli贡献
├── templates/           ← 文档模板库
│   ├── products/       ← 产品文档模板
│   ├── technical/     ← 技术文档模板
│   ├── logs/          ← 日志类模板
│   └── checklists/     ← 检查清单模板
├── tools/              ← 工具原型
│   ├── wiki-maintenance/
│   └── source-evaluation/
├── sources/           ← 源数据（原始资料）
└── index.md           ← 总索引
```

**命名规范**：
- 目录：`kebab-case`（小写+横线）
- 文件：`kebab-case.md` 或 `YYYY-MM-DD-主题.md`

### 4.2 链接健康原则

| 检查项 | 标准 |
|--------|------|
| **链接可访问** | 无死链 |
| **链接必要** | 控制在5个以内/页 |
| **链接更新** | 文件移动时更新链接 |

### 4.3 过时检测

| 阈值 | 处理方式 |
|------|----------|
| **3个月内** | 正常 |
| **3-6个月** | 标记"待审核" |
| **6个月以上** | 更新或归档 |

## 六、反模式警示

### 6.1 内容反模式

| ❌ 模式 | 问题 | ✅ 正确 |
|--------|------|--------|
| **知识孤岛** | 页面无人引用 | 建立链接，形成网络 |
| **重复建设** | 同一内容多个页面 | 合并到一处 |
| **过度设计** | 专题层级过深(>4层) | 扁平化结构 |
| **命名随意** | 中文标题/大小写混乱 | 统一命名规范 |

### 6.2 维护反模式

| ❌ 模式 | 问题 | ✅ 正确 |
|--------|------|--------|
| **写完不管** | 内容从不更新 | 定期审核机制 |
| **只增不减** | 内容无限膨胀 | 定期清理无效内容 |
| **无标准** | 每个人写法不一 | 遵循页面模板 |
| **闭门造车** | 不参考已有内容 | 先检索，再创建 |
