## 教训内容

**派单接收方必先 4 项实证（候选 #129 防御）**：

1. **任务 ID 清单实证** — grep 派单消息全文，找具体任务 ID（不接受"6 任务"抽象描述）
2. **派单对象一致性实证** — 比对 cron 表 / 任务板 / 派单编号指向（不接受 cron 名 vs 派单编号混淆）
3. **验收标准实证** — grep close 标准 / 截止证据模板（不接受无验收标准）
4. **背景依赖实证** — grep 关联候选（#129 等同根病家族）历史教训

**4 项缺任一 = 候选 #129 同根病命中 = 诚实归零**：

```
派单背景 ✅ 派单对象 ✅ 派单要求 ✅ 派单执行要素 ❌  → 同根病命中
```

**诚实归零动作**：
1. HEARTBEAT.md 立刻落档（派单回执 + 阻塞早报）
2. INC 落档到 `review-logs/incidents/YYYY-MM/`
3. lessons 落档到 `review-logs/lessons/by-agent/nick_fury/`
4. 10:30 早检 sessions_send 派蒙：派单要素缺失，请补发
5. 14:01 截止：诚实归零报告（不冒充 close 完成）
