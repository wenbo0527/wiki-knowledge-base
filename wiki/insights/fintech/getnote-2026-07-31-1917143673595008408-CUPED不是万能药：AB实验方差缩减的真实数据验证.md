前两篇讲完了分流：MurmurHash3分桶、蛇形分配校准、P1用户池预留——5000用户分10组的偏差压到了0%。分得匀了，实验就能跑出可信结论了吗？

不能。

偏差0%只是分流质量及格线。真正的墙在另一头：5000用户分10组，每组500人。500人的样本量，在95%置信度、80%统计功效下，最小可检测效果（MDE）是3.86个百分点——策略得把转化率从5%拉到8.86%以上，才能被统计显著地检出。低于这个阈值的效果，全被随机噪声淹了。

分流解决"分组公不公平"，MDE揭示"样本够不够用"。前两篇解决了前者，这篇直面后者——以及一个被工业宣传忽略的事实：CUPED方差缩减不是万能解药，指标类型决定了它的天花板。

## 一、MDE的墙：分匀了也检不出效果

先回顾一个容易混淆的关系。

分流偏差和MDE是两件完全不同的事。分流偏差衡量的是"各组人数匀不匀"——蛇形分配把偏差压到0.51%，P1用户池预留做到0%。MDE衡量的是"样本量够不够把真实效果从噪声里分辨出来"——500人样本的MDE是3.86个百分点，跟分流偏差无关。偏差0%和偏差8%的两组分流，只要每组人数一样，MDE一模一样。

这个区别意味着：即使分流完美，5000用户下仍然检不出小于3.86个百分点的效果差异。策略如果只提升了2%的转化率，实验跑完P值停在0.12——不是策略没用，是样本量不够分辨。

怎么破？两条路。第一条，加流量——MDE与1/√n成正比，样本量翻4倍，MDE缩一半。但5000用户的场景，往往是业务约束下的全部流量，加不动。第二条，缩减方差——在样本量不变的情况下，把指标的方差压低，等效于放大了样本量。这就是CUPED干的事。

## 二、CUPED：工业宣传说了什么

CUPED（Controlled-Experiment Using Pre-Experiment Data）是微软2013年提出的方法，目前已被字节跳动、Netflix、Booking.com等大型科技公司作为实验平台标配。它的核心思路一句话能说清：用实验前的历史数据预测用户"本来"会怎样，把这个"本来"从实验结果里扣掉，剩下的就是策略的真实效果。

公式长这样：

```
Y_cuped = Y - θ × (X - X̄)
```

- Y：用户在实验期间的真实表现（比如实验周骑了5次）
- X：用户在实验前的历史表现（比如实验前一周骑了4次）
- X̄：所有参与实验用户的历史均值
- θ：最优缩减系数，θ = Cov(Y, X) / Var(X)

这个公式本质上是一元线性回归。用历史数据X预测实验数据Y，θ就是回归斜率，Y_cuped就是回归残差。减掉的不是随便一个数，而是"根据历史表现预测的自然增量"。

举个例子。外卖小哥在实验组，实验周骑了50次，但他历史上每天就骑48次——这50次里有48次是"本来就会骑的"，策略真实贡献可能只有2次。另一边，对照组的懒宅实验周骑了5次，历史上只骑0次——他的5次全是"超常发挥"。不做CUPED，你看到的是50 vs 5，以为策略效果巨大；做了CUPED，变成2 vs 5，发现策略可能还有反向效果。

方差缩减的数学保证很清晰。修正后的方差：

```
Var_new = Var(Y) × (1 - ρ²)
```

ρ是X和Y的相关系数。ρ越高，方差缩减越多。ρ=0.8时，方差缩减36%，等效样本量提升约1.5倍；ρ=0.9时，方差缩减81%，等效样本量提升约5倍。业界常见说法是"方差缩减50-80%，等效样本量提升2-5倍"——对应ρ在0.7到0.9之间，数学上完全自洽。据相关技术文献记载，在1%流量、相对收益0.003的场景下，CUPED可将召回率从35%提升到90%——这里的召回率是检出力的提升，不是方差缩减比例，但检出力提升的前提正是方差缩减有效。

这些数字看起来很美。但有一个前提条件被工业宣传轻描淡写地带过了：**ρ必须高，CUPED才有用。** 而ρ能到多高，取决于指标类型——不是所有指标的历史数据和实验数据都高度相关。

## 三、真实数据验证：颠覆性发现

工业宣传说"方差缩减50-80%"，这个数字在什么场景下成立？用真实数据跑一次就知道了。

实验用Kaggle公开的信用卡欺诈数据集（2000用户），在两种业务场景下分别测了CUPED的方差缩减效果。同一套代码、同一个方法、同一批用户，唯一变量是指标类型。

**场景一：欺诈检测（fraud）**

指标是用户是否发生欺诈（0/1事件）。实验前用用户的历史欺诈率作为协变量X，实验期用实验欺诈率作为Y。结果：


| 方法                | 检出力 | 方差缩减 |
| ----------------- | --- | ---- |
| 普通t检验             | 26% | 0%   |
| CUPED（单协变量）       | 28% | 0.1% |
| CUPED（多协变量）       | 24% | 1.0% |
| DID + CUPED（多协变量） | 24% | 1.1% |


方差缩减0.1%。不是50%，不是80%，是0.1%。CUPED几乎没用。检出力从26%微升到28%，在统计上和不做CUPED没有本质区别。

**场景二：消费金额（consumption）**

指标换成用户的消费金额（连续变量）。同样用历史消费数据做协变量。结果：


| 方法    | 方差缩减  |
| ----- | ----- |
| 普通t检验 | 0%    |
| CUPED | 93.7% |


方差缩减93.7%。等效样本量提升约16倍。这才是工业宣传里说的"CUPED方差缩减50-80%"——甚至更好。

同一套方法，两个场景，方差缩减从0.1%到93.7%，差了近1000倍。这个差距不是CUPED实现的问题，不是参数调优的问题，是指标类型决定的数学天花板。

## 四、指标类型决定上限：为什么CUPED在fraud上没用

回到方差缩减公式：Var_new = Var(Y) × (1 - ρ²)。一切取决于ρ——协变量X和目标变量Y的相关系数。ρ能到多高，取决于指标本身的数学性质。

**0/1事件（fraud、注册、付费转化）的ρ天花板很低。**

欺诈检测的指标是"用户是否发生欺诈"——一个0或1的伯努利变量。用户历史欺诈率（X）和实验期欺诈率（Y）之间的相关性，受制于一个数学事实：协方差主要由"同时为1"的用户贡献。

什么意思？相关系数ρ = Cov(Y, X) / √[Var(Y) × Var(X)]，分子是协方差。对于两个伯努利变量，协方差的核心来源是"历史上有欺诈且实验期也有欺诈"的用户——即X=1且Y=1的那些人。欺诈是低概率事件，p=0.03时，"同时为1"的概率约p²=0.0009——1000个用户里不到1个。协方差的样本量太稀疏，估计噪声大，ρ的实测值自然上不去。

实测验证了这个判断：fraud场景的ρ只有0.03左右，方差缩减1 - 0.03² ≈ 0.1%。这与微软实验平台团队的公开发现一致——他们在某些产品上观察到"超过68%的指标，等效流量提升不到1.05倍"，即CUPED几乎没用。

**连续变量（消费金额、活跃天数、点击次数）的ρ天花板高得多。**

消费金额是连续变量，取值范围从0到数万元。用户历史消费和实验期消费之间的相关性可以很高——消费习惯有惯性，上个月花5000的人这个月大概率也花几千。实测ρ≈0.97（在实验窗口内、未做异常值处理），方差缩减约94%。

连续变量的方差由用户行为的异质性决定——有人月消费10元，有人月消费10万元，这个差异巨大，历史数据能很好地预测。而0/1事件的"方差"只有p(1-p)——用户之间的差异被压缩到了0和1两个值之间，历史数据的预测空间天然受限。

**一句话总结：CUPED的效果上限 = 1 - ρ²，ρ由指标类型决定。连续变量ρ可达0.9+，低概率事件（如p<0.05的0/1事件）的ρ天花板可能只有0.1-0.2。** 这不是方法的问题，是数据的数学性质决定的。业界常见说法"方差缩减50-80%"有一个隐藏前提：你的指标得是连续变量。

## 五、真实数据的补充验证

CUPED验证用的是Kaggle公开的信用卡欺诈数据集（2000用户）。同一批数据还可以验证前两篇的分流结论——之前用的是5000个虚拟用户ID，真实用户ID的分布会不会不一样？


| 算法      | 流量偏差   | 客群最大偏差     | 判定       |
| ------- | ------ | ---------- | -------- |
| 纯hash   | 11.80% | 12.5%（总债务） | △ 超标     |
| 蛇形分配    | 1.25%  | 9.7%（总债务）  | ✓ 通过     |
| 用户池预留P1 | 0.00%  | 6.9%（总债务）  | ✓ 通过（最优） |
| 校准路由C1  | 0.60%  | 9.2%（总债务）  | ✓ 通过     |


纯hash在2000真实用户下偏差11.80%——比5000虚拟用户的8.05%还高。真实用户ID不是均匀分布的，手机号、会员ID、设备标识各有各的模式，哈希碰撞概率比理想随机更高。蛇形分配和P1仍然稳定，批量预分桶方案对真实数据的适应性比纯hash强得多。

但客群均值偏差暴露了一个新维度：即使流量偏差0%的P1，客群最大偏差仍有6.9%。**人数匀了，不代表用户结构匀了。** 流量均匀是第一层，客群均匀是第二层——而CUPED是第三层：即使前两层都做到了，指标类型仍然决定了你能不能检出效果。三层叠加，才是AB实验从"能跑"到"能信"的完整链路。

## 六、附：业务沟通速查

前五段是给工程师和数据科学家看的。但实验结果最终要汇报给业务方——PM、运营、高管。他们不需要懂公式，但需要能判断实验结果可不可信。一个简单的框架：红绿灯法。

**绿灯（建议上线）**：流量健康（SRM检验通过）、用户结构一致、主指标显著（P<0.05）、效果稳定、收益大于成本。**黄灯（再观察）**：流量或客群有一项不健康、显著但效果接近MDE边界、效果震荡——延长实验1-2周。**红灯（停止）**：SRM失衡——立即排查分流代码；长期不显著且效应极小——策略可能真没用。

业务方最容易踩的坑：以为"显著=有价值"（P<0.05只说明差异是真信号，值不值得上线是业务判断）；以为"分流量就是按规则分一下"（50:50跑出47:53，用户结构已经偏了，后续结论不可信）。还有一个关于CUPED的业务认知：如果你的核心指标是0/1事件（欺诈、注册、付费），CUPED几乎没用；如果是消费金额、活跃天数这类连续变量，一般CUPED效果能让实验周期缩短到原来的1/3（consumption场景下甚至能到1/16）。

## 总结

三篇文章串起来，是一条完整的链路：分流算法解决"分得匀不匀"（第一篇），CDP+MA场景下的ID Mapping和正交分层解决"分的是不是同一个人、多实验怎么并行"（第二篇），这篇解决"分匀了能不能检出效果"。

核心结论三条。

第一，分流偏差和MDE是两回事。偏差0%只是分流质量及格线，5000用户下MDE是3.86个百分点——分得再匀，样本量不够就是检不出效果。加流量或缩减方差，二选一。

第二，CUPED方差缩减不是万能解药，指标类型决定天花板。连续变量（消费金额、活跃天数）的方差缩减可达93.7%，等效样本量提升16倍；0/1事件（欺诈、注册、付费）的方差缩减只有0.1%，几乎没用。业界常见说法"方差缩减50-80%"有一个隐藏前提：你的指标得是连续变量。这不是方法的问题，是伯努利变量的协方差天然受限——低概率事件的历史数据和实验数据之间的"同时为1"样本太稀疏，ρ上不去，数学性质决定的，不是调参能改的。

第三，真实数据验证了前两篇的分流结论，同时暴露了新维度。2000真实用户的纯hash偏差11.80%，比5000虚拟用户的8.05%更高——真实用户ID分布不均匀。蛇形分配和P1仍然稳定。但客群均值偏差揭示了一个新问题：人数匀了不代表用户结构匀了。P1流量偏差0%，但总债务的客群偏差有6.9%。流量均匀是第一层，客群均匀是第二层。

AB实验的地基是分流，上层建筑是效果检测。地基稳了，上层建筑才值得盖。但盖完地基不等于上层建筑自动就好了——CUPED是上层建筑的工具，而工具的效果，取决于你拿它去量什么。
