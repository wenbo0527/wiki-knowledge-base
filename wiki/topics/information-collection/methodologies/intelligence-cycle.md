# 情报收集周期 (Intelligence Cycle)

> 情报学的核心方法论，从需求到评估的完整闭环
> 版本: v1.0
> 创建: 2026-05-01

---

## 1. 什么是情报收集周期

情报收集周期是情报学(Intelligence Studies)的核心框架，最早应用于军事和商业情报，后被研究者和投资人广泛采用。

```
核心理念:
├── 情报是持续的循环过程，非一次性活动
├── 每个环节相互关联，形成闭环
├── 反馈机制确保持续改进
└── 最终目标: 支撑决策、减少不确定性
```

## 2. 五步详解

### Step 1: 需求定义 (Requirements)

**核心问题**: 我们需要什么信息？

```
需求类型:

战略需求
├── 定义: 长期方向、重大决策所需
├── 示例: "AI Agent未来3年发展趋势"
├── 时间跨度: 月度/季度
└── 决策影响: 资源配置、战略方向

战术需求
├── 定义: 中期规划、项目推进所需
├── 示例: "竞品最近3个月的技术动态"
├── 时间跨度: 周度
└── 决策影响: 产品路线、项目优先级

执行需求
├── 定义: 具体任务、即时问题所需
├── 示例: "某个开源项目的最新版本特性"
├── 时间跨度: 日度
└── 决策影响: 技术选型、代码实现
```

**需求定义模板**:
```markdown
## 信息需求

### 需求描述
[简洁描述需要什么信息]

### 用途
[这个信息用来做什么决策？]

### 时间窗口
[什么时候需要？]

### 置信度要求
[信息准确度要求多高？]

### 如果缺失
[如果无法获取，后果是什么？]
```

### Step 2: 来源规划 (Source Planning)

**核心问题**: 从哪里获取这些信息？

```
来源类型矩阵:

┌─────────────────────────────────────────────────────────────┐
│                    信息来源光谱                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  公开来源 (OSINT)           半公开           内部来源        │
│  ─────────────────────────  ───────────────  ───────────   │
│  • 新闻媒体                   • 行业报告       • 内部数据   │
│  • 学术论文                   • 专家访谈       • 员工反馈   │
│  • 社交媒体                   • 会议演讲       • 运营日志   │
│  • 政府数据                   • 竞品官网       • 销售数据   │
│  • 专利文件                   • 招聘JD         • 客户访谈   │
│                                                              │
│  获取难度: 低 ─────────────────────────────────→ 高         │
│  独家性:   低 ─────────────────────────────────→ 高         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**来源评估标准**:
| 维度 | 评估问题 | 权重 |
|------|----------|-----:|
| **权威性** | 来源是否可靠？背景是什么？ | 25% |
| **专业性** | 在这个领域是否专业？ | 20% |
| **独立性** | 是否独立第三方？利益相关？ | 15% |
| **时效性** | 更新频率如何？是否及时？ | 15% |
| **历史准确** | 过去的预测/分析准确吗？ | 25% |

### Step 3: 信息抓取 (Collection)

**核心问题**: 如何高效获取信息？

```
抓取方法:

主动抓取
├── RSS订阅: 博客、文章更新
├── 邮件订阅:  newsletters、报告
├── 爬虫: 网页数据、结构化抓取
├── API: 平台数据接口
└── 搜索: 关键词、布尔搜索

被动接收
├── 邮件推送: 关注主题的邮件
├── 社交推荐: Twitter/朋友圈算法
├── 播客: 行业访谈节目
└── 社群: Slack/Discord专家群
```

**RSS抓取最佳实践**:
```python
# 示例: 分层抓取策略
TIER_1_SOURCES = [
    "https://example-high-priority.xml",  # 每日全量抓取
]

TIER_2_SOURCES = [
    "https://example-medium-priority.xml",  # 每周抓取
]

TIER_3_SOURCES = [
    "https://example-low-priority.xml",  # 每两周抓取
]

def fetch_with_priority(url, tier):
    if tier == 1:
        return fetch_full(url)
    elif tier == 2:
        return fetch_last_week(url)
    else:
        return fetch_last_two_weeks(url)
```

### Step 4: 分析处理 (Analysis)

**核心问题**: 如何从信息中提炼洞察？

```
分析层次模型:

Layer 0: 原始保存
─────────────────────────────────────────
- 保存原文/截图
- 记录来源和时间
- 不做任何处理
目的: 保留证据链

Layer 1: 筛选过滤
─────────────────────────────────────────
- 判断相关性和价值
- 打标签分类
- 过滤噪声
目的: 减少信息量

Layer 2: 提炼摘要
─────────────────────────────────────────
- 加粗关键句
- 写执行摘要 (3句话)
- 提取关键数据点
目的: 快速回顾

Layer 3: 关联整合
─────────────────────────────────────────
- 连接已有知识
- 发现模式/趋势
- 形成观点
目的: 知识增值

Layer 4: 输出应用
─────────────────────────────────────────
- 支撑决策建议
- 生成报告/文章
- 制定行动方案
目的: 知识变现
```

**分析方法**:

| 方法 | 适用场景 | 工具 |
|------|----------|------|
| **对比分析** | 竞品对比、方案选型 | 表格、Mermaid |
| **时间线分析** | 事件追踪、趋势发现 | 时间轴 |
| **因果分析** | 问题诊断、根因挖掘 | 5Why、鱼骨图 |
| **PEST分析** | 宏观环境、行业趋势 | 四象限 |
| **SWOT分析** | 战略规划、竞争分析 | 矩阵图 |

### Step 5: 分发应用 (Dissemination)

**核心问题**: 如何让情报发挥作用？

```
分发原则:

正确的情报
├── 给正确的人
├── 在正确的时间
├── 用正确的形式
└── 达到正确的效果

分发矩阵:

                    即时 (突发)    定期 (日/周)    按需 (检索)
──────────────────  ────────────  ────────────  ────────────
个人决策者          飞书私信      日报           知识库
团队                飞书群        周报           Wiki
决策层              摘要卡片      深度报告      咨询

```

### Step 6: 效果评估 (Evaluation)

**核心问题**: 这次情报收集有效吗？

```
评估维度:

及时性
├── 问题: 信息是否及时获取？
├── 指标: 事件发生到获取的时间
└── 目标: 战略级<7天，战术级<3天，执行级<1天

准确性
├── 问题: 信息是否准确可靠？
├── 指标: 多源验证通过率
└── 目标: >80%多源一致

有用性
├── 问题: 信息是否支撑了决策？
├── 指标: 情报被引用次数
└── 目标: 每周至少1次被引用

完整性
├── 问题: 是否遗漏重要信息？
├── 指标: 事后"没想到"的事件数
└── 目标: 季度<2次重大遗漏

效率
├── 问题: 获取信息的成本如何？
├── 指标: 时间成本 vs 价值产出
└── 目标: 持续优化ROI
```

**反馈闭环**:
```
┌─────────────────────────────────────────────────────────────┐
│                    评估反馈循环                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│    情报产出 ──→ 被使用 ──→ 效果如何？                       │
│         ↑              │                                    │
│         │              ↓                                    │
│         │         评估结果                                   │
│         │              │                                    │
│         │              ↓                                    │
│         │         改进方向 ──→ 调整需求定义                  │
│         │                            │                      │
│         └────────────────────────────┘                      │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 5. 常见问题

### Q1: 信息太多，处理不过来？

```
解决方案:
├── 设置TIER分级，只关注TIER_1
├── 使用自动化工具初筛
├── 设定"每篇最多5分钟"原则
└── 只处理与当前项目相关的内容
```

### Q2: 如何判断信息可信度？

```
解决方案:
├── 多源验证: 至少2-3个独立来源
├── 查历史记录: 来源过去的准确性
├── 溯源检查: 原始信息 vs 二手传播
└── 利益分析: 来源是否有利益相关
```

### Q3: 收集的信息如何避免成为死知识？

```
解决方案:
├── 项目驱动: 只收集当前项目需要的信息
├── 定期回顾: 每周回顾新捕获的内容
├── 刻意连接: 主动链接到已有知识
└── 输出倒逼: 设定每周输出目标
```
