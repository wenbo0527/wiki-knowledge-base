### 🏆 核心观点总览

AI Agent正在推动AI从"回答问题"全面走向"完成任务"，存储也随之完成范式升级：从过去仅提供容量、承载文件的资源层，升级为贯穿Agent运行、协作与持续优化的关键**状态底座**。火山引擎存储团队以**Storage Agent Infra**为核心载体，围绕Sandbox Store、Artifact Store、Agent观测&评测三大能力方向重构存储体系，全面适配Agent时代的真实生产业务需求。

### 📊 AI数据Workload的三阶段演进

随着AI应用形态从模型调用、对话式助手逐步进化为具备工具调用、任务执行、环境交互、长期记忆能力的智能体，AI驱动的数据负载也同步完成了三次迭代：

| 发展阶段 | 核心负载特征 | 关键技术要求 | 典型量化指标 |
| :--- | :--- | :--- | :--- |
| **Training（训练）** | 海量、大规模、高吞吐 | 保障数据集加载与Checkpoint写入的性能，避免GPU空转 | 预训练数据集规模达百PiB~EiB级，读写带宽达TB/s级 |
| **Inference（推理）** | 低时延、高并发、KV化、高吞吐 | 优化KVCache的命中率与访问时延，直接影响推理TTFT（首Token时间）、TBT（Token生成间隔）指标 | 时延要求达到毫秒甚至微秒级 |
| **Agent（智能体）** | 场景多元化、批量高负载、可观测/自进化 | 支撑沙箱动态启停、跨沙箱数据共享、全链路Trace溯源，服务于Agent稳定运行与迭代进化 | 面向真实生产业务，场景碎片化特征突出 |

### 🔄 存储范式的根本性跃迁

AI Workload的演变直接驱动存储从传统的**Content Storage**全面进化为**State Storage**，完成从"数据底座"到"状态底座"、从Data Lake到State Lake的升级：

| 范式类型 | 面向数据 | 核心目标 | 典型特征 |
| :--- | :--- | :--- | :--- |
| **Content Storage** | Dataset、文档、图片、视频、日志 | 把内容保存好 | 海量持久化、冷归档、分发，对应成熟的对象存储、并行文件系统范式 |
| **State Storage** | Checkpoint/优化器状态、KVCache/向量嵌入、运行环境/记忆/追踪数据 | 把系统状态维持住 | 短生命周期状态块高速流转、秒级恢复、低成本分叉 |

二者的差异并非仅体现在数据规模，而是在四个维度完成了深度进化：
1.  数据形态：从文件进化为数百MB~数十GB的短生命周期状态块
2.  IO模式：从带宽敏感的顺序批扫进化为延迟敏感的随机流转
3.  SLO要求：从秒级可用进化为毫秒/微秒级不可失
4.  成本结构：从支持冷热分层进化为无"冷"态可退

### 🧩 Agent应用生态的六层架构

从工程视角，Agent应用可抽象为自上而下的六层体系，存储能力贯穿多个核心关键环节：
1.  **L6 应用层**：面向终端用户的Agent App、多Agent编排、业务工作流等产品形态
2.  **L5 声明层**：定义Agent身份、指令、模型、工具、记忆、策略等核心属性
3.  **L4 执行层**：驱动Agent运行的核心循环、调度与守护模块
4.  **L3 能力层**：为Agent接入模型、工具、记忆、沙箱与外部环境
5.  **L2 平台设施层**：支撑多租户运行、可观测、计费与治理
6.  **L1 基础设施层**：计算、存储、网络、安全的底层底座

火山引擎Storage Agent Infra的三大核心方向精准覆盖Agent全生命周期需求：
- **Sandbox Store**：解决Agent"在哪里运行"的问题，提供沙箱环境挂载、快照、启动恢复能力
- **Artifact Store**：解决Agent"读写什么数据"的问题，提供任务产物持久化、共享、分发能力
- **Agent观测&评测**：解决Agent"运行得怎么样"的问题，支撑全链路溯源与持续优化闭环

### ⚙️ 三大核心能力方向深度解析

#### 1. Sandbox Store：沙箱全生命周期的状态底座

沙箱是Agent执行受控任务的核心载体，其背后的状态保存、数据共享与会话通信共同构成Agent Infra的关键层，覆盖沙箱从启动、运行、休眠到唤醒的完整闭环：
- 启动阶段：支持数万元盘并发创建，极速拉起运行环境
- 运行阶段：依托ESSD实现高性能读写，状态实时持久化
- 休眠阶段：通过快照落盘释放算力，按需回收资源，整体成本降低约90%
- 唤醒阶段：基于Lazyload按需加载，秒级恢复运行上下文

火山引擎采用三类存储产品分层协同覆盖沙箱的三大核心场景：
| 场景需求 | 对应存储产品 | 核心能力 |
| :--- | :--- | :--- |
| 通用沙箱rootfs场景 | EBS弹性块存储 | 快速批量创建、高频快照、延迟加载恢复、强隔离数据保护，支持Agent随时保存状态、回退任意步骤 |
| 多Agent并行实验、共享工作区场景 | EFS弹性文件存储 | 完整POSIX语义、弹性扩展、目录级隔离配额，支撑多沙箱协同访问共享数据集与中间结果 |
| 多Agent协作通信场景 | MQ LiteTopic | 会话级强顺序隔离、百万级Topic动态调度，支撑长会话高并发交互链路 |

#### 2. Artifact Store：Agent全链路数据流转入口

Artifact Store承接Agent执行过程中所有输入输出数据，覆盖从强POSIX高性能读写到灵活公网分发的全场景需求：
- 面向强POSIX语义场景：EFS提供亚毫秒级访问时延、最高3000万IOPS与2TB/s突发带宽，适配git clone、tar解压等小文件密集场景，同时通过数据流动自动将冷数据沉降至TOS，兼顾性能与成本
- 面向灵活分发场景：TOS对象存储依托近乎无限的横向扩展能力，单桶可承载亿级对象，天然适配Agent产物"平时平稳、任务突发"的访问特征，配合多档存储类型将长期留存成本降至最低

针对亿级Agent生产级应用需求，火山引擎推出**Agent Bucket**：在传统Bucket→Object两层模型中新增AI原生层级ObjectSet，无需自建复杂中间层即可为海量终端用户提供安全隔离、配额管控的专属存储空间。在此基础上延伸出两大智能化能力：
- **SenseFlow**：多模态理解处理引擎，数据不出桶即可完成内容感知、智能检索与生成，让静态文件转化为可消费的数据资产
- **ContextBucket**：收敛Agent长期记忆与工作区，实现"记得住、找得到、带得走"，支撑跨任务跨会话的上下文沉淀
- **ADrive智能网盘**：专为Agent与人协同设计，支持产物持久化共享、亿级租户隔离、多端同步访问、自然语言智能检索，构建人机协作的统一工作空间闭环

#### 3. Agent观测&评测：驱动Agent持续进化的数据飞轮

Agent运行结果无法通过固定规则判定，必须依托全链路数据完成观测、分析与迭代。火山引擎**TLS AgentLoop**基于日志服务TLS构建完整闭环：
1.  接入层：支持Agent、生态框架通过标准协议快速接入观测数据
2.  观测层：提供指标大盘、会话分析、Trace调用链分析能力
3.  沉淀层：完成观测数据回流与加工处理
4.  评测层：打通评测集、评估器、评估实验全流程

这套体系将Agent从"黑盒结果"转化为可分析的数据资产，帮助研发团队定位版本效果差异、平台团队发现系统瓶颈、业务团队持续优化任务完成质量，同时支撑Ops Agent实现运维工作流的智能化演进。

#### 4. Storage Agent Family：从存储系统到协作队友

火山引擎进一步提出智能存储助手体系，围绕TOS、EBS、EFS、TLS、MQ等产品构建专属Agent家族，提供四类专家能力：
- 智能运维专家：自动完成健康巡检、异常诊断、生成修复建议
- 数据洞察专家：分析访问模式、自动冷热分层、优化存储成本
- 方案检索专家：智能检索最佳实践、完成多模态日志总结
- 安全围栏专家：实现风险分级管控，高危操作引入人工审核机制

这套体系让存储不再只是被Agent调用的资源，而是进化为与人和Agent并肩协作的智能Teammate，在使用过程中持续沉淀知识、越用越智能。

### 🎯 真实业务落地场景

三大核心能力已在三类典型Agent生产场景中完成落地验证：
1.  **研发测试类Agent**：依托EBS高频快照、超长快照链能力，在代码变更时自动记录沙箱状态，支持任意历史版本回退、切换分支重跑，大幅降低试错成本
2.  **多模态创作类Agent**：基于Agent Bucket on TOS构建输入输出资产库，所有素材沉淀后可直接通过公网分发，支撑多模态内容生产的全链路资产化管理
3.  **智能办公类Agent**：通过ADrive实现用户私有空间与Agent协作空间的双隔离，支持团队共享访问与自然语言检索，构建人机协同的统一办公空间

### 💡 关键洞察

Agent时代存储的价值坐标已经彻底重构：衡量存储基础设施的标准不再是单点的容量、带宽或时延，而是能否在Agent完整生命周期中全程在场——环境秒级拉起恢复、产物可理解可检索可记忆、运行过程可观测可评测可反哺。Storage Agent Infra通过重新编排各类存储产品能力，让离散的存储介质凝聚为"理解任务、承接状态、参与闭环"的有机整体，最终实现从"更大的Data Lake"到"更懂业务的State Lake"的深层跃迁。
