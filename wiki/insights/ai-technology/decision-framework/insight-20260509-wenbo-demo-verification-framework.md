# Demo验证框架 v1.1

> 版本: v1.1（基于v2.0挖掘流程 + 行业最佳实践）
> 创建: 2026-05-09
> 来源: 文博隐性知识挖掘

---

## 核心能力

用可交互的Demo加速验证周期，同步校验需求文档，减少业务和研发的沟通误解。

---

## 框架流程

```
需求拆解 → 功能规划 → 时间盒 → Coding → Demo → 开会 → 公网访问 → 灰度验证
```

| 步骤 | 说明 | 关键动作 |
|------|------|---------|
| **需求拆解** | 将需求拆解成功能点 | 识别可独立验证的模块 |
| **功能规划** | 规划Demo的验证范围 | 聚焦核心交互 |
| **时间盒** | 设置明确的完成时间 | 避免完美主义 |
| **Coding** | vibe coding实现 | Trae从0到1，OpenClaw处理组件 |
| **Demo** | 生成可交互原型 | 业务向：全交互；技术向：半交互 |
| **开会** | 演示+收集反馈 | 确认方向+记录问题 |
| **公网访问** | 提供持久化链接 | 业务和研发可随时查看 |
| **灰度验证** | 小范围用户试用 | 验证真实价值 |

---

## 关键原则

### 1. 时间盒标准

| 需求类型 | 时间盒 | 说明 |
|---------|--------|------|
| **大需求** | 2天 | 复杂交互，涉及多模块 |
| **中等需求** | 1天 | 标准页面/表单 |
| **简单复刻** | 2-4小时 | 已有模式的复用 |
| **技术向** | 不设硬性时间 | 以"能说明问题"为准 |

**规则**：到时间就停，不管完成度。剩余内容下次迭代。

### 2. 灰度验证

| 阶段 | 内容 |
|------|------|
| **小范围试用** | 先给10-20个用户试用 |
| **收集反馈** | 关注使用路径、问题、建议 |
| **判断继续/回滚** | 数据支持继续全量，否则回滚调整 |
| **全量发布** | 验证通过后再全量 |

**价值**：业务和研发说好 ≠ 用户真的喜欢。真实数据比主观判断更可靠。

### 3. 技术向Demo标准

| 类型 | 工具 | 说明 |
|------|------|------|
| **模拟数据展示** | Excel/截图 | 用模拟数据说明流程 |
| **流程录制** | 屏幕录制 | 展示完整操作路径 |
| **截图+注解** | PPT/图片 | 分步骤说明 |
| **半交互Demo** | Notion/Figma | 可点击但不连后台 |

|---------|------|------|------|

| 中小需求 | 1-2周 | - | - |

## 核心价值

1. **验证周期大幅缩短**：4x提速
2. **需求文档同步完善**：Coding过程反补思考
3. **减少业务和研发误解**：可交互Demo比文档更清晰

---

## 适用边界

| 场景 | 适用性 | 说明 |
|------|--------|------|
| **业务向** | ✅ 适用 | 流程、交互、表单、页面 |
| **技术向** | ⚠️ 有限适用 | 实验分析、数据侧 |
| **维护期** | ❌ 不适用 | 小修小补不需要Demo |

```
    ↓

    ↓
[产品升级] / [技术选型] → 执行
```

## 案例：营销画布可拖拽前端

**流程**：
1. 需求拆解 → 功能点规划
2. Coding（Trae从0到1）
3. Demo完成 → 开会
4. 提供持久化公网访问

**结果**：
- 验证周期从月→周
- 需求文档同步完善
- 业务和研发误解减少
