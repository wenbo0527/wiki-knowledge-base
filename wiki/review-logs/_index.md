# 📖 Review Logs 使用指南

> Agent团队问题记录与经验沉淀规范
> 版本: v1.0 | 更新: 2026-05-07

---

## 1. 核心理念

| 理念 | 说明 |
|:---|:---|
| **Blameless** | 记录问题是为了改进系统，不是找责任人 |
| **及时记录** | 发现问题立即记录，不要依赖记忆 |
| **闭环追踪** | 每个问题都要有结果，不能石沉大海 |
| **经验复用** | 沉淀为Lessons，供其他Agent参考 |

---

## 2. 记录类型

| 类型 | 用途 | 文件前缀 |
|:---|:---|:---|
| **Incident** | 记录遇到的问题 | `inc_` |
| **Lesson** | 沉淀的经验教训 | `les_` |
| **Review** | 周期性复盘（如周报） | `rev_` |

---

## 3. 记录时机

### 必须记录的场景

| 场景 | 类型 | 时机 |
|:---|:---|:---|
| 发现新问题 | Incident | 立即 |
| 问题已解决 | Lesson | 解决后的24h内 |
| 每周复盘 | Review | 每周日22:00 |
| 月度复盘 | Review | 每月最后一天 |

### 记录前置确认

```
记录 Incident 前，先问自己：
  1. 这个问题会影响其他人吗？
  2. 这个问题可能会重复发生吗？
  3. 从这个问题能学到什么？

  如果以上任一为"是" → 记录
  如果都是"否" → 可选记录
```

## 4. 记录流程

### Incident 流程

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 发现问题                                          │
│  → 在 incidents/YYYY-MM/ 创建 inc_YYYY-MM_NNN.md           │
│  → 填写基本信息（级别、发现者、状态=Open）                   │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 2: 通知相关Agent                                     │
│  → 在_feishu 或对应Agent的session中通知                     │
│  → 说明问题、影响、期望谁来解决                             │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 跟踪进展                                          │
│  → 更新 incident 的"最后更新"时间                           │
│  → 记录已尝试的措施（不要删除失败的尝试）                   │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 4: 问题解决                                          │
│  → 更新状态为 Resolved                                     │
│  → 移动到 incidents/resolved/ 目录                         │
│  → 沉淀 Lesson                                             │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 5: 更新注册表                                        │
│  → 更新 _registry.md                                       │
│  → 确保状态一致                                            │
└─────────────────────────────────────────────────────────────┘
```

### Lesson 流程

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 判断是否值得沉淀                                   │
│  满足以下任一条件 → 值得沉淀：                              │
│    ✅ 问题花了超过1小时才解决                               │
│    ✅ 涉及多个Agent协作                                     │
│    ✅ 有可复用的经验教训                                    │
│    ✅ 文博明确要求记录                                      │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 2: 撰写 Lesson                                        │
│  → 在 lessons/by-agent/{agent_name}/ 创建 les_xxx.md       │
│  → 关联对应的 Incident（如果有）                           │
│  → 重点写"正确做法"和"复用建议"                            │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  Step 3: 审核（如需要）                                    │
│  → 重要Lesson → @文博 审核                                 │
│  → 一般Lesson → 自己审核即可                               │
└─────────────────────────────────────────────────────────────┘
```

## 5. 严重级别定义

| 级别 | 标识 | 定义 | 处理时限 |
|:---:|:---:|:---|:---|
| **Critical** | 🔴 | 影响核心功能/数据丢失风险 | 即时通知，1小时内解决 |
| **High** | 🟠 | 影响主要功能，但有 workaround | 2小时内解决 |
| **Medium** | 🟡 | 影响部分功能，不阻塞主流程 | 24小时内解决 |
| **Low** | 🟢 | 体验问题/优化建议 | 有空时处理 |

---

## 6. 状态定义

| 状态 | 说明 |
|:---|:---|
| **Open** | 待处理，需要跟进 |
| **In Progress** | 有人正在处理 |
| **Blocked** | 遇到阻塞，需要帮助 |
| **Resolved** | 已解决，等待沉淀 |
| **Closed** | 已沉淀，完成归档 |

## 8. 命名规范

### 文件命名

```
# Incident
inc_{发现日期YYYY-MM-DD}_{序号NNN}.md
示例: inc_2026-05-07_001.md

# Lesson
les_{沉淀日期YYYY-MM-DD}_{序号NNN}.md
示例: les_2026-05-07_001.md

# Review
rev_{类型}_{周期}_{日期}.md
示例: rev_weekly_2026-W19.md
```

### Frontmatter 命名

```yaml
---
id: inc_2026-05-07_001
type: incident
severity: 🟠 High
status: Open
discovered_by: nick_fury
discovered_at: 2026-05-07 09:15
---
```

## 9. 快速参考

### 创建 Incident 的快捷命令

```markdown
1. 复制模板: `_template_incident.md`
2. 填入基本信息
3. 命名: `inc_YYYY-MM-DD_NNN.md`
4. 放入: `incidents/YYYY-MM/`
5. 更新: `_registry.md`
6. 通知: 相关Agent
```

### 创建 Lesson 的快捷命令

```markdown
1. 复制模板: `_template_lesson.md`
2. 填入经验内容
3. 命名: `les_YYYY-MM-DD_NNN.md`
4. 放入: `lessons/by-agent/{agent_name}/`
5. 更新: `_registry.md`
```
