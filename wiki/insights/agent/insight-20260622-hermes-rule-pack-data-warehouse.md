## 一句话洞察

> **"规则包 (Rule Pack)" 是 Hermes Agent 在得物数仓场景的核心创新——把"老同事才知道"的埋点经验沉淀为可执行检查清单，形成"知识复利效应"。这套机制 = 我们 SKILL.md 系统的工程化升级模板。**

---

## 一、问题域：传统埋点的 3 大痛点

| 痛点 | 表现 | 业务影响 |
|:---|:---|:---|
| **口径不一致** | 不同人对同一指标定义不同 | 数据失真，决策风险 |
| **规则记忆困难** | 历史规则靠人脑记忆 | 离职即失传，新人重踩坑 |
| **信息碎片化** | 需求散落文档/对话/系统 | 整合效率低，需求响应慢 |

**核心矛盾**：埋点需求是"一次性响应"，但埋点知识是"可复用资产"——传统流程把两者混为一谈，导致每次都从零开始。

---

## 二、解法：Hermes 四类核心资产

得物团队用 Hermes Agent 构建了 4 类核心资产：

| 资产 | 核心功能 | 价值定位 | 类比 Nick 团队 |
|:---|:---|:---|:---|
| **工作区 (Work Zone)** | 需求上下文一键沉淀 | 多轮状态保持 | Nick/钟离/托尼 session |
| **看板 (Dashboard)** | 状态机流转透明 | 进入→设计→预演→评审→交付 | Paimon 任务板 |
| **⭐ 规则包 (Rule Pack)** | 历史经验资产化 | 新需求自动关联历史口径 | SKILL.md 系统 |
| **结构化工具接口 (Tool Interface)** | AI 调用规范化 | 高风险动作人工确认 | 工具白名单机制 |

**最值得借鉴的是"规则包"**——把"老同事才知道"的判断写成可执行检查清单。

---

## 三、四步判断准备流程（工程化准备者）

Hermes Agent 定位 **"判断前的工程化准备者"**，AI 与人分工清晰：

```
材料收齐 → 历史找出 → 风险预演 → 过程留存
   ↓          ↓          ↓          ↓
 PRD/飞书    历史埋点    diff/dry   确认点/
 会议纪要    指标口径    run模拟    变更原因
```

| 步骤 | AI 负责 | 人工负责 |
|:---|:---|:---|
| 材料收齐 | ✅ 多源梳理 | 业务语义确认 |
| 历史找出 | ✅ 自动检索 | 口径定义 |
| 风险预演 | ✅ diff/字段审计 | 敏感字段审核 |
| 过程留存 | ✅ 自动记录 | 生产放行决策 |

**关键设计**：AI 不替代人决策，而是把决策前的工作全部准备好——避免"黑箱决策"风险。

---

## 四、三道治理门（风险防控核心）

| 治理门 | 作用 | 类比我们的治理 |
|:---|:---|:---|
| **事实源门** | 需求可追溯到原始材料 | INC 报告链 |
| **预演门** | 系统模拟验证（dry-run）| Cron 自动监督 |
| **责任门** | 人工确认留痕 | 文博拍板 |

**这套机制 = 我们 OpenClaw 治理 v2.0（Standing Orders + Cron + Tasks + Sessions + Hooks）的应用实例**。

## 六、可迁移能力设计（5 契约）

得物总结的可迁移能力 5 契约：

| 契约 | 含义 | 我们 SKILL.md 现状 |
|:---|:---|:---:|
| **输入** | 触发条件明确 | ⚠️ 部分缺失 |
| **边界** | 适用范围清晰 | ⚠️ 部分缺失 |
| **输出** | 期望结果可验证 | ✅ 基本齐全 |
| **失败处理** | 异常降级路径 | ❌ 多数缺失 |
| **经验回写** | 用后优化闭环 | ❌ 多数缺失 |

**行动建议**：Nick/钟离/托尼的 SKILL.md 应补全"失败处理"和"经验回写"两字段——这是 Hermes 规则包的核心思想。

## 七、方法论映射（6 大方法论 × 得物案例）

| 方法论 | 得物应用点 |
|:---|:---|
| **技术理解** | Hermes vs OpenClaw 选型：选 Hermes 因分层记忆+技能沉淀 |
| **需求决策** | 单 Agent+能力模块 编排（vs 多 Agent 拆分） |
| **产品设计** | 四类核心资产 = AI 数据产品的产品化设计 |
| **数据驱动** | 三道治理门 = 数据治理闭环 |
| **价值闭环** | 人力节约 70% + 规则复用 +80% 量化 |
| **风险防控** | 单 Agent 编排 + 状态机 + 工具接口 |
