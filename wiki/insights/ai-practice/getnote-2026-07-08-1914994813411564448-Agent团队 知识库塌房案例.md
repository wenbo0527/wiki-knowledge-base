📕 故事 A · 派蒙空 Chroma vs Tony 真 Chroma（最早也最经典）

2026-05-26 → 05-28 · 派蒙差点被自己人骗了

- 我自己起了一个 Chroma，绑在 0.0.0.0:8082，但 chroma_data/ 是空的

- Tony 真正的 Chroma 在 /System/Volumes/Data/.../Tony/knowledge_base/vector_db/ · 215MB / 9,411 chunks

怎么发现：文博问"你昨天回复的 Chroma 绑定细节" → 我自己 grep 才看出来我自己起的就是个空壳  
  
教训：路径 + 端口 + 数据 三件套必须三对齐，光看服务在跑就以为 OK = 假象

📕 故事 B · 首次索引从未成功完成（2026-05-26 ~ 05-29）

📕 故事 D · "服务在线 = 真相假象"（2026-07-07 实证 · 最新最狠）

7/7 15:28 实测，保活检查全 OK，但实际数据管道已经6 周没新增

塌房现场（健康检查全部绿，但底下全烂）：


| 检查项            | 结果                    | 真相                      |
| -------------- | --------------------- | ----------------------- |
| HTTP /health   | ✅ {"status":"ok"}     | API 进程在                 |
| 进程 PID 6691    | ✅ 启动 2026-07-01 15:43 | 跑着                      |
| 端口 8082 LISTEN | ✅                     | TCP 在听                  |
| /search 端点     | ✅ 返回真实结果              | 还能搜                     |
| POST /index    | ❌ 全 404               | API 设计就不支持在线重建          |
| knowledge.db   | ❌ 0 字节                | SQLite 通道未启用（chroma 在用） |
| 内容管道           | ⚠️ 6 周无新增             | 没人喂数据                   |
| 索引管道           | ⚠️ 5 天未动              | dirty=0 但 chunks 不增     |


派蒙判断：服务在线 ≠ 真在用。HTTP 200 给的安全感是假象。  
  
教训：健康检查只能查"活没活"，不能查"准不准 / 新不新 / 能不能用" —— 这是派蒙 7/7 写的"等文博/Tony 决策是否介入"

📕 故事 E · T3' v1.1 L2 regex 假阳性塌房（2026-06-24 ~ 06-26 · 5 个 INC 串成链）

不是知识库本身，是检测知识库工具能力的脚本塌房——但塌法很典型，写 INC 5 次都没根治


| INC                | 现象                      | 根因                          |
| ------------------ | ----------------------- | --------------------------- |
| INC-2026-06-24-001 | v1.1 退路 A regex 误报      | "tools":[[^]]*] 贪婪到第一个 ]    |
| INC-2026-06-25-001 | L2 检测 15 false positive | 同上，5 agent × 3 tools 全 fail |
| INC-2026-06-25-002 | 假阳性仍激活                  | cron payload 没换 spec        |
| INC-2026-06-25-003 | 改成 inline + head -10 修复 | 7/15 false negative（又翻车一次）  |
| INC-2026-06-26-002 | 退路 A head -10 实证失败      | head -10 看不到 pm 刚启 session  |


真相：L1 + L3 全 PASS，工具实际能用，只是检测脚本写错了  
  
最终方案：v1.2b = 取近 5 个 session 全部内容 + tool name grep → 15/15 PASS ✅  
  
教训：检测塌房比真实塌房更坑——会让你以为世界末日其实啥事没有

🎯 派蒙反思三条（写进 MEMORY 的）

"cron + 健康检查 + 路径对齐 SOP, 缺一就翻车"  
"服务在线 ≠ 真相 · 数据更新 ≠ 索引健康"  
"自动机制 ≠ 自动成功 · 兜底命令必留"
