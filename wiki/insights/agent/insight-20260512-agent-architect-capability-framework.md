## 一、技术筛选五维评估框架

| 评估问题 | 判断标准 | 示例（高价值 vs 低价值） |
|:---|:---|:---|
| **半年后是否重要** | 属于包装层还是底层能力 | 协议设计（高） vs 模型封装层（低） |
| **能否接入现有系统** | 是否兼容日志/权限/部署体系 | 接口标准化工具（高） vs 独立SDK（低） |
| **解决什么失败模式** | 生产环境痛点还是Demo新鲜感 | 状态恢复机制（高） vs 特效展示（低） |
| **能否被评估验证** | 可通过trace和样本量化效果 | 准确率提升（高） vs "更智能"体感（低） |
| **延迟采用损失** | 系统能力沉淀优先级 | 沙箱隔离（高） vs CLI参数优化（低） |

### 关键洞察

> 模型榜单、Agent SDK、Demo产品等半衰期短（<6个月），而**协议、状态管理、评估体系**等底层能力半衰期长

## 二、上下文：运行时工作集管理

### 上下文分层架构

| 层级 | 承载内容 | 管理策略 |
|:---|:---|:---|
| **模型窗口** | 当前目标、关键约束、决策信息 | 动态筛选 |
| **会话状态** | 任务计划、已完成动作、错误记录 | 结构化存储，支持回溯与压缩 |
| **文件/数据库** | 代码、文档、可回放事实 | 按需检索，避免全量加载 |
| **项目规范** | AGENTS.md、验收标准、团队约定 | 静态缓存 |
| **工具层** | 检索、验证、权限受控动作 | 结果分页，仅返回关键摘要 |

## 三、工具：业务接口化设计

### 高质量工具的核心特征

| 特征 | 说明 |
|:---|:---|
| **数量精简** | 5-10个边界清晰的工具优于20个重叠工具 |
| **描述精准** | 明确工具适用场景、参数格式、返回结构及错误处理 |
| **安全可控** | 危险操作需权限分级、二次确认 |

## 四、评估：从体感到系统化验证

### 场景化评估指标

| 业务场景 | 关键评估信号 |
|:---|:---|
| **编程Agent** | 代码保留率、测试通过率、返工次数 |
| **客服Agent** | 问题解决率、转人工率、用户追问次数 |
| **数据分析Agent** | SQL执行成功率、图表采用率 |
| **运维Agent** | 告警恢复率、误操作率、MTTR |

## 五、状态：超越窗口的持久化管理

| 状态类型 | 存储位置 | 核心价值 |
|:---|:---|:---|
| **当前推理状态** | 模型窗口 | 支持实时决策 |
| **任务进度** | Session/Checkpoint | 实现断点续跑 |
| **可回放事实** | 文件系统/数据库 | 保障可追溯性 |
| **团队经验** | AGENTS.md/Skill库 | 沉淀复用知识 |
| **用户偏好** | 记忆模块/画像系统 | 优化个性化体验 |

## 六、多Agent：边界优先于角色

### Subagent适用原则

- **上下文隔离**：将搜索、验证等探索性任务放入子Agent
- **读写控制**：子Agent优先只读模式，仅返回结论与证据
- **依赖管理**：强依赖任务串行，独立任务可并行

### 落地建议

> 默认从单Agent起步，待上下文压力、工具延迟等问题实际出现后，再引入Orchestrator-Subagent架构

## 七、可延后关注的技术

| 技术 | 原因 |
|:---|:---|
| **包装层框架** | 仅提供模型/工具封装 |
| **复杂记忆系统** | 在上下文分层未完善前优先级低 |
| **多角色Agent** | 在上下文与读写边界未明确时易协同混乱 |
| **公开Benchmark** | 无法替代真实业务场景评估 |
| **模型追新** | 建议按季度评估模型升级 |

## 八、认知更新

### 旧认知
- 追逐最新工具和框架
- Agent能力 = 模型能力

### 新认知
- **优先沉淀跨模型/框架的底层工程能力**
- Agent质量取决于**模型 + Harness组合**
- 系统能力半衰期长，应作为团队资产重点沉淀
