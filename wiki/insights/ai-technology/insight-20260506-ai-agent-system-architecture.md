### **🏗️ Harness：容易被忽视的底座（核心框架）**

#### **(一) 定义与本质**
- **核心定位**：Harness是AI智能体的**运行时控制层**，负责连接模型（大脑）、Agent（身体）和Skills（标准），实现**稳定、可控的连接**。
- **功能本质**：解决"模型能聊但做不了事"的关键问题，通过权限控制、工具调度、任务恢复和Agent通信等机制，将模型能力转化为可执行、可约束的输出。
- **命名来源**：源自Anthropic在Claude Code技术博客中的"马具"比喻，强调对模型能力的引导与控制。

#### **(二) 核心管理范畴**

通过对比Claude Code和Hermes Agent的配置实现，Harness主要管理四大核心问题：

| 管理维度 | Claude Code 实现特点 | Hermes Agent 实现特点 |
| :------- | :------------------- | :------------------- |
| **权限控制** | pattern-based权限白名单，工具名+参数模式匹配 | 工具分组(toolsets)，按平台单独开关，危险命令由独立AI模型审批 |
| **工具调度** | hooks（preToolUse、postToolUse）+ MCP servers | SQLite任务账本，支持子任务恢复与父任务追溯 |
| **记忆管理** | 简化设计，隐藏复杂度 | OTEL全链路追踪，50+项自诊断，操作可观测 |
| **安全机制** | 弹框确认非白名单操作 | 并发审批带线程锁，不暴露原始Prompt |

#### **(三) 与Context的关键关系**
- **Context定义**：Agent"此刻知道什么"，包括文件内容、对话历史、Skills指令、搜索记忆等。
- **Harness的Context管理职责**：
  1. 启动时自动注入项目规则和偏好
  2. 任务触发时匹配Skill并加载指令（渐进式披露）
  3. 跨会话时通过记忆检索注入相关片段
  4. Context快满时触发压缩，保护最近N条对话

- **Agent与Chatbot的本质区别**：
  - Chatbot："输入一段话，输出一段话"
  - Agent："理解意图→检查权限→加载Context→执行动作→观察结果→更新记忆→调整策略"的闭环，该闭环通过Harness实现稳定运转。

### **🧠 大脑：模型的选择（能力基础）**

#### **主流模型能力对比**

当前模型市场呈现多强竞争格局，各模型在能力边界上存在交叉，尚无"全能解"：

| 模型 | 核心优势 | 适用场景 |
| :--- | :------- | :------- |
| **DeepSeek V4 Pro** | 开源阵营顶级复杂推理与Agent能力 | 复杂任务处理、Agent系统构建 |
| DeepSeek Flash | 成本与延迟优势 | 高频简单任务 |
| Kimi K2.6 | 长上下文与工程工作流 | 文档处理、工作流自动化 |
| GLM-5.1 | 均衡与工程化能力 | 通用场景 |
| Qwen 3 | 均衡与工程化能力 | 通用场景 |
| MiniMax M2.7 | 语音与多模态差异化 | 多模态交互 |

#### **选型原则**
- 核心策略："什么任务用什么模型"，而非追求单一"最强模型"
- 灵活性：模型作为可替换零件，可通过配置层快速切换

### **🤖 身体：Agent的选择（执行载体）**

#### **三大品类及代表产品**

Agent市场形成三类互补定位：

| 品类 | 代表产品 | 核心特点 | 适用场景 |
| :--- | :------- | :------- | :------- |
| **终端编程Agent** | Claude Code | 命令行和Plan Mode见长，擅长先规划后执行 | 多文件重构、架构设计 |
| **自主Agent** | Hermes Agent | 7×24后台运行，持久记忆，cron调度，主动交互 | 消息处理、定时周报、跨平台自动化 |
| **IDE编程Agent** | Cursor、Cline | 嵌入编辑器，视觉反馈快，代码库交互直观 | 轻量重构、深度编程 |

#### **协同策略**

品类间非替代关系，可组合使用：重规划任务用Claude Code，日常迭代用Cursor，后台自动化用Hermes。

### **📏 标准：Skills的选择（输出规范）**

#### **核心价值**
- **输出标准化**：通过SKILL.md定义任务格式、流程和标准，确保AI输出专业、稳定、可预期
- **合规适配**：将"AI生成内容"转化为"可直接提交合规部门的正式报告"（如金融业风险披露格式）
- **数字化资产激活**：封装现有服务化能力（量化模型、风控规则等），使Agent可直接调用

#### **来源类型**
- 手写：人工定义规则
- 社区：共享模板
- 自进化：Agent通过重复任务半自动生成并优化

### **🔄 自进化：当Agent开始互相学习（系统升级）**

#### **自进化模式**
1. **单个Agent自进化**：
   - Claude Code：人工发现规律→手写SKILL.md
   - Hermes：通过重复任务半自动生成Skill并逐步优化

2. **多Agent协同进化**：
   - **典型架构**：Claude Code（执行层）←→ Hermes Agent（记忆层），通过Harness桥接（hooks + shared memory + Skills）
   - **核心机制**：每次产出成为下次输入的养分，形成知识闭环
   - **进化表现**：积累Bug模式库→关联根因→生成预防规则→减少重复错误

### **🧩 拼图完整之后（总结与趋势）**

#### **核心结论**
1. **模块化思维**：模型、Agent、Skills是独立可选零件，可根据需求替换
2. **Harness决定可用性**：权限粒度、审批机制、任务恢复能力、Agent通信等硬指标决定实际体验
3. **系统协同价值**：Agent间对话会生长出设计之外的能力，从工具组合升级为有机系统

#### **行业趋势**
- **模型商品化**：选择增多，切换成本降低（DeepSeek/Kimi/GLM/Qwen等）
- **Agent品类收敛**：终端、IDE、自主三大品类格局逐渐清晰
- **Skills生态增长**：可复用模板增多，编写门槛降低
- **上下文独特性**：项目结构、团队规范、决策偏好等私有上下文成为核心竞争力，Harness作为"长在自己土壤里"的底座，承载这些独特价值

### **📝 补充细节**
- **关键术语解释**：
  - **MCP servers**：工具调用协议服务器，负责工具抽象与接口定义
  - **OTEL**：OpenTelemetry，开源可观测性框架，用于分布式追踪
  - **渐进式披露**：Skills的匹配加载机制，不匹配的指令不加载，避免浪费Context
- **Harness与Agent的关系**：Harness可能独立存在或内嵌在Agent内部，但职责一致；Agent负责决策生成，Harness负责执行约束与调度
