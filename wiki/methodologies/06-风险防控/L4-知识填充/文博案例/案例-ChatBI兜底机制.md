## 一、项目背景

### 1.1 项目信息

| 字段 | 内容 |
|:---|:---|
| **项目名称** | ChatBI（对话式BI） |
| **公司** | 某金融机构 |
| **时间** | 2024年 |
| **类型** | AI Agent产品 |
| **核心能力** | 自然语言问数、智能分析 |

### 1.2 业务挑战

| 挑战 | 说明 |
|:---|:---|
| **问答不稳定** | 自然语言理解有偏差 |
| **数据不准确** | 有时SQL生成错误 |
| **用户不信任** | 不敢直接相信AI结果 |
| **问题难追溯** | 错误时难以定位原因 |

---

## 二、兜底机制设计

### 2.1 分级策略

| 等级 | 置信度 | 策略 | 响应时间 |
|:---:|:---:|:---|:---:|
| **A级** | < 60% | 转人工处理 | 即时 |
| **B级** | 60-80% | 提示用户确认 | < 1min |
| **C级** | > 80% | 直接输出结果 | 即时 |

### 2.2 兜底场景

| 场景 | 风险描述 | 兜底方式 |
|:---|:---|:---|
| **意图识别失败** | 听不懂用户问什么 | 转人工 |
| **SQL生成错误** | 生成的SQL有问题 | 提示并建议确认 |
| **数据质量差** | 底层数据有问题 | 提示数据质量问题 |
| **无相关数据** | 数据库没有相关表 | 友好提示 |

---

## 三、人工介入流程

```
用户提问
    │
    ▼
┌─────────────────────┐
│   自然语言理解       │
└─────────────────────┘
    │
    ▼ 置信度判断
┌─────────────────────┐
│  置信度 < 60%       │
│  → 转人工处理       │
└─────────────────────┘
    │
    ▼ 置信度 60-80%
┌─────────────────────┐
│  置信度 60-80%     │
│  → 提示用户确认     │
└─────────────────────┘
    │
    ▼ 置信度 > 80%
┌─────────────────────┐
│  置信度 > 80%       │
│  → 直接输出结果     │
└─────────────────────┘
```

---

## 四、置信度阈值设计

### 4.1 阈值设定依据

| 因素 | 说明 |
|:---|:---|
| **业务容忍度** | 不同业务场景容忍度不同 |
| **数据质量** | 底层数据质量影响阈值 |
| **用户信任度** | 新功能需更高阈值 |

### 4.2 阈值调整机制

| 场景 | 初始阈值 | 调整方式 |
|:---|:---:|:---|
| **新功能上线** | 80% | 稳定后降至75% |
| **核心功能** | 85% | 一般不调整 |
| **探索功能** | 70% | 可适当降低 |

---

## 五、风控机制

### 5.1 监控指标

| 指标 | 监控内容 |
|:---|:---|
| **意图识别准确率** | AI理解对的比率 |
| **SQL生成准确率** | 生成的SQL正确的比率 |
| **兜底触发率** | 触发兜底的比率 |
| **用户满意度** | 人工介入后的满意度 |

### 5.2 告警机制

| 级别 | 阈值 | 动作 |
|:---:|:---|:---|
| **P0** | 兜底率>30% | 立即告警，停止服务 |
| **P1** | 兜底率>20% | 2小时内处理 |
| **P2** | 兜底率>10% | 每日复盘 |

---

## 六、护栏指标

| 指标 | 阈值 | 说明 |
|:---|:---:|:---|
| **有害内容率** | < 0.1% | 触碰红线立即人工介入 |
| **数据准确率** | > 95% | 低于阈值触发兜底 |
| **响应时间** | < 5s | 超时降级 |
