## 一、背景

### 1.1 问题定义

**核心痛点**：钟离（代码Agent）理解现有代码的能力有限

| 痛点 | 表现 |
|:---|:---|
| **上下文限制** | 只能看到部分代码，无法理解全貌 |
| **结构不清晰** | 不理解模块间的调用关系 |
| **影响分析难** | 修改一处，难以识别受影响范围 |
| **规范不一致** | 不知道项目的特殊要求 |

### 1.2 解决方案架构

## 二、文档层：CLAUDE.md最佳实践

### 2.1 为什么CLAUDE.md有效

**Karpathy案例**：

| 指标 | 数据 |
|:---|:---|
| 单日GitHub Stars | 5,828 |
| 排名 | 当日全球第二 |
| 内容 | 仅一个markdown文件 |

**结论**：一个纯文本文件能爆发，说明行业对Agent配置范式的共识形成。

### 2.2 CLAUDE.md的核心作用

| 配置项 | 说明 |
|:---|:---|
| **行为规则** | 定义Agent的决策边界 |
| **上下文管理** | 提供项目结构和关键信息 |
| **质量标准** | 定义何为"完成"的标准 |
| **错误处理** | 定义遇到问题时的处理方式 |

### 2.3 CLAUDE.md标准结构

#### 基础级（L1）

```markdown
# {项目名称}

## 项目概述
- 项目定位

## 技术栈
- 框架版本
- 语言版本

## 代码结构
- 目录结构
- 核心模块说明
```

```markdown
## 核心模块详解
```

#### 完整级（L3）


## 三、技术层：代码索引系统

### 3.1 核心架构

```
代码 → AST解析 → 图结构(Call Graph) → 向量嵌入 → 语义检索 → LLM理解
```

### 3.2 RepoKG代码知识图谱

**来源**：[[insight-20260511-code-knowledge-graph-repo-doc]]

**四步闭环**：
```
建图谱 → 模块化 → 智能生成 → 精准更新
```

**3类实体 + 7类关系**：

| 实体 | 说明 |
|:---|:---|
| 代码实体 | 函数、类、模块 |
| 概念实体 | User、Auth、Cache |
| 文档实体 | 生成的文档 |

| 关系 | 说明 |
|:---|:---|
| 调用 | function_a → function_b |
| 实现 | interface → class |
| 继承 | parent → child |
| 导入 | module → module |
| 包含 | package → class |
| 语义影响 | config → logic |
| 描述 | code → doc |

### 3.3 关键技术组件

| 组件 | 功能 | 工具 |
|:---|:---|:---|
| **代码解析器** | 生成AST和语法树 | Tree-sitter, LSP |
| **图构建器** | 构建Call/Dependency Graph | code², Sourcegraph |
| **向量索引** | 语义检索代码片段 | ChromaDB, FAISS |
| **RAG引擎** | 检索增强代码生成 | Ranger, Code RAG |

### 3.4 支持语言

| 语言 | AST支持 |
|:---|:---:|
| **Python** | ✅ |
| **Java** | ✅ |
| **JavaScript/TypeScript** | ✅ |
| **C#** | ✅ |
| **C/C++** | ✅ |
| **PHP** | ✅ |

### 3.5 增量更新机制

| 步骤 | 实现方式 |
|:---|:---|
| **变更检测** | AST对比Git提交差异 |
| **影响传播** | RepoKG双向遍历（下游+上游） |
| **更新顺序** | Kahn算法拓扑排序 |
| **文档再生** | 仅选择性更新受影响片段 |

**性能优势**：相比全量生成方案，增量更新可减少**70%以上**的计算资源消耗。

### 3.6 开源工具对比

| 工具 | 特点 | 适用场景 |
|:---|:---|:---|
| **Sourcegraph Cody** | 代码理解+检索增强 | 闭源/大型代码库 |
| **RepoDoc** | 增量更新+语义增强 | 项目文档生成 |
| **RAGstack** | 代码RAG专用 | 需要RAG的场景 |
| **Beyonder** | 上下文窗口优化 | 长代码文件 |

## 四、两层方案对比

| 维度 | CLAUDE.md | 代码索引系统 |
|:---|:---|:---|
| **层次** | 文档层 | 技术层 |
| **构建方式** | 人工编写 | 自动化构建 |
| **内容** | 规范、模式、注意事项 | 代码结构、依赖关系 |
| **更新频率** | 按需更新 | Git提交触发 |
| **成本** | 低（人工） | 中（工具+存储） |
| **效果** | 规范约束 | 精准理解 |

**互补关系**：CLAUDE.md + 代码索引系统 = 完整解决方案
