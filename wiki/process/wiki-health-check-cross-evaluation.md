# Wiki健康走查方案 × Karpathy LLM Wiki 交叉评估

> 评估时间: 2026-04-28
> 评估人: 尼克·弗瑞

---

## 一、方案对比

### 1.1 Karpathy LLM Wiki 核心要素

| 要素 | 说明 |
|------|------|
| **三层架构** | Raw Sources → Wiki → Schema |
| **两种特殊文件** | index.md（索引）、log.md（操作日志） |
| **三种操作** | Ingest（消化）、Query（查询）、Lint（健康检查） |
| **页面类型** | Entity、Concept、Topic、Insight、Temporal |
| **核心机制** | 矛盾检测、过时检测、孤立页面检测 |

### 1.2 我们的Wiki健康走查方案核心要素

| 要素 | 说明 |
|------|------|
| **MECE检查** | 相互独立、完全穷尽 |
| **结构完整性** | README覆盖、目录层级 |
| **链接健康** | 死链、悬空链检测 |
| **归类合理性** | 决策树 + 质量评分 |
| **问题分级** | P0-P3处理时限 |

## 二、交叉评估矩阵

### 2.1 评估维度对比

| 维度 | Karpathy方案 | 我们方案 | 评估 |
|------|-------------|----------|------|
| **覆盖面** | 侧重知识内容（矛盾/过时） | 侧重结构（层级/链接） | ⚖️ 互补 |
| **自动化程度** | Lint脚本半自动 | 手动+脚本 | ⚠️ Karpathy更成熟 |
| **MECE验证** | 无明确机制 | 有完整检查清单 | ✅ 我们更优 |
| **过时检测** | 有（3个月阈值） | 无 | ⚠️ Karpathy更优 |
| **矛盾检测** | 有 | 无 | ⚠️ Karpathy更优 |
| **操作日志** | 有（log.md） | 无持续日志 | ⚠️ Karpathy更优 |
| **归类决策树** | 无 | 有 | ✅ 我们更优 |
| **问题分级** | 无 | P0-P3分级 | ✅ 我们更优 |

### 2.2 关键差距分析

| 差距 | 说明 | 影响 |
|------|------|------|
| **过时检测缺失** | 我们方案无"内容是否过时"的检查 | 可能积累过时信息 |
| **矛盾检测缺失** | 我们方案无"同一实体不同描述是否矛盾"的检查 | 知识一致性风险 |
| **缺乏操作日志** | 无持续记录每次维护操作 | 难以追溯维护历史 |
| **缺乏页面类型规范** | 我们的Insight命名不够规范 | 影响可发现性 |

## 三、Karpathy方案可借鉴要素

### 3.1 高优先级借鉴

| 要素 | 如何融入我们方案 | 预期效果 |
|------|-----------------|----------|
| **过时检测** | 增加检查：超过3个月未更新的页面标记为"待审核" | 保持内容新鲜度 |
| **操作日志** | 创建`process/maintenance-log.md`，记录每次走查和修复 | 追溯维护历史 |
| **孤立页面检测** | 已有，但可以增强：检测无内部引用的页面 | 减少知识孤岛 |

### 3.2 中优先级借鉴

| 要素 | 如何融入我们方案 | 预期效果 |
|------|-----------------|----------|
| **矛盾检测** | 增加检查：同名实体在不同页面的描述是否冲突 | 提高知识一致性 |
| **index.md维护** | 增加检查：index.md是否与实际内容同步 | 提高可发现性 |

### 3.3 低优先级（暂不采纳）

| 要素 | 原因 |
|------|------|
| **强制页面模板** | 现有模板已足够，过度标准化降低灵活性 |
| **Temporal页面类型** | 我们暂无此需求 |

## 四、融合后的增强方案

### 4.1 增强检查清单（v1.1）

**新增检查项**：

```
#### 过时检测（Monthly）
□ 检查超过3个月未更新的页面
□ 标记为"待审核"状态
□ 决定是更新还是归档

#### 矛盾检测（Monthly）
□ 检查同一实体在不同页面的描述
□ 识别可能的矛盾点
□ 协调后统一描述

#### 操作日志（每次走查时）
□ 记录本次走查时间、内容
□ 记录发现的问题
□ 记录修复结果
```

### 4.2 融合后的走查频率

| 频率 | 检查项 |
|------|--------|
| **每日** | 链接健康检查 |
| **每周** | 结构完整性、空目录、孤立页面 |
| **每月** | MECE原则、过时检测、矛盾检测、操作日志审查 |

## 五、结论

### 5.1 方案互补性

| 方案 | 优势 | 劣势 |
|------|------|------|
| **Karpathy LLM Wiki** | 内容质量保障（矛盾/过时检测） | 无结构管理和归类机制 |
| **我们方案** | 结构管理和归类（MECE） | 缺内容质量保障 |

**结论**：两个方案高度互补，建议融合。

### 5.2 建议行动

1. **立即采纳**：过时检测机制（低实施成本，高价值）
2. **本周内**：创建操作日志模板
3. **本月内**：评估是否需要矛盾检测（实施成本较高）
