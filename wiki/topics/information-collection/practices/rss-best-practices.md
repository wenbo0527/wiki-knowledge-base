## 1. 为什么RSS仍然重要

```
RSS的价值:

✅ 主动推送
├── 不用访问网站
├── 信息主动到你
└── 节省时间

✅ 去中心化
├── 不被算法控制
├── 信息源自己选
└── 避免信息茧房

✅ 订阅纯净
├── 无广告干扰
├── 无推荐算法
└── 专注内容本身

✅ 长期积累
├── 可追溯历史
├── 便于回顾
└── 知识沉淀
```

## 2. RSS源筛选

### 2.1 优质源特征

```
高质量RSS源标志:

1. 原创内容
├── 不是洗稿/搬运
├── 有独特视角
└── 有作者署名

2. 更新规律
├── 固定频率更新
├── 不过于频繁
└── 也不长期停滞

3. 内容深度
├── 不是标题党
├── 有实质内容
└── 有独到见解

4. 可验证性
├── 有具体来源
├── 有数据支撑
└── 便于核实
```

```
评估模板:

类型: □ 博客 □ 新闻 □ 官方 □ 聚合

六维评分 (1-5):

├── 专业性: __/5
├── 时效性: __/5
├── 独立性: __/5
```

## 3. 分层管理

### 3.1 TIER分级

```
TIER_1: 核心源 (≤20个)
────────────────────
扫描: 每日
处理: Layer 3 (深度分析)
数量: 最多50篇/天
原则: 宁缺毋滥

示例:
├── Lilian Weng (AI研究)
├── Martin Fowler (软件工程)
├── Simon Willison (AI/编程)
├── a16z Blog (投资)
└── 核心技术博客

TIER_2: 标准源 (≤50个)
────────────────────
扫描: 每周
处理: Layer 2 (摘要提炼)
数量: 最多30篇/周
原则: 按需深入

示例:
├── 技术媒体
├── 行业博客
├── 产品博客
└── 研究机构

TIER_3: 发现源 (≤100个)
────────────────────
扫描: 每两周
处理: Layer 1 (快速浏览)
数量: 最多10篇/两周
原则: 发现线索

示例:
├── Hacker News
├── GitHub Trending
├── Product Hunt
└── 新发现的博客
```

## 4. 阅读工作流

### 4.1 晨间阅读法

```
时间: 30分钟 (起床后)

目标: 快速扫描，获取今日重点

步骤:

Step 1: 扫标题 (5分钟)
────────────────────
快速浏览所有TIER_1
只看标题
标记感兴趣的

Step 2: 读摘要 (10分钟)
────────────────────
读感兴趣文章的摘要/开头
判断是否值得深入

Step 3: 深度阅读 (15分钟)
────────────────────
选择1-2篇深度阅读
做笔记、标注关键点

Step 4: 整理归档 (不占用阅读时间)
────────────────────
读完后统一处理
标注、收藏、归档
```

### 4.2 文章处理层次

```
Layer 0: 直接跳过
──────────────
- 标题党
- 不相关
- 低质量

Layer 1: 快速浏览 (30秒)
──────────────
- 标记: ★
- 只看标题+首段
- 知道这个话题

Layer 2: 简单摘要 (2分钟)
──────────────
- 标记: ★★
- 读完全文
- 记录核心观点

Layer 3: 深度分析 (10分钟)
──────────────
- 标记: ★★★
- 做详细笔记
- 关联已有知识

Layer 4: 创造性输出 (30分钟)
──────────────
- 标记: ★★★★
- 写博客/文章
- 形成洞察
```

## 6. 常见问题

### 6.1 信息过载

```
问题: 订阅太多，看不过来

解决:
├── 定期审计: 每月检查订阅源
├── 严格筛选: 不值得TIER_1的不加
├── 设置上限: TIER_1最多20个
├── 批量处理: 固定时间统一处理
└── 敢于取关: 不合适的源直接移除
```

### 6.2 源失效/迁移

```
问题: 博客关闭或迁移，RSS失效

解决:
├── RSS Hub: 生成无法RSS的网站
├── Wayback Machine: 找历史内容
├── 搜索新博客: 找作者新RSS
└── 关注Twitter: 追踪博主动态
```

### 6.3 深度阅读时间

```
问题: 收藏了很多，但没时间读

解决:
├── 固定阅读时间: 晨间30分钟
├── 降低收藏率: 只收藏真正想读的
├── 批量处理: 每天/每周固定处理
├── 设定目标: 每周至少深度读X篇
└── 输出倒逼: 写笔记促进阅读
```

## 7. 自动化方案

### 7.1 RSS抓取脚本

```python
# 示例: 分层抓取
import feedparser
import json

TIER_1 = ["https://example1.com/rss", "https://example2.com/rss"]
TIER_2 = ["https://example3.com/rss", "https://example4.com/rss"]

def fetch_tier1():
    """每日抓取核心源"""
    articles = []
    for url in TIER_1:
        feed = feedparser.parse(url)
        for entry in feed.entries[:10]:  # 最多10篇
            articles.append({
                "title": entry.title,
                "url": entry.link,
                "source": feed.feed.title,
                "published": entry.get("published"),
                "tier": 1
            })
    return articles

def fetch_tier2():
    """每周抓取标准源"""
    articles = []
    for url in TIER_2:
        feed = feedparser.parse(url)
        for entry in feed.entries[:5]:  # 最多5篇
            articles.append({
                "title": entry.title,
                "url": entry.link,
                "source": feed.feed.title,
                "published": entry.get("published"),
                "tier": 2
            })
    return articles
```
