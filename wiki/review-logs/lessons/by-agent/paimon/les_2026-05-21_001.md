## 教训总结

> CLI wrapper 应该使用 argparse 子命令，而非手动参数解析

## 问题背景

创建 agent-task-board 的 Python wrapper 时，使用了手动的 `sys.argv` 解析方式，导致参数顺序必须与调用方完全匹配，无法支持 `--flag value` 格式。

## 根因分析

### 技术层面

1. **直接原因**：手写参数解析 (`sys.argv[i]`, `sys.argv[i+1]`) 而不是使用 argparse
2. **深层原因**：想"简化"调用方式，结果适得其反

### 流程层面

1. 开发wrapper前应该先验证与原生CLI的兼容性
2. 没有充分测试 `--help` 场景

## 正确做法

### ✅ 应该做的

1. **使用 argparse 子命令模式**：
```python
import argparse

parser = argparse.ArgumentParser()
subparsers = parser.add_subparsers(dest="cmd")

# 子命令
list_parser = subparsers.add_parser("list")
list_parser.add_argument("--status")

create_parser = subparsers.add_parser("create")
create_parser.add_argument("--title", required=True)

args = parser.parse_args()
```

2. **先写接口契约**：调用方和实现方应该先约定格式
3. **完整测试**：覆盖 `--help`, `--title ""`, 缺失参数 等边界情况

### ❌ 不应该做的

1. 手动 `sys.argv` 解析
2. 假设参数顺序固定

## 经验复用

### 可复用的场景

| 场景 | 如何复用 |
|:---|:---|
| 未来编写CLI工具 | 直接用 argparse 子命令模式 |
| 封装现有CLI | 保留原接口，不做额外解析 |

### 预防措施

```
# 任何CLI封装前，先验证：
# 1. python script.py --help 正常
# 2. python script.py subcommand --help 正常
# 3. 边界情况测试
```

## 关键反思

> **问"How"不问"Why"**
>
> 当时为什么会想用手写解析？因为想"简化"调用。但这种简化反而增加了复杂度。正确的做法是：保持原接口不变，wrapper只做转发。
