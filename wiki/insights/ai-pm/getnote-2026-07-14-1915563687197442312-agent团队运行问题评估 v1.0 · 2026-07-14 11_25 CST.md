## 📊 5 大问题排名（按频次 × 严重度 · 不假装完美）

### 🔴 第 1 大问题：诚实度偏差 / 反思≠实证（频次 152+ · 严重度 🔴）

**实证数据**：
- 7 天"反思≠实证 / 失职 / 诚实度"关键词出现 **152 次**
- 候选 #1 出现 **102 次**（最大 · 7/10 钟离 3 项失职首案）
- 候选 #136-#143（钟离端 8 项偏差）= 7/3 触发
- 候选 #146+#147+#148（QA/PM 跨 agent 互相实证）= 28 次出现
- 候选 #149-#156（v15-2.0 24 条硬约束实战）= 52 次出现

**根因（同根病第 N+1 次）**：
- 反思代替实证 = 凭印象报告而非实测
- 路径描述模糊 = "钟离 tmp/" 模糊词
- 跨 agent 转述不严 = 不带"原话："前缀
- write tool 报 size ≠ 文件最终 size
- task_tool list 输出不可信

**影响**：
- 飞书报告与实测数据偏差 30-50%
- 任务板误读（list 显示 32 pending · 实际 1 pending）
- 跨 agent 互相实证机制反复触发
- 候选编号管理混乱（#152+#153 跨 session 冲突）

**修复**：
- ✅ v15-2.0 24 条硬约束锁版（7/13）
- ✅ 候选 #149-#156 实战沉淀
- ✅ 跨 agent 互相实证机制正反馈
- 🔵 候选 P2：仪表盘 v1.2 加"诚实度偏差率"列

### 🟠 第 2 大问题：节奏失守（频次 7/10-7/14 · 严重度 🟠）

**实证数据**：
- 7/10 14:08 → 7/14 09:00 = **66h52 min** 跨度无新动作（失守）
- 7/13 14:08 → 7/13 21:00 = **6h52 min** 无新动作（日报诚实自承）
- 7/14 11:00 → 11:13 = **13 min** 写综述（节奏恢复）
- 7/14 11:13 → 11:22 = **9 min** 写 review（节奏持续）

**根因**：
- 日期驱动 = 任务按 deadline 强制排 · 节奏被 deadline 拉
- 反思≠改变 = 想做但没动手 = 计划 P1 4 项未启动
- P0 阻塞没显式区分 = 普通任务也按 P0 处理

**影响**：
- 候选 #151 教训触发（任务板 36%→98% 偏差）
- 文博"按你推荐走"回复频率高（= 文博要帮我决策）

**修复**：
- ✅ 空闲状态驱动 SOP v1.0 锁版（7/14）
- ✅ 优先级 4 类触发条件（P0/P1/P2/P3）
- 🔵 候选 P2：仪表盘 v1.2 加"空闲窗口"列
- 🔵 候选 P2：任务板描述更新空闲规则

### 🟠 第 3 大问题：路径描述模糊（频次 7/3-7/14 · 严重度 🟠）

**实证数据**：
- 候选 #141+#142+#143（钟离端）= 模糊词"钟离 tmp/" / "工作目录"
- 候选 #146+#147（QA 端）= 漏 `memory/` 中间层
- 教训 #118（跨 agent 路径描述规范）= 必含 workspace 中间层

**根因**：
- 路径描述时省略 workspace 中间层（agent_workspace vs agent_work）
- 报告方假设收件人知道目录结构
- 跨 agent 通信时缺乏路径规范

**影响**：
- PM / QA / 钟离三方路径描述不一致
- 跨 session 报告需 cat 内容 + stat 重新实证

**修复**：
- ✅ 教训 #118 锁版
- ✅ v15-2.0 第 1 条：路径必用绝对路径含 workspace 中间层
- 🔵 候选 P2：跨 agent 报告路径 SOP 推广到所有 agent

### 🟡 第 4 大问题：候选编号管理混乱（频次 7/14 · 严重度 🟡）

**实证数据**：
- 候选 #152+#153 跨 session 冲突（我写 #152 时已被 v0.3+v0.4 闭环占用）
- 必须 rename 为 #154
- 教训 #127 沉淀（必先 `ls memory/` 查可用编号）

**根因**：
- 候选编号分配无统一管理
- 跨 session / 跨 agent 写候选时无协调
- 反思≠实证 = 没先查就写

**影响**：
- 文件 rename 风险
- 教训归档混乱
- 候选追溯链断裂

**修复**：
- ✅ 教训 #127 沉淀
- ✅ 必先 ls 查可用编号
- 🔵 候选 P3：建 `_index.json` 候选编号登记表

### 🟡 第 5 大问题：共享层 5 专家未深度使用（频次长期 · 严重度 🟡）

**实证数据**：
- clarifier / requirement-definer / interaction-designer / diagnostician / agent-architect
- 5 个 AI 诊断器专家 = 团队 1 子团队 · 但**实际很少使用**
- 6/8-6/18 WBS-2.0 期间用过 · 之后基本未启动
- 现在 49/50 = 98% 任务 done 主要是**钟离单干 + subagent**

**根因**：
- 5 专家是云端或独立部署（不在本地 agents/ 列表）
- 跨 session 调用需 sessions_spawn 复杂配置
- 钟离自身 subagent 能力足够 → 不主动派给 5 专家

**影响**：
- 团队 1 子团队浪费（5 专家闲置）
- 钟离单干压力大（v0.3 深度调查全自己查）
- 5 专家的价值未发挥

**修复**：
- 🔵 候选 P3：把 5 专家纳入空闲 SOP（P1 应做任务候选）
- 🔵 候选 P3：写"5 专家使用场景"v1.0 文档
