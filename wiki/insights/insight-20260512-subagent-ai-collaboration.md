## 一、核心痛点：单一AI的困境

### 问题表现

单一AI处理大型任务时，随上下文窗口饱和出现三大问题：

| 问题 | 表现 |
|:---|:---|
| **忘记早期设计** | 前后端权限字段不匹配 |
| **逻辑冲突** | 同一接口出现两套不同鉴权逻辑 |
| **操作污染** | 改前端时误动后端配置 |

### 核心结论

> **问题不是AI能力不足，而是单一AI无法承载大型任务**

## 二、Subagent定义

### 本质特征

| 特征 | 说明 |
|:---|:---|
| **角色定位** | 从主AI拆分的"专属助手"，类比团队成员 |
| **核心隔离** | 独立上下文窗口、系统提示、工具权限 |
| **模型选择** | 可运行不同AI模型 |

### 与传统方案的区别

| 维度 | 多开对话窗口 | Subagent协作体系 |
|:---|:---|:---|
| **协调成本** | 需人工复制粘贴上下文 | 主Agent自动完成委派、传递、汇总 |
| **并行能力** | 依赖人工记忆各窗口状态 | 主Agent统一调度多Subagent并行 |
| **上下文控制** | 新会话完全空白 | 主Agent智能打包必要上下文 |

### 协作流程

```
主Agent委派任务 → Subagent独立完成 → 返回结果
                    ↓
              不污染主会话上下文
```

## 三、Claude Code内置Subagent

### 三种类型

| 名称 | 用途 | 模型 | 权限 | 典型场景 |
|:---|:---|:---|:---|:---|
| **Explore** | 代码库搜索与理解 | Haiku | 只读 | 函数调用关系分析、模块结构梳理 |
| **Plan** | 收集上下文并制定方案 | 继承主会话 | 只读 | `/plan`指令触发的规划任务 |
| **General-purpose** | 复杂多步骤任务 | 继承主会话 | 全部工具 | 代码理解+重构的组合任务 |

## 四、Subagent适用任务判断

### 四大判断标准

满足2项以上值得拆分：

| 标准 | 说明 |
|:---|:---|
| **重复频繁** | 每日/每个项目均需执行 |
| **上下文重** | 需加载大量文件，快速消耗主会话容量 |
| **流程固定** | 执行步骤明确，标准化程度高 |
| **可以并行** | 无依赖关系，可独立同时进行 |

## 五、六大典型应用场景

### 1. 前后端同时开发

- **价值**：打破"先后端再前端"的串行模式
- **前提**：任务无依赖，不修改同一文件

### 2. 探索大型代码库

- **痛点**：主会话中直接分析会加载大量内容
- **解决方案**：Explore Subagent独立梳理，仅返回关键信息

### 3. 安全审查/专项检查

- **优势**：专注"找问题"，系统提示可集成OWASP清单等专业规则
- **与Skill区别**：Subagent拥有完全独立上下文

### 4. 工作成果验证

- **闭环流程**：主Agent改完代码 → 触发验证Subagent → 检查 → 反馈修复

### 5. 多假设并行排查Bug

- **方法**：为不同假设分配Subagent（网络层/认证逻辑/数据库/缓存）
- **优势**：并行验证，效率远高于依次排查

### 6. 后台异步任务

- **场景**：文档生成、单元测试生成等非紧急任务

## 六、自定义Subagent创建

### 文件格式示例

```markdown
---
name: security-reviewer
description: 安全审查专家。当用户说「帮我做安全review」时触发。
tools: Read, Grep, Glob
model: sonnet
color: blue
---

你是Web应用安全工程师，审查步骤：
1. 认证授权：JWT expiration校验
2. 输入校验：SQL注入/XSS风险
3. 敏感信息：密钥日志泄漏检查
```

### 核心配置要点

| 配置 | 要点 |
|:---|:---|
| **description** | 明确触发条件，避免过于宽泛 |
| **模型选择** | 简单任务用Haiku，复杂任务用Sonnet |
| **权限控制** | 通过tools/disallowedTools限制操作范围 |
| **行为约束** | 系统提示中明确"不要做什么" |

## 七、注意事项

| 注意 | 说明 |
|:---|:---|
| **禁止套娃** | Subagent不能再委派任务，仅支持一层拆分 |
| **并行边界** | 确保任务无依赖且不修改同一文件 |
| **描述精准** | 避免"做任何代码任务"等宽泛表述 |
| **记忆配置** | 通过memory: project字段让Subagent跨会话积累知识 |
