## 二、ChatBI 项目细节

### 2.1 项目背景

```
痛点：非技术业务无 SQL 能力，BI 团队被重复取数需求淹没
目标：自然语言问数 + 生成数据集
约束：
  ├── 限定单指标宽表
  ├── 不做多表关联
  ├── 不重构底层 OLAP
  └── 最小成本验证业务接受度
```

### 2.2 方案演进

| 阶段 | 方案 | 说明 |
|:---:|:---|:---|
| 初代 | NL2SQL + 知识召回 | 知识库 + SQL 生成 |
| 迭代 | Skill + 指标字典 + Agent | 受 OpenClaw 启发 |

### 2.3 测试手段

- **40 条 Case 测试集**：口径校验
- **厂商选型诉求**：知识维护 + 可视化调错 + 小模型召回 + UI 成熟

## 三、OpenClaw 问数 Demo 架构

### 3.1 五层架构

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: 交互接入层                                        │
│  └── 飞书集成（企业版需打通 IM/浏览器）                    │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: Agent 编排层                                       │
│  ├── 意图理解                                              │
│  ├── Skill & Tools 路由                                    │
│  └── 任务拆解与流程编排                                    │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: 知识检索层                                       │
│  ├── 指标字典                                              │
│  ├── 业务概念说明                                          │
│  └── 向量检索 + 未来图谱扩展                              │
├─────────────────────────────────────────────────────────────┤
│  Layer 4: LLM 推理层                                       │
│  └── Ollama + BGM-M3（本地轻量推理）                      │
├─────────────────────────────────────────────────────────────┤
│  Layer 5: 数据底座层                                       │
│  └── SQLite（Demo）/ 未来对接数据平台                      │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 跨表/跨主题演进路径

```
自然语言解析 → 数据权限分析 → 数据映射 → SQL生成 → 代码校验 → 执行渲染

核心卡点：
1. 数据权限（按人查，不通用账号）
2. 表关联（接入数据血缘 or 场景模板兜底）
3. SQL 可视化 + 校验 + 错误溯源
```

## 四、产品设计原则

### 4.1 Agent 顶层原则

| 原则 | 说明 |
|:---|:---|
| **准确 > 应答** | 金融场景准确比快速回答更重要 |
| **模糊不猜** | 信息不全时主动反问，不臆测 |

### 4.2 Skill vs Tools 边界

| 类型 | 职责 | 示例 |
|:---|:---|:---|
| **Skill** | 业务决策、意图分类、会话澄清 | 需求澄清、问题分类 |
| **Tools** | 确定性能力封装、输入输出可预期 | Shell、文件读取、API 调用 |

### 4.3 知识库召回策略

| 体量 | 策略 |
|:---|:---|
| **小规模** | 全量召回 + 精排 |
| **大规模** | 分级分类召回 + 排序 + 冗余剔除 |

## 六、Agent Reflect 机制（OpenClaw Dreaming）

### 6.1 核心概念

OpenClaw 的 **Dreaming** 系统实现了类似反思的能力，位于 `memory-core`。

### 6.2 三阶段模型

| 阶段 | 目的 | 持久化写入 |
|:---|:---|:---|
| **Light** | 排序和暂存近期短期材料 | ❌ |
| **Deep** | 评分和提升持久化候选 | ✅ MEMORY.md |
| **REM** | 提取模式和反思信号 | ❌ |

### 6.3 Deep Ranking 信号权重

| 信号 | 权重 | 说明 |
|:---|:---:|:---|
| Relevance | 0.30 | 平均检索质量 |
| Frequency | 0.24 | 短期信号累积 |
| Query diversity | 0.15 | 不同查询/日期上下文 |
| Recency | 0.15 | 时间衰减新鲜度 |
| Consolidation | 0.10 | 多日 recurrence 强度 |
| Conceptual richness | 0.06 | snippet/path 的概念标签密度 |

### 6.4 Dreaming 配置

```json
{
  "plugins": {
    "entries": {
      "memory-core": {
        "config": {
          "dreaming": {
            "enabled": true,
            "frequency": "0 3 * * *"
          }
        }
      }
    }
  }
}
```

### 6.5 CLI 命令

```bash
# 预览 Promote
openclaw memory promote

# 应用 Promote
openclaw memory promote --apply

# 预览 REM 反思
openclaw memory rem-harness

# 深度状态
openclaw memory status --deep
```

## 七、产品视角的 Reflect 三大核心能力

> 面试官标准：不是"评价、反馈、沉淀"这种口语，要到产品架构层级

### 7.1 结果自省

```
比对「任务目标」和「实际输出」，识别：
├── 口径错误
├── 逻辑漏洞
├── 工具调用选错
└── 步骤冗余
```

### 7.2 过程复盘

```
回溯规划路径、工具选择、上下文使用，判断：
└── 哪一步决策出错
```

### 7.3 资产沉淀落地

| 沉淀类型 | 说明 |
|:---|:---|
| **修正记忆** | 修正会话/任务记忆 |
| **规则迭代** | 迭代 Skill 规则、Prompt 样例 |
| **知识补充** | 补充知识库缺失条目 |
| **失败归档** | 归档失败 Case 到评测库，用于版本回归测试 |
