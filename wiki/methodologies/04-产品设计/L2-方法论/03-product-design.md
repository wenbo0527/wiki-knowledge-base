## 三、具体方法论详情

### 1. 用户体验设计方法

**核心**：让用户用得爽

**成熟框架**：10 Usability Heuristics
| # | 原则 | 说明 |
|:---:|:---|:---|
| 1 | 系统状态可见 | 操作有反馈 |
| 2 | 系统与真实世界匹配 | 用户语言而非技术语言 |
| 3 | 用户控制与自由 | 操作可撤销 |
| 4 | 一致性与标准化 | 风格统一 |
| 5 | 防错优于纠错 | 预防错误设计 |
| 6 | 识别而非回忆 | 减少记忆负担 |
| 7 | 灵活高效 | 满足新手和老手 |
| 8 | 审美与简约设计 | 不要冗余信息 |
| 9 | 容错帮助 | 错误信息有用 |
| 10 | 帮助与文档 | 需要时能找到帮助 |

**实践要点**：
- 用用户语言而非技术语言
- 设计清晰的系统状态
- 考虑容错和降级体验

**✅ 实践案例：数据门户UX**
- 问题：业务人员找不到想要的数据表
- 设计方案：
  - 搜索框置顶，一键直达
  - 常用表收藏+分享
  - 表详情页显示血缘链路
  - 字段说明清晰，口径可查
- 关键经验：用户不关心元数据管理，只关心"快速找到我要的表"

### 2. 交互设计方法

**核心**：让用户知道怎么操作

**成熟框架**：
- 悬停效果/点击反馈
- 加载状态/进度指示
- 错误提示/成功反馈

**AI产品特有交互**：
- 置信度提示
- AI思考过程展示
- 人机协作模式

**实践要点**：
- 交互要有即时反馈
- AI输出要有置信度标识
- 设计人工介入的交互入口

**✅ 实践案例：营销套件交互**
- 可视化画布：拖拽节点→连线→配置参数
- 节点状态：待配置/已配置/执行中/已完成
- 触达反馈：发送成功/失败/重试
- AI辅助：推荐策略用特殊标识，点击可查看推荐理由

### 3. 基础设计原则方法

**核心**：极简智能原则

**成熟框架**：
| 原则 | 说明 |
|:---|:---|
| **极简智能** | AI做复杂决策，用户做简单选择 |
| **一致性** | AI能力+交互体验+技术架构三维统一 |
| **可解释性** | 用户能理解AI为什么这么做 |
| **可控性** | 用户能纠正AI的错误 |

**实践要点**：
- 隐藏AI复杂性，简化用户界面
- 保持AI能力与体验一致
- 让用户始终保持控制权

**✅ 实践案例：ChatBI极简智能**
- 极简智能：
  - 用户输入自然语言："昨天的新增用户有多少"
  - AI自动转SQL、查数据、返回结果
  - 用户只需要"问-看"两步
- 一致性：
  - 对话风格统一
  - 图表展示风格统一
  - 错误提示风格统一
- 可解释性：
  - 显示"我理解的SQL是什么"
  - 置信度用颜色标识（高置信绿色/低置信黄色）
  - 点击可查看查询过程
- 可控性：
  - 用户可修正SQL
  - 用户可调整查询范围
  - 支持手动刷新数据

### 4. AI 数据产品设计方法（2026-06-22 新增 🆕）

**核心**：把 AI 能力包装成可复用的数据产品

**实践案例：Hermes Agent 得物四类核心资产**（来源：insight-20260622-hermes-rule-pack-data-warehouse）

#### 4.1 四类核心资产

| 资产类型 | 核心功能 | 产品化设计 |
|:---|:---|:---|
| **工作区 (Work Zone)** | 需求上下文一键沉淀 | 集中存放 PRD/讨论/产物 |
| **看板 (Dashboard)** | 执行过程透明可查 | 状态机流转 + 责任人明确 |
| **规则包 (Rule Pack)** | 历史经验资产化 | 新需求自动关联历史口径 |
| **结构化工具接口 (Tool Interface)** | 系统对接标准化 | 高风险动作人工确认 |

#### 4.2 单 Agent + 能力模块架构

| 方案 | 优势 | 不足 | 适用 |
|:---|:---|:---|:---|
| 单段提示词 | 启动成本低 | 输出漂移，无沉淀 | 一次性问答 |
| 多 Agent 拆分 | 角色边界清晰 | 上下文同步成本高 | 高度并行任务 |
| **单 Agent + 能力模块** | 统一上下文，流程可控 | 需工程化规则 | 数据/研发全链路 |

**对应我们 4 Agent 团队（Nick/钟离/托尼/派蒙）+ Skills 体系，正好是这种架构的应用**。

#### 4.3 人机协同分工（产品设计的关键原则）

```
AI 负责：  材料收集 / 历史检索 / 风险预演 / 过程记录
人工负责： 业务语义 / 口径定义 / 敏感审核 / 放行决策
```

**设计原则**：AI 不替代人决策，而是把决策前的工作全部准备好——避免"黑箱决策"风险。

## 四、AI产品设计检查清单

```
□ 用户语言：术语是否用户能理解？
□ 系统状态：操作是否有反馈？
□ 容错设计：出错时是否有提示？
□ 置信度：AI输出是否有置信标识？
□ 人工介入：是否提供人工入口？
□ 降级方案：AI不可用时是否可降级？
□ 一致性：风格/交互/术语是否统一？
```
