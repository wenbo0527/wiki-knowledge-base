## 核心洞察

> **TL;DR**: Agent评估核心困境是多路径正确性、模型找设计者没预料到的解、以及状态重要性超越文本输出。

### Agent评估三大困境

| 困境 | 说明 | 案例 |
|:---|:---|:---|
| **多路径正确** | 同一任务可用不同工具组合解决 | 只要结果对，过程可以多样 |
| **设计者未预料的解** | 模型能找到比标准答案更优的方案 | Opus 4.5机票预订案例 |
| **状态重要性** | Agent正确性不能只看文本输出 | 还要看做了什么、改了什么、留了什么状态 |

### Opus 4.5典型案例

| 项目 | 内容 |
|:---|:---|
| **场景** | τ2-bench机票预订题 |
| **结果** | 被判失败，但给出了比标准答案更优的方案 |
| **原因** | 策略文档里找到了漏洞，用规则允许但设计者没想到的方式拿到了更好的结果 |
| **启示** | 按测试代码，它没通过；但按实际效果，它给出了更优方案 |

## 核心术语

| 术语 | 含义 |
|:---|:---|
| **Task** | 一个具体的测试，包含输入、参考答案、评分标准 |
| **Transcript** | Agent执行过程的完整记录（做了什么） |
| **Outcome** | 最终结果产出（做完了什么） |
| **Evaluation harness** | 跑eval的基础设施，负责下发任务、并发执行、记录过程、评分、汇总 |
| **Agent harness** | 让模型能当Agent使用的外部系统，负责输入处理、工具调度、结果回传 |
| **Evaluation suite** | 一组目标相似的task集合 |
| **部分计分** | 任务完成部分给分，非0即1 |

### 两组关键概念区分

| 概念 | 说明 |
|:---|:---|
| **Transcript vs Outcome** | 过程记录 vs 结果产出 |
| **Evaluation harness vs Agent harness** | 评估基础设施 vs Agent运行系统 |
| **部分计分** | 任务完成部分给分，而非0即1 |

## 部分计分原则

> **来源**: 原文

**为什么需要部分计分**：

| 问题 | 原因 |
|:---|:---|
| **非0即1的问题** | 任务完成80%但因一个小失误得0分，不公平 |
| **多路径正确** | 不同路径可能完成不同子目标 |
| **实际价值** | 看Agent实际解决了多少问题 |

**部分计分场景**：

| 场景 | 计分方式 |
|:---|:---|
| **数据处理** | 清洗了多少条，处理质量如何 |
| **代码生成** | 编译通过率，功能覆盖率 |
| **文档撰写** | 完整度、准确性、可读性 |

## Evaluation harness vs Agent harness

| 组件 | 职责 | 说明 |
|:---|:---|:---|
| **Evaluation harness** | 下发任务、并发执行、记录过程、评分、汇总 | 跑eval的基础设施 |
| **Agent harness** | 输入处理、工具调度、结果回传 | 让模型能当Agent使用 |

**关系**：评估一个Agent实际是在评估harness和模型的组合。

---

## Transcript vs Outcome区分

| 概念 | 定义 | 用途 |
|:---|:---|:---|
| **Transcript** | Agent执行过程的完整记录 | 分析行为、调试问题、理解决策过程 |
| **Outcome** | 最终结果产出 | 评估效果、验证目标达成 |

**评估时两者都需要看**：
- 只看Outcome → 不知道怎么做出来的
- 只看Transcript → 不知道最终效果如何

## Grader Agent三角色

| 角色 | 职责 | 核心功能 |
|:---|:---|:---|
| **Grader Agent** | 评估断言是否通过 | 8步流程：读Transcript→检查输出→评估断言→提取隐含声明→读执行者笔记→评价评估 |
| **Comparator Agent** | 对比不同方案 | 比较效果、效率、成本 |
| **Analyzer Agent** | 分析失败原因 | 诊断问题、定位根因、提出改进建议 |

### Grader Agent 8步流程

1. 读Transcript
2. 检查输出
3. 评估断言
4. 提取隐含声明
5. 读执行者笔记
6. 评价评估
7. 评分
8. 生成报告

---

## 评估成熟度路径

| 阶段 | 评估方式 | 说明 |
|:---|:---|:---|
| **L1** | 人工Review | 完全靠内部用户反馈 |
| **L2** | 窄维度Eval | 加入concision、file edits等单一维度 |
| **L3** | 复杂行为Eval | 扩展到over-engineering等复杂行为 |
| **L4** | 自动Eval | 自动化评估+回归测试 |
