## 2. 分工原则

### 2.1 分工核心原则

| 原则 | 说明 | 示例 |
|:-----|:-----|:-----|
| **单一职责** | 每个Agent专注一个领域 | 托尼不写代码,钟离不做产品设计 |
| **能力匹配** | 任务分配给最擅长的Agent | 技术选型→钟离,PRD→托尼 |
| **端到端** | 每个需求有明确的负责人 | 端到端负责,避免踢皮球 |
| **可替代** | 关键流程有备份机制 | 派蒙可中转任何Agent的消息 |
| **最小通信** | 优先本地处理,减少跨Agent通信 | 能自己搞定的不转发 |

### 2.2 任务类型→Agent映射

| 任务类型 | 负责Agent | 辅助Agent | 输出物 |
|:---------|:---------|:---------|:-------|
| 需求理解 | 托尼·斯塔克 | 派蒙 | REQ文档 |
| 需求拆解 | 托尼·斯塔克 | - | Epic/Feature/Story → Neo4j |
| PRD撰写 | 托尼·斯塔克 | 钟离(评审) | PRD文档 |
| 技术方案 | 钟离 | 托尼·斯塔克(需求澄清) | 技术方案文档 |
| 代码实现 | 钟离 | - | 代码 |

| 技术评审 | 钟离 | 托尼·斯塔克 | 评审意见 |

## 4. 五层记忆架构

### 4.1 记忆层级概览

> **与最佳实践的差异说明**：知识库最佳实践提及四层架构（当前工作集→工作区文件→Memory Store→事件日志）。本项目基于实际工具（SQLite任务系统 + Wiki/SOP）扩展为**五层架构**，增加了Task层和SOP层，更符合SOP驱动的任务管理场景。

```
┌─────────────────────────────────────────────────────────────┐
│                    Session Memory (会话层)                   │
│              上下文窗口，会话结束后自动释放                   │
│              用途: 当前任务上下文、对话历史                  │
├─────────────────────────────────────────────────────────────┤
│                    Task Memory (任务层)                     │
│         SQLite任务数据库，任务生命周期内持久化                │
│         用途: 任务状态、进度、依赖                           │
├─────────────────────────────────────────────────────────────┤
│                  SOP Memory (SOP流程层)                     │
│           SOP文档+执行记录，任务生命周期内参考               │
│           用途: 执行规范、流程指引、模板                     │
├─────────────────────────────────────────────────────────────┤
│                 Episodic Memory ( эпизодический层)            │
│            memory/YYYY-MM-DD.md，生命周期30天                │
│            用途: 每日工作记录、周期性总结                    │
├─────────────────────────────────────────────────────────────┤
│                Long-term Memory (永久层)                     │
│                      MEMORY.md，永久保留                     │
│            用途: 核心知识、规范、关键教训                    │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 各层记忆职责

| 层级 | 存储 | 生命周期 | 用途 | 内容要求 |
|:-----|:-----|:---------|:-----|:---------|
| **Session** | 会话内存 | 会话结束 | 当前任务上下文 | 完整保留 |
| **Task** | SQLite | 任务生命周期 | 任务状态进度 | CRUD管理 |
| **SOP** | Wiki/SOP/ | 任务生命周期 | 执行规范流程 | 模板指引 |
| **Episodic** | memory/YYYY-MM-DD.md | 30天 | 每日工作记录 | 压缩到1375字 |
| **Long-term** | MEMORY.md | 永久 | 核心知识规范 | 压缩到2200字 |

### 4.3 Task Memory(任务层)

```sql
-- SQLite: agent_tasks.db
CREATE TABLE tasks (
    id TEXT PRIMARY KEY,          -- TASK-YYYYMMDD-XXX
    title TEXT NOT NULL,          -- 任务标题
    type TEXT NOT NULL,           -- SOP/PRD/研究/代码/支持/其他
    assignee TEXT NOT NULL,       -- 负责人
    status TEXT DEFAULT 'pending', -- pending/in_progress/done/blocked/closed
    priority TEXT DEFAULT 'P2',    -- P0/P1/P2/P3
    created_by TEXT NOT NULL,     -- 创建者
    sop_step TEXT,                 -- SOP-S3/Nick-S1 等
    depends_on TEXT,               -- 依赖任务ID
    description TEXT,              -- 描述
    created_at TEXT,
    updated_at TEXT,
    completed_at TEXT
);
```

### 5.3 任务状态流转

```
pending → in_progress → done → closed
    ↓
 blocked
```

| 状态 | 标识 | 说明 | 可执行动作 |
|:-----|:-----|:-----|:----------|
| pending | 🔴 | 待处理 | START |
| in_progress | 🟠 | 进行中 | COMPLETE / FAIL |
| blocked | ⚫ | 阻塞 | RESUME |
| done | 🟡 | 已完成 | CLOSE |
| closed | 🟢 | 已关闭 | - |

## 8. 最佳实践

### 8.1 任务分配最佳实践

```
✅ 正确做法:
1. 明确任务边界和验收标准
2. 指定对应SOP步骤
3. 设置合理的截止时间
4. 创建依赖关系

❌ 错误做法:
1. "帮我看看这个"(边界不清)
2. 无SOP指导(流程混乱)
3. 不设截止时间(无限拖延)
```

### 8.2 记忆管理最佳实践

```
✅ 正确做法:
1. 任务完成后更新MEMORY.md
2. 每日生成Episodic记忆
3. 关键信息及时沉淀
4. 按SOP流程执行

❌ 错误做法:
1. 全部依赖Session(会丢失)
2. 从不更新MEMORY(知识不积累)
3. 不按SOP执行(流程混乱)
```

### 8.3 五层记忆协作

```
Session ←→ Task ←→ SOP ←→ Episodic ←→ Long-term

正确流程:
1. 从Long-term获取上下文
2. 从Episodic获取近期记忆
3. 从SOP获取执行规范
4. 从Task获取当前任务
5. 在Session中执行
6. 结果写回Task + Episodic
7. 重要沉淀到Long-term
```
