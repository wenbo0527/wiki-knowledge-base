## 教训总结

> **空白页面 ≠ 系统故障，也可能是 URL 错误。先确认路由是否存在，再排查部署问题。**

---

## 问题背景

文博随机抽查 Portal Shell 的子应用页面，发现 `/mkt/interaction` 和 `/dfd/data-flow` 两个 URL 返回空白页面（body 为空）。初始怀疑是部署问题或 JS 运行时错误。

---

## 正确做法

### ✅ 应该做的

1. **先用 Playwright 确认 HTTP 状态和 JS 错误**
   - HTTP 200 + 无 JS 错误 → 排除部署/运行时问题
   - body 为空但无错误 → 路由可能不存在（Vue Router fallback 到空白页面）

2. **检查源码路由清单**
   - `grep -rn "path:" src/router/` 列出所有路由
   - 确认目标路径是否真的在源码中定义

3. **对比 nginx alias 配置**
   - 确认 nginx 配置存在且路径正确
   - 两个都是 200 → nginx 配置没问题

4. **综合判断**
   - 路由不存在 → 不是系统故障，是 URL 误输入
   - 通知相关人正确路径即可

### ❌ 不应该做的

1. **不要在 nginx 配置或部署文件上浪费时间**（配置已确认正确）
2. **不要猜测是 JS 运行时错误**（已排除：Playwright 无 error，控制台干净）
3. **不要假设系统有问题**（标题正确说明 Vue 已加载，只是路由没匹配到组件）

---

## 经验复用

### 排查 Portal Shell 空白页面 SOP

```
1. Playwright 检查：HTTP 状态 + JS 错误 + body 内容长度
   ↓
2. HTTP 403 → 检查 nginx alias 路径 + 文件权限（755）
   ↓
3. HTTP 200 + JS 错误 → 检查 TDZ/minify 问题
   ↓
4. HTTP 200 + 无 JS 错误 + body 为空 → 检查路由是否存在（源码 router/）
   ↓
5. 路由存在但空白 → 检查 index.html 是否存在（nginx try_files fallback）
```

### 适用场景

- 任何 Portal Shell 子应用返回空白页面的排查
- 新增路由后页面不显示的初步判断
