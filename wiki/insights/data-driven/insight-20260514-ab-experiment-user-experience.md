## 一、实验配置位置的优化

### 配置复杂性的根源

| 根源 | 说明 |
|:---|:---|
| **系统流程与业务认知差异** | AB实验部署涉及前端请求、推荐流程等复杂系统链路 |
| **用户选择权的平衡** | 需在满足业务实验诉求与避免系统链路时效影响之间找到平衡 |

### 场景化接入方案

| 应用场景 | 实现方式 | 核心价值 |
|:---|:---|:---|
| **MA产品** | 将AB分流作为画布节点接入 | 降低操作门槛，与现有工作流无缝集成 |
| **物料类实验** | 创建投放策略时加入"开启AB实验"选项 | 减少独立门户跳转 |

### 平台成熟度衡量指标

> **场景接入深度**：AB实验与人群、策略、内容、权益、活动、推荐、营销链路、风控决策等场景配置系统的结合紧密程度

**理想状态**：无需作为独立门户存在，深度融入业务系统

## 二、层与流量比例的科学设置

### 实验分层策略

| 策略 | 说明 |
|:---|:---|
| **预设简化原则** | 产品团队基于实验粒度和场景预设层数 |
| **互斥组** | 实验属主需对已知冲突实验设置互斥组 |
| **父子实验** | 在强管理场景下，构建父子实验实现用户旅程上多个实验的正交性 |

### 流量比例测算

| 参数 | 说明 |
|:---|:---|
| **实验版本数量** | - |
| **核心指标基线** | - |
| **MDE（最小可检测效应）** | 检验灵敏度 |
| **统计功效** | 通常80% |
| **统计显著性** | 通常95% |

## 三、分层实验设计原则

### 核心原则

1. **互斥组设计**：避免互相干扰的实验同时生效
2. **父子实验**：实现用户旅程上的正交性
3. **分流稳定性监控**：对直接相关的流量层进行实时监控
