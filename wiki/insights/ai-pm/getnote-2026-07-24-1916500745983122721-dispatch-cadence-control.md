## 1. Minimax 滑动窗口机制

| 维度 | 限制 |
|:---|:---|
| 计划 | **Token Plan Max** |
| 总量 | 19,834,000 tokens / 5h |
| Reset 机制 | **滑动窗口**（不是固定 5h，是 trailing 5h 用量达到上限）|
| 触发错误 | `FailoverError: ⚠️ usage limit exceeded, 5-hour usage limit reached` |
| 影响 | **派蒙自己不能 sessions_send** 任何消息到 dev/qa/pm |

**核心机制**：每 1h 滑出 1h（5h 前的 token 释放）。**派蒙要在 5h 周期内控制 token 消耗**。

## 3. 派单节奏控制 5 条硬规矩

### 规矩 1：单次派单 ≤ 3 张任务卡
- 超过 3 张必须**分批派**（间隔 30min+）
- 派单消息 ≤ 1500 字（**派单任务描述放 task board，不放派单消息**）

### 规矩 2：派单消息精简模板
**当前派单模板**（约 800-1500 字，含详细 task 描述、命令、验证步骤）→ 派蒙得改成：
- **只发 100-200 字**：包含 task ID + 截止时间 + 关键 1-2 句
- **详细描述放 task board**（task_tool.py 创建时 description 文件）
- 派蒙**不重复** task board 里的内容

### 规矩 3：批量读 → 批量写
- 多次 `read` 工具调用累积 token 大
- 派蒙**先一次性看完整图**（1-2 个 read 拿所有关键文件）
- 然后**批量决策**（1 个回复处理 5+ 任务）
- 避免"小步快跑"——每次小回复都累积 token

### 规矩 4：减少 sessions_send 频次
- 派单 1 次发完 → 等 30min+ 回报
- **不要**：5min 内连发 3 次
- **不要**：派单后立即 sessions_history 查回执
- 派蒙**统一 15min 巡查**（不连续巡查）

### 规矩 5：sessions_send 大消息拆成小消息
- 派单消息**含**派蒙反思、关联任务、命令、SOP 提醒**容易超 1500 字**
- 派蒙**分 2-3 次发**：第 1 次发核心，第 2 次发 SOP 提醒，第 3 次发截止说明
- 或者：**只发核心 + 派蒙反思单独文**

## 4. 派单时机建议

| 优先级 | 时机 | 节奏 |
|:---:|:---|:---|
| **P0** | 立刻 | 单次派单（1-2 张），不等 |
| **P1** | 30min 后 | 累积到 2-3 张一起派 |
| **P2** | 1h 后 | 累积到 3-5 张一起派 |
| **巡查** | 15min/30min/60min | **不连续巡查** |

## 5. 派单模板（精简版，~150 字）

```
[派单 - YYYY-MM-DD HH:MM 派蒙]

文博 HH:MM 拍板「XXX」。

N 张 P0 任务卡（一起做 + 一起 build + 部署-XXX）：
1. TASK-XXX-1 [P0-XXX-#1] 修 XXX（详情见 task board）
2. TASK-XXX-2 [P0-XXX-#2] 修 XXX
3. TASK-XXX-3 [P0-XXX-#3] 修 XXX

截止：HH:MM
回执：「收到 N 张 P0，HH:MM 启动」

派蒙 HH:MM 跟进度。
```

**不再附**：完整 task 描述、命令、5/26 教训、SOP 细节、相关文件路径——这些**全部在 task board 任务卡的 description**里。

## 6. 派单发不出时（usage limit 触发）

| 现象 | 派蒙动作 |
|:---|:---|
| sessions_send 失败 (FailoverError usage limit) | 1. **不重发**（消耗更多 token）<br>2. **写 task board**：把派单内容写到 task 描述（task_tool.py）<br>3. **通知文博**：派单暂时挂了，恢复时间 X<br>4. **5min 内不重复尝试** |
| 5min 后仍 limit | 改用 sessions_history 看 dev 是否主动接 task（task 卡 in_progress 表示 dev 收到）|
| Reset 后 | 立刻重派 + 通知文博 |

## 7. 派单失败影响评估

| 失败类型 | 派单影响 | 派蒙动作 |
|:---|:---|:---|
| sessions_send fail (limit) | dev 没收到，但 task 卡可能 in_progress | 1. 查 task 状态<br>2. 重派（reset 后）|
| dev session 中断 | dev 不会推进 | 派蒙手动 dev 主动回复触发 session |
| gateway restart | dev/qa 全部失联 | gateway 重启后，dev/qa session 自动恢复 |

## 8. 派蒙自检

每 30min 派蒙主动扫：
```bash
# 看派蒙自身 token 用量
openclaw status | grep -i token

# 看 dev/qa 是否在 active 状态
openclaw status | grep "agent:data_community"
```

**如果 token 接近 80%（~16M）**：派蒙**主动减少派单**，**累积** task card 一起发。
