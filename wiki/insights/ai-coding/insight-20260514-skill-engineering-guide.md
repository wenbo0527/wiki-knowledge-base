## 核心开发理念

**Skill开发的工程化思维**

- **本质定位**：开发Skill与维护模块的README+可执行脚本类似，需定义入口契约、调用步骤、权限边界。
- **常见误区**：开发者易陷入"写小作文"惯性，过于注重文档而非实际可执行性。

---

## Skill工程化要点

### 1. 入口契约

| 要素 | 说明 |
|:---|:---|
| **输入** | 什么触发Skill |
| **输出** | Skill产出什么 |
| **前置条件** | 需要什么准备 |
| **后置处理** | 结果如何消费 |

### 2. 调用步骤

```
定义入口 → 解析参数 → 执行逻辑 → 输出结果 → 错误处理
```

### 3. 权限边界

| 权限类型 | 说明 |
|:---|:---|
| **文件访问** | 能读写哪些文件 |
| **网络访问** | 能访问哪些API |
| **命令执行** | 能执行哪些命令 |

---

## 反面案例

> ❌ "写小作文"：过于注重文档，忽略可执行性
> ❌ 缺乏错误处理
> ❌ 权限边界不清晰
