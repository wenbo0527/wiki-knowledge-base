# 大模型智能问数技术路线深度解析：Anthropic 与 OpenAI 的殊途同归及本体智能问数的演进方向

> 🕵️ **Nick 摘要洞察**：智能问数已经从"Text2SQL 准确率"问题升级到"语义层 + 本体建模"问题。两条路径殊途同归：(1) Anthropic 派——Text2DSL + 语义层架构 (2) OpenAI 派——多轮反思 + 工具调用。**文博托尼 PM 的数据 Agent PRD 可直接参考本框架**。

---

## 📌 核心观点

智能问数从早期"Text2SQL 准确率"问题，已升级为**"语义层 + 本体建模"问题**。业界出现两条主流路线殊途同归：

| 路线 | 代表 | 核心思路 |
|:---|:---|:---|
| **Anthropic 派** | Claude Code + MCP | Text2DSL + 语义层架构 |
| **OpenAI 派** | Codex + Agent Harness | 多轮反思 + 工具调用 |

---

## 🔍 技术演进四阶段

### 阶段 1：Text2SQL 直查（2023）
- **核心范式**：自然语言 → 直接生成 SQL → 执行
- **代表项目**：ChatBI / Vanna / 各类 NL2SQL 工具
- **瓶颈**：
  - 大表 JOIN 性能差
  - 业务术语与表字段映射错误率高
  - 跨表关联查询准确率 < 60%

### 阶段 2：Text2DSL + 语义层（2024）
- **核心范式**：自然语言 → DSL（领域特定语言）→ 语义层查询
- **代表项目**：Anthropic Claude Code + MCP / Aloudata Agent / Cube.dev
- **核心组件**：
  - **语义层**：业务术语 ↔ 物理表/字段的标准映射
  - **DSL 抽象**：屏蔽底层 SQL 复杂性
  - **本体建模**：定义业务实体、关系、度量

### 阶段 3：多轮反思 + 工具调用（2025）
- **核心范式**：Agent Harness + 多轮 LLM 反思 + 工具组合
- **代表项目**：OpenAI Codex / LangChain Agent / Hermes Agent
- **核心机制**：
  - **多轮反思**：每一步推理后评估结果，必要时重试
  - **工具调用**：Schema 查询 / 试执行 / 错误恢复
  - **Harness 设计**：把"试错+纠错"封装在执行框架中

### 阶段 4：本体智能问数（2026-）
- **核心范式**：本体（Ontology）+ 推理引擎 + LLM
- **代表项目**：Palantir Ontology / OpenAI Ontology 实验
- **核心思路**：
  - 业务领域知识以**本体图**形式存储
  - LLM 作为推理引擎，本体作为"知识底座"
  - 支持复杂业务推理（如"高净值客户的流失预警"）

---

## 🔀 Anthropic vs OpenAI 路线对比

### Anthropic 派：Text2DSL + 语义层

**核心架构**：
```
用户问题 → 意图识别 → DSL 转换 → 语义层查询 → SQL 生成 → 执行
```

**优势**：
- ✅ 语义层可由业务团队维护，不依赖 LLM 推理
- ✅ 准确率高（语义层做了一次映射）
- ✅ 可解释性（每一步可追溯）

**局限**：
- ❌ 语义层建设成本高
- ❌ 跨域语义难以统一
- ❌ LLM 沦为"翻译器"，智能上限低

### OpenAI 派：多轮反思 + 工具调用

**核心架构**：
```
用户问题 → 任务规划 → Schema 查询 → SQL 生成 → 试执行 → 反思 → 修复 → 最终执行
```

**优势**：
- ✅ 智能上限高（LLM 全程决策）
- ✅ 跨域适应性强
- ✅ 错误恢复能力强

**局限**：
- ❌ 推理成本高（多轮 LLM 调用）
- ❌ 延迟大（多轮 + 试执行）
- ❌ 调试复杂（错误链路长）

## 🎯 演进方向：本体智能问数

### 核心思想

将**本体（Ontology）** 作为智能问数的"知识底座"，LLM 作为"推理引擎"：

```
本体（图） + LLM（推理） + 语义层（业务术语）
```

### 三大组件

| 组件 | 作用 | 代表实现 |
|:---|:---|:---|
| **本体** | 定义业务实体、关系、规则 | Palantir Ontology / Stardog |
| **LLM 推理引擎** | 解析自然语言 + 调用本体查询 | Claude / GPT / 开源模型 |
| **语义层** | 业务术语 ↔ 本体映射 | dbt Semantic Layer / Cube |

### 典型应用场景

1. **金融风控**：本体定义"高净值客户 / 信用违约 / 风险敞口"等概念，LLM 自动推理风险传播路径
2. **零售选品**：本体定义"商品 / SKU / 库存 / 客户偏好"等概念，LLM 推荐最优选品策略
3. **医疗诊断**：本体定义"症状 / 疾病 / 检查 / 治疗"等概念，LLM 辅助诊断决策

## 💡 对文博托尼 PM 的建议

### 数据 Agent PRD 框架

1. **第一阶段（1-3 月）**：Text2DSL + 语义层
   - 优先建设语义层（业务术语 ↔ 物理表）
   - 选型参考：Aloudata Agent / Cube.dev
2. **第二阶段（3-6 月）**：多轮反思增强
   - 在语义层基础上叠加 Agent Harness
   - 选型参考：LangChain Agent / Hermes Agent
3. **第三阶段（6-12 月）**：本体智能问数
   - 引入业务本体建模
   - 选型参考：Palantir Ontology / Stardog

### 关键决策点

- **业务术语复杂度**：如果业务术语多且变化频繁，优先语义层路线
- **智能上限要求**：如果需要复杂推理（如跨域分析），优先多轮反思路线
- **长期投资**：如果定位为"数据 Agent"长期产品，建议同步规划本体层
