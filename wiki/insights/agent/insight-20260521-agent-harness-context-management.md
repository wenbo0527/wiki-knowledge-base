# Agent Harness上下文管理：会话压缩与工作集范式转变

> **版本**: v1.0
> **日期**: 2026-05-21
> **作者**: 尼克·弗瑞
> **来源**: Get笔记-上下文管理研究
> **Tags**: #harness #context-management #session-compression #context-boundary
> **状态**: 新增入库

---

## 核心洞察

> **TL;DR**: 上下文压缩必须保留四要素：目标/已排除方案/错误/下一步，且需守住tool-call/result配对完整性。

### 会话压缩的工程挑战

| 挑战 | 说明 |
|:---|:---|
| **任务可续性** | 压缩后需保持任务可续性 |
| **状态保留** | 需保留用户目标、已排除方案、错误修复、下一步动作 |
| **边界处理** | 避免切断tool-call/result配对 |

---

## 上下文压缩四要素

| 要素 | 必须保留 | 说明 |
|:---|:---|:---|
| **目标** | ✅ | 用户原始目标 |
| **已排除方案** | ✅ | 尝试过但失败的方案 |
| **错误** | ✅ | 已发现的错误和修复方式 |
| **下一步** | ✅ | 下一步要做什么 |

### 为什么这四要素必须保留？

| 要素 | 如果丢失 | 后果 |
|:---|:---|:---|
| **目标** | 不记得要做什么 | 任务迷失 |
| **已排除方案** | 重复尝试失败方案 | 浪费资源 |
| **错误** | 重复犯同样错误 | 效率低下 |
| **下一步** | 不知道下一步 | 任务中断 |

## 自查清单

> **来源**: Agent Harness自查清单

| 检查项 | 说明 |
|:---|:---|
| **工具预算** | 大内容工具是否设硬上限？ |
| **访问路径** | 截断内容是否提供继续访问方式？ |
| **分页参数** | 工具描述是否包含offset/limit等指令？ |
| **压缩维度** | 是否分层保留任务状态（目标/文件/错误/计划）？ |
| **工具边界** | 压缩时是否守住tool call/result完整性？ |
| **子体隔离** | 子智能体是否默认使用独立会话？ |
| **状态持久化** | 关键状态是否迁移至文件/数据库/记忆仓？ |

---

## 上下文管理最佳实践

### 分层保留任务状态

```
工作集分层：
├── 用户目标层（长期保留）
├── 规划层（中期保留）
├── 执行层（短期，可能压缩）
└── 临时层（即时丢弃）
```

### 工具边界完整性

| 要求 | 说明 |
|:---|:---|
| **tool-call完整** | 不要切断配对 |
| **result紧随** | tool-call后必须有result |
| **原子性** | 保持操作原子性 |

### 子体隔离原则

| 原则 | 说明 |
|:---|:---|
| **独立会话** | Sub-agent默认使用独立会话 |
| **上下文不污染** | 不把探索过程带回主上下文 |
| **结果导向** | 只返回结论，不返回过程 |
