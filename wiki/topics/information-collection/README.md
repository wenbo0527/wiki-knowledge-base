## 2. 信息收集方法论

### 2.1 情报收集框架 (ICM)

基于情报学(Intelligence Collection Management)的五步法：

```
┌─────────────────────────────────────────────────────────────┐
│  情报收集周期 (Intelligence Collection Cycle)               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│    ┌──────────────┐                                         │
│    │   需求定义    │ ← 你需要什么信息？                      │
│    └──────┬───────┘                                         │
│           ↓                                                 │
│    ┌──────────────┐                                         │
│    │   来源规划    │ ← 从哪里获取？                          │
│    └──────┬───────┘                                         │
│           ↓                                                 │
│    ┌──────────────┐                                         │
│    │   信息抓取    │ ← 如何获取？                            │
│    └──────┬───────┘                                         │
│           ↓                                                 │
│    ┌──────────────┐                                         │
│    │   分析处理    │ ← 如何提炼？                            │
│    └──────┬───────┘                                         │
│           ↓                                                 │
│    ┌──────────────┐                                         │
│    │   分发应用    │ ← 给谁？怎么用？                        │
│    └──────┬───────┘                                         │
│           ↓                                                 │
│    ┌──────────────┐                                         │
│    │   效果评估    │ ← 效果如何？改进？                      │
│    └──────────────┘                                         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 需求定义矩阵

| 需求类型 | 描述 | 示例 | 收集频率 |
|----------|------|------|----------|
| **战略级** | 长期方向、重大决策 | 行业趋势、技术路线 | 月度 |
| **战术级** | 中期规划、项目推进 | 竞品动态、技术方案 | 周度 |
| **执行级** | 具体任务、即时问题 | 代码实现、工具使用 | 日度 |

### 2.3 来源分级体系

基于RSS情报系统的三级分类：

| 等级 | 数量限制 | 扫描频率 | 适用场景 |
|:---:|---:|:---:|:---|
| **TIER_1** | ≤20源 | 每日 | 核心追踪、深度分析 |
| **TIER_2** | ≤50源 | 每周 | 定期检查、行业动态 |
| **TIER_3** | ≤100源 | 每两周 | 发现线索、拓宽视野 |

**晋升规则**: 30天内产出≥3篇⭐⭐⭐+ → 晋升TIER_1
**降级规则**: 连续30天无⭐⭐⭐+ → 降级；连续60天无任何产出 → 移除

## 4. 五步法实施指南

### Step 1: 需求定义

```
问题模板:
├── 这个信息用来做什么决策？
├── 决策的时间窗口是多久？
├── 信息的置信度要求多高？
├── 如果信息缺失，后果是什么？
└── 谁需要知道这个信息？
```

### Step 2: 来源规划

| 来源类型 | 优点 | 缺点 | 适用场景 |
|----------|------|------|----------|
| **RSS** | 聚合推送、去中心化 | 需要维护、易过时 | 博客、文章 |
| **Twitter/X** | 实时、观点多元 | 噪声大、算法影响 | 热点、动态 |
| **学术论文** | 深度、权威 | 周期长、难读 | 技术方向 |
| **专家访谈** | 深度、独家 | 成本高、偏差大 | 战略决策 |
| **数据平台** | 量化、客观 | 滞后、需解读 | 投资、市场 |

### Step 3: 信息抓取

```
工具矩阵:

┌─────────────────────────────────────────────────────────────┐
│                    信息抓取工具栈                            │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  聚合层                                                      │
│  ├── Feedly/Reeder (RSS阅读)                               │
│  ├── Flipboard (杂志式阅读)                                 │
│  └── 飞书 (企业信息聚合)                                    │
│                                                              │
│  采集层                                                      │
│  ├── RSS Hub (RSS生成)                                      │
│  ├── Get笔记 (网页剪藏)                                     │
│  └── Readwise (跨平台标注同步)                              │
│                                                              │
│  自动化层                                                    │
│  ├── Python脚本 (定时抓取)                                   │
│  ├── Zapier/Make (流程自动化)                              │
│  └── OpenClaw (Agent自动化)                                 │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Step 4: 分析处理

```
分析层次:

Layer 0: 原始保存
   └── 网页快照、PDF、截图

Layer 1: 标注关键
   └── 加粗核心句子

Layer 2: 提炼摘要
   └── 执行摘要、关键洞察

Layer 3: 关联整合
   └── 与已有知识连接、形成观点

Layer 4: 创造性输出
   └── 文章、报告、决策建议
```

### Step 5: 分发应用

```
分发矩阵:

           │ 即时      │ 定期      │ 按需
───────────┼───────────┼───────────┼───────────
给个人    │ 飞书推送  │ 日报/周报 │ 知识库检索
给团队    │ 飞书群    │ Wiki沉淀  │ 专家咨询
给决策层  │ 摘要卡片  │ 深度报告  │ 战略建议
```

## 6. 知识注入流程

### 6.1 输入→处理→输出

```
┌─────────────────────────────────────────────────────────────┐
│                    知识注入流水线                            │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  【输入】                                                     │
│  RSS文章 │ 文档 │ 播客 │ 视频 │ 专家对话                      │
│      │                                                     │
│      ↓                                                     │
│  【处理】                                                     │
│  筛选 → 标注 → 摘要 → 分类 → 关联                           │
│      │                                                     │
│      ↓                                                     │
│  【沉淀】                                                     │
│  案例库 │ 方法论库 │ 工具库 │ 洞察库                         │
│      │                                                     │
│      ↓                                                     │

```

### 6.2 知识质量评估

| 维度 | 评估标准 | 权重 |
|------|----------|-----:|
| **来源权威性** | 是否来自可信来源？ | 20% |
| **内容深度** | 是否有实质洞察？ | 25% |
| **可操作性** | 能否落地执行？ | 20% |
| **可验证性** | 能否用数据验证？ | 15% |
| **时效性** | 是否仍然有效？ | 10% |
| **独特性** | 是否难以复制？ | 10% |

## 8. 常见陷阱与规避

| 陷阱 | 表现 | 后果 | 规避方法 |
|------|------|------|----------|
| **收集癖** | 囤积大量资料从不回顾 | 信息过载、无效努力 | 设置"捕获预算" |
| **完美主义** | 过度整理格式 | 效率低下、延迟行动 | 渐进式总结 |
| **信息孤岛** | 笔记之间无连接 | 难以复用、形成死知识 | 双向链接、定期关联 |
| **只进不出** | 只有输入没有输出 | 知识无法变现 | 设定输出目标 |
| **来源单一** | 只看自己喜欢的内容 | 信息茧房、判断偏差 | 多源交叉验证 |
| **工具病** | 频繁切换工具 | 效率损失、数据分散 | 选定主工具、深入使用 |
