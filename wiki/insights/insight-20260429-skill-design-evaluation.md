## 核心洞察

### 1. 大模型Skill（技能）描述三板框架

#### 第一板：核心价值层

**定义**：技能能解决的核心问题，明确技能的定位。

> 示例："分析Figma设计稿并生成可交付的开发代码"

#### 第二板：能力拆解层

**定义**：罗列式清晰描述技能包含的具体子能力。

> 示例：Figma技能包含以下能力：
> - 提取设计规范（颜色、字体、间距）
> - 生成组件文档（组件名称、变体、状态）
> - 导出标注（像素标注、CSS值）
> - 生成布局代码（HTML/CSS结构）

#### 第三板：激活条件层

**定义**：明确技能应该被触发的具体场景。

包含：
- **正向触发条件**：什么情况下激活此技能（关键字、可信场景）
- **反向约束**：什么情况下禁止触发此技能

> 🚩 **考点**：缺少激活条件会导致技能滥用或误触发

> 🚩 **实践要点**：激活条件是现阶段大模型能力不足的情况下**必须保留的核心部分**，该过渡阶段会持续一年以上，现阶段无法省略。

### 2. 分层评测法

#### 评测维度

| 维度 | 说明 | 权重 |
|------|------|------|
| 准确性 | 输出结果是否正确 | 40% |
| 完整性 | 是否覆盖所有要求的子能力 | 25% |
| 稳定性 | 多次执行结果是否一致 | 20% |
| 性能 | 执行时间、token消耗 | 15% |

#### 评测方法

```
Skill评测流程
├── 单元测试
│   ├── 输入：标准测试用例
│   ├── 期望：精确匹配的输出
│   └── 适用：确定性强的技能
├── LLM评估
│   ├── 输入：开放式测试用例
│   ├── 期望：语义等价
│   └── 适用：开放性强的技能
├── 人工评估
│   ├── 输入：边界案例
│   ├── 期望：人工判断
│   └── 适用：主观性强的技能
└── 自动化回归
    ├── 输入：历史成功案例
    ├── 期望：结果一致
    └── 适用：防止破坏性变更
```

### 3. 长链路任务三原则

#### 原则一：Checkpoint保存

**问题**：长链路任务耗时长，中途失败代价高。

**方案**：在关键节点保存Checkpoint，支持从断点恢复。

```python
# Checkpoint示例
class LongTaskRunner:
    def run(self, task_id, steps):
        checkpoint = self.load_checkpoint(task_id)
        start_step = checkpoint.get('last_step', 0)
        
        for i, step in enumerate(steps[start_step:], start=start_step):
            result = self.execute_step(step)
            self.save_checkpoint(task_id, {
                'last_step': i,
                'results': checkpoint.get('results', []) + [result]
            })
            
            if self.should_checkpoint(step):
                self.save_checkpoint(task_id, {...})
```

#### 原则二：错误边界清晰

**问题**：长链路中错误可能级联放大，难以定位根因。

**方案**：
1. 每个步骤有明确的成功/失败定义
2. 失败时保存完整上下文
3. 错误信息包含步骤ID和输入摘要

#### 原则三：可观测性

**问题**：长链路执行不透明，难以判断进度和状态。

**方案**：
- 结构化日志（步骤、耗时、输入摘要、输出摘要）
- 实时进度推送（WebSocket/SSE）
- 中间结果可查

### 4. 自动化生成Skill的高层级方法

#### 核心思路

```
手工设计Skill → 自动化生成Skill
     ↓                    ↓
  专家经验            轨迹数据 + LLM
     ↓                    ↓
  规则驱动            数据驱动
```

#### 关键步骤

1. **轨迹收集**：让LLM在目标场景执行多次，记录完整轨迹
2. **模式提取**：从轨迹中识别成功案例的共同模式
3. **Skill生成**：基于模式让LLM生成Skill描述
4. **评测迭代**：用分层评测法验证Skill质量
5. **持续优化**：根据实际使用数据迭代改进

## 要点总结

1. **Skill描述三板框**：核心价值 → 能力拆解 → 激活条件
2. **激活条件不可省略**：过渡阶段必备，模型能力不足的补偿机制
3. **分层评测**：准确性40%、完整性25%、稳定性20%、性能15%
4. **长链路三原则**：Checkpoint保存、错误边界清晰、可观测性
5. **自动化生成**：从手工到数据驱动的范式转变
