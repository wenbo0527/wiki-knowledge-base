## 🔍 项目概述

**项目定位**：将Andrej Karpathy的AutoResearch AI研究方法迁移至软件开发领域，构建全自动开发闭环系统。

**核心成果**：实现从GitHub Issue识别、代码实现、测试验证到审核合并的全流程自动化，仅需人工提供Issue号，系统可在**10分钟内完成中等复杂度任务**，代码质量达**9.0/10**标准。

**项目地址**：https://github.com/smallnest/autoresearch

---

## 🧠 技术背景

### Karpathy AutoResearch原理解析

- **核心思想**：AI自主完成ML研究，人类仅维护`program.md`（研究章程）
- **工作流**：AI修改`train.py`→运行5分钟实验→仅保留val loss改善的版本，否则git revert回滚
- **关键指标**：每小时约12次实验，零人工干预实现上百轮优化

### 软件开发领域的迁移逻辑

| ML研究 | 软件开发 |
| :--- | :--- |
| 修改train.py | 实现GitHub Issue |
| 5分钟实验验证 | 自动化测试验证 |
| val loss单一指标 | 5维度加权评分 |

## 🚀 核心改进

### 1. 多Agent交叉审核机制

- **实现方式**：Codex与Claude轮流担任实现者与审核者（A写B审→B写A审）
- **价值**：不同模型盲区互补，解决单Agent自审的视角局限

### 2. 5维度加权评分体系

| 评分维度 | 权重 | 评分标准 |
| :--- | :--- | :--- |
| **正确性** | 35% | 功能实现与需求匹配度 |
| **测试** | 25% | 覆盖率≥70%及边界用例 |
| **代码质量** | 20% | 规范、可读性、架构合理性 |
| **安全** | 10% | 漏洞风险与防护措施 |
| **性能** | 10% | 资源占用与执行效率 |

- **达标线**：总分≥9.0自动提交PR

### 3. 审核反馈驱动迭代

- **机制**：审核结果直接传入下一轮Agent提示词，实现针对性改进而非盲试
- **案例**：Issue #21通过3轮迭代从1.0分提升至9.0分

## 📊 系统架构与工作流

### 四阶段工作流

```
Phase 1: 环境准备 → Phase 2: 迭代核心 → Phase 3: 自动提交 → Phase 4: 记录归档
```

### 核心原则

1. **program.md即宪法**：定义Agent权限边界
2. **多Agent对抗**：交叉验证确保质量
3. **量化门槛**：评分≥9.0为唯一通过标准
4. **反馈驱动**：基于审核结果定向优化

## 💡 关键洞察

1. **多Agent交叉审核**：不同模型盲区互补，显著优于单Agent方案
