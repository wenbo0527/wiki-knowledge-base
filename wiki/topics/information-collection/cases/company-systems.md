## 2. Stripe

### 2.1 基本信息

| 字段 | 内容 |
|------|------|
| **背景** | 支付基础设施，估值950亿美元 |
| **工程师文化** | 极强，代码质量至上 |
| **情报特点** | 内部知识高度共享、文档完善 |

### 2.2 情报系统分析

```
信息来源:
├── 每周1300+ Pull Requests
├── 内部代码审查
├── 技术雷达 (Technology Radar)
├── 学术论文追踪
└── 开源项目监控

收集方法:
├── Minions Blueprint (自动化任务编排)
├── 工程师自发贡献
├── 文档即代码
└── 内部Wiki

特点:
├── 所有文档公开可见
├── PR必须附带文档
├── 每周工程周报
└── 内部技术分享
```

### 2.3 核心实践

```
✅ Stripe的文档飞轮:

代码实现
    ↓
同步文档更新
    ↓
PR审查包含文档
    ↓
合并后自动发布
    ↓
全公司可见
    ↓
新人快速上手
```

## 3. Google

### 3.1 基本信息

| 字段 | 内容 |
|------|------|
| **背景** | 全球最大科技公司之一 |
| **SRE文化** | 可靠性、稳定性至上 |
| **情报特点** | 事后分析、复盘驱动 |

### 3.2 情报系统分析

```
信息来源:
├── 内部代码仓库 (全球最大之一)
├── Postmortem (故障复盘)
├── 设计文档 (Design Docs)
├── 学术研究 (Google Research)
└── 内部技术分享

收集方法:
├── 全面文档化
├── 复盘无责文化
├── 知识库搜索
└── 跨团队分享
```

### 3.3 Postmortem文化

```
Google Postmortem模板:

## 事件摘要
- 时间:
- 影响:
- 根本原因:

## 时间线
- (详细时间线)

## 根本原因分析
- (5Why分析)

## 经验教训
- (学到了什么)

## 行动项
- [ ] 短期修复
- [ ] 长期改进
```

## 7. 通用模式总结

### 7.1 公司情报类型

```
┌─────────────────────────────────────────────────────────────┐
│                    公司情报四象限                            │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│        外部情报                    内部情报                   │
│    ┌─────────────┬─────────────┐                           │
│    │             │             │                           │
│  高 │  竞品动态   │  技术文档   │ ← 战略性                 │
│    │  行业趋势   │  架构决策   │                           │
│    │  客户反馈   │  复盘总结   │                           │
│    ├─────────────┼─────────────┤                           │
│    │             │             │                           │
│  低 │  新闻舆情   │  工作日志   │ ← 日常性                 │
│    │  社交媒体   │  会议记录   │                           │
│    │             │             │                           │
│    └─────────────┴─────────────┘                           │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 知识管理成熟度

| 等级 | 特征 | 风险 |
|------|------|------|
| **Level 1** | 知识散落、依赖个人 | 🔴 知识流失 |
| **Level 2** | 有Wiki、但搜索难 | 🟠 更新不及时 |
| **Level 3** | 有模板、有分类 | 🟡 跨团队难 |
| **Level 4** | 文档随代码走 | 🟢 持续改进 |
| **Level 5** | 知识图谱、AI发现 | 🟢 智能化 |

### 7.3 最佳实践

```
✅ 文档即代码
├── 文档随代码提交
├── PR包含文档更新
└── 文档是代码的一部分

✅ 无责复盘
├── 错误是学习机会
├── 复盘文档公开
└── 持续改进

✅ 内部知识共享
├── 跨团队分享
├── 每周技术分享
└── 知识集中沉淀

✅ 外部情报追踪
├── 技术雷达
├── 竞品监控
└── 行业研究
```
