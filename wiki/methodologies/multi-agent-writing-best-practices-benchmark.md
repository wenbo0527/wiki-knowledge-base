```python

task_id = "TASK-20260518-3E5CEBF6"
```

### 维度 3 · 写作纪律（9/10 vs 5/10）

**v1.0 实践**：

```
C-1 禁止口头承诺 · write 实证后才回 "已完成"
C-2 length 截断 · 单轮 ≤ 1500 字
C-3 每日 21:00 cron · "写"vs"已完成" ratio 扫描
+ L-37 报告必调实时 API
+ L-38 Agent 数量必用 openclaw agents list
+ L-29 真实数据 · 不 mock
+ L-50.5 INC 5 必检（截止/源/分类/覆盖/洞察）
```

**行业基准**：

```
多数 AI Agent 写作系统：
- 无显式 "write 实证" 铁律（口头承诺常见）
- 无 length 截断分段（length 截断丢失中间内容）
- 无实时数据 API 调用（用 v1.0 备份印象）
- 无覆盖率真实校验（"我以为有 4 个 KB" 错误）
```

**差距分析**：
- ✅ v1.0 强项：**C-1/C-2/C-3 + L-29/L-37/L-38 + L-50.5**（5+ 族硬约束）
- ⚠️ v1.0 弱项：**未集成 27 Agent 设计模式**（insight-20260429 提及 27 模式）
- 📊 差距：v1.0 **大幅领先 4 分**（行业普遍无硬约束）

```

1. 不替文博决策（决策权在文博）
2. 不假设需求（追问场景 → 确认需求）
3. 不隐瞒问题（透明推理 · INC 闭环留痕）
4. 不擅自 push（git push 等文博授权）
5. 不擅自 send（外部消息必先确认）
```

**行业基准**：

```
多数 AI Agent 系统：
- 越权 push 频繁（"我以为用户同意了"）
- 越权 send 频繁（自动发邮件/IM）
- 无显式边界铁律（错误后才有边界）
- 同根病频繁（重复犯同根问题）
```

**差距分析**：
- ✅ v1.0 强项：**5 边界铁律 + L-49.10 + 4 次同根病防御**

### 差距 1（🔴 P0）· Sub-Agent vs Agent Team 决策框架

**行业基准（insight-20260521）**：

```markdown
## Sub-Agent vs Agent Team 决策框架

### Sub-Agent 适用场景
1. 隔离探索（压混乱为干净结论）
2. 压缩信息（只返回结论和证据）
3. 独立调查（不依赖主流程）

### Agent Team 适用场景
1. 持续协作（前一个改完，所有人都要立即知道）
2. 共享状态（处理冲突、可见性、版本化）
3. 实时同步（接口契约变更需即时通知）

### 决策 7 项检查清单
| # | 检查项 | 如果是 |
|:---|:---|:---|
| 1 | 独立调查？ | → Sub-Agent |
| 2 | 上下文污染？ | → Sub-Agent |
| 3 | 子 Agent 只读 vs 写？ | → 只读更适合 Sub-Agent |
| 4 | 子任务强依赖？ | → 强依赖慎拆 |
| 5 | 结果合并边界清楚？ | → 边界清楚有价值 |
| 6 | 持续协作？ | → Agent Team |
| 7 | 共享可变状态？ | → Agent Team |
```

```markdown
## §01.5  上下文边界优先于角色原则

> 核心原则：Design around context boundaries, not roles.

分拆决策三问：
1. 这两件事，需不需要看到对方的中间过程？
2. 这两件事，会不会因为对方做完了某一步就影响自己下一步？
3. 如果交给同一个 Agent 一次性做完，会不会更省心？

如果答案偏向 "是"，那它们本就该在一起，不该被拆开。
```
