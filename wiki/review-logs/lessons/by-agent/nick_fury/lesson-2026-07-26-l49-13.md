## L-49.13：看门狗必须"通用扫描"，绝不依赖白名单

**陷阱**：每个新 cron / plist / 脚本都要"手动加白名单"——白名单迟早会漏：
- 新 cron 注册但没白名单 → 盲区
- 有人忘了注册白名单 → 看门狗不全
- 删了的 cron 还在白名单 → 假阳性浪费调研时间
- 白名单维护成本 > 看门狗本身的价值

**治本**：
1. **argv 看门狗**：扫 `openclaw cron list --json` 返回的所有 cron argv（不依赖白名单）
2. **plist 看门狗**：扫 `/Users/wenbo/Library/LaunchAgents/*.plist` 所有 plist
3. **脚本路径看门狗**：扫 `scripts/*.py` 所有脚本
4. **L-49.13 原则**：不维护白名单（除非有强需求如"豁免列表"）

**复用场景**：所有"防退化"型看门狗——
- cron argv / plist argv / 脚本路径 / KB 列表 / Agent 列表
- 通用扫描 + 单一真相源（api/list 的实时结果）
- 维护白名单 = 反模式

---

## 反模式 vs 治本对比

| 维度 | 反模式（❌）| 治本（L-49.12/13）|
|:---|:---|:---|
| **白名单维护** | 每次新加都要手动维护 | 0 维护 |
| **新元素覆盖** | 易漏（依赖人为记得加）| 100% 自动 |
| **回归风险** | 高（白名单 vs 实际列表漂移）| 0（数据源实时）|
| **可读性** | 看门狗代码 + 白名单 + 注册流程 | 单一看门狗 |
| **L-50.4 合规** | ❌ 会留白名单硬编码 | ✅ 不写硬编码 |
