## 三、需求 1：短信短链打开率监测

### 3.1 业务背景

当前短信触达只能追踪"发送→送达"的链路状态，无法衡量用户是否真正打开了短信中的短链。运营同学无法回答：

- 这批营销短信，用户到底点没点？
- 不同文案/人群/时段的短链打开率差异如何？
- 短信投放ROI怎么算？没有点击数据，只能靠"发了多少"估算

### 3.2 业务诉求

- **来源**：已与敏敏沟通确认
- **运营同学**：短信触达模板中增加一个6位长参数，用于监测短信短链的打开率
- **数据统计放至BI**：打开率数据不在触达系统内展示，统一走BI看板
- **敏捷提供数据逻辑**：6位参数的生成规则、归因逻辑、统计口径由敏捷团队定义

### 3.3 业务范围


| 项        | 内容                            |
| -------- | ----------------------------- |
| **新增参数** | 短信触达模板增加6位长参数，用于短链打开率监测       |
| **参数位置** | 短信模板中的短链URL内，作为追踪参数附加         |
| **参数生成** | 触达系统生成，具体编码规则待敏捷定义            |
| **数据归因** | 用户点击短链 → 6位参数回传 → 归因到对应短信发送记录 |
| **数据统计** | 统计结果放至BI，不在触达系统内展示            |
| **数据逻辑** | 由敏捷团队提供（参数生成规则、归因口径、统计维度）     |


### 3.4 业务验收标准


| 验收项       | 标准                               |
| --------- | -------------------------------- |
| **参数可配置** | 短信触达模板支持配置6位监测参数                 |
| **参数可生成** | 每条短信发送时自动生成唯一6位参数，附加到短链URL       |
| **数据可回传** | 用户点击短链后，6位参数能回传并归因到发送记录          |
| **BI可统计** | BI看板能基于回传数据统计短链打开率（按模板/人群/时段等维度） |


### 3.5 不在本 PRD 范围

- ❌ 6位参数的具体编码规则（由敏捷团队定义）
- ❌ BI看板的设计与开发（由BI团队负责）
- ❌ 短链生成服务本身的架构（假设已有短链服务）
- ❌ 非短信渠道的打开率监测（本期只做短信）

### 3.6 待确认项


| #   | 待确认                                | 我的默认            | 你的拍板 |
| --- | ---------------------------------- | --------------- | ---- |
| 1   | 6位参数是纯数字还是字母数字混合？                  | 待敏捷定义           | ⬜    |
| 2   | 6位参数的容量（6位数字=100万，6位字母数字≈20亿）是否够用？ | 待敏捷评估           | ⬜    |
| 3   | 参数是每条短信唯一，还是每批次/每模板唯一？             | 每条短信唯一（才能归因到个体） | ⬜    |
| 4   | 短链服务是否已有？还是需要新建？                   | 待确认             | ⬜    |

## 五、需求 3：CDP标签下发

### 5.1 业务背景

当前触达系统下发消息时，模板中的个性化内容（如客户姓名、贷款金额等）只能硬编码或从有限数据源获取。但消费金融场景中，运营需要基于CDP的丰富标签做个性化触达——比如：

- "尊敬的{客户姓名}，您的{贷款产品}已审批通过，额度{授信额度}元"
- 不同风险等级的客户收到不同措辞的还款提醒

这些个性化字段来自CDP的用户标签，当前触达系统无法直接获取。

### 5.2 业务诉求

- **运营同学**：在触达模板中使用标签占位符（如 `{{标签实例ID}}`），系统自动替换为用户真实的标签值
- **MA系统**：在配置营销策略时，将CDP标签同步到MA；MA下发触达任务时，自动组装标签值到模板中

### 5.3 协作链路

```
┌─────────┐    ①配置模板时      ┌─────────┐    ②配置策略时      ┌─────────┐
│  触达    │ ──────────────────→ │   MA    │ ──────────────────→ │  CDP    │
│  系统    │  使用标签占位符      │  系统   │  同步标签到MA       │  系统   │
│         │                     │         │                     │         │
│         │ ←────────────────── │         │ ←────────────────── │         │
│         │    ③MA下发时        │         │    ②获取标签值      │         │
│         │    组装标签值到模板   │         │                     │         │
└─────────┘                     └─────────┘                     └─────────┘
```

**三步流程**：

1. **触达系统配置模板**：运营在触达模板中使用标签占位符（按标签实例ID引用CDP标签）
2. **MA配置策略时同步标签**：MA配置营销策略时，将涉及的CDP标签同步到MA策略中
3. **MA下发时组装**：MA下发触达任务时，从CDP获取用户标签值，组装到模板中，完成个性化触达

### 5.4 业务范围


| 项        | 内容                                  |
| -------- | ----------------------------------- |
| **标签来源** | CDP系统的用户标签（按标签实例ID引用）               |
| **占位方式** | 触达模板中使用标签占位符，占位符对应CDP的标签实例ID        |
| **同步机制** | MA配置策略时，将涉及的CDP标签同步到MA              |
| **组装时机** | MA下发触达任务时，实时从CDP获取用户标签值并组装到模板       |
| **标签类型** | 支持CDP已定义的标签类型（属性标签/行为标签/规则标签），本期不限制 |
| **降级策略** | 标签值获取失败时，模板中使用默认值或跳过该占位符（不阻塞下发）     |


### 5.5 业务验收标准


| 验收项       | 标准                           |
| --------- | ---------------------------- |
| **占位符可配** | 触达模板支持配置标签占位符，占位符绑定CDP标签实例ID |
| **标签可同步** | MA配置策略时能同步CDP标签到策略中          |
| **值可组装**  | MA下发时能从CDP获取用户标签值并替换到模板占位符   |
| **降级可用**  | 标签值获取失败时不阻塞下发，使用默认值          |
| **一致性**   | 触达内容中的标签值与CDP当前标签值一致         |


### 5.6 不在本 PRD 范围

- ❌ CDP标签的定义与管理（由CDP系统负责）
- ❌ MA策略的编排逻辑（由MA系统负责）
- ❌ 标签值的实时性保障（SLA由CDP定义）
- ❌ 标签权限管控（由CDP的权限体系负责）

## 六、需求 4：促实名策略差异化下发

### 6.1 业务背景

消费金融业务中存在一类特殊策略——**促实名策略**：用户尚未完成实名认证，系统只有手机号，没有身份证号等核心身份参数。

当前触达系统下发时，默认携带核心参数（如身份证号、客户姓名等）。但促实名策略的目标用户恰恰是未实名用户，核心参数不存在——如果强行携带，要么下发失败，要么传空值导致下游异常。

这本质上是**策略类型决定下发参数集**的需求：不同策略类型，下发时使用的身份字段不同。

### 6.2 业务诉求

- **运营同学**：配置策略时能标记为"促实名策略"，系统自动切换下发参数逻辑
- **系统层面**：当策略为促实名策略时，下发取手机号字段外发，不支持原有核心参数

### 6.3 业务范围


| 项             | 内容                                         |
| ------------- | ------------------------------------------ |
| **策略类型**      | 新增"促实名"策略类型标识，与现有策略类型并列                    |
| **促实名策略下发规则** | 取手机号字段进行外发；不支持原有核心参数（身份证号、客户姓名等）           |
| **普通策略下发规则**  | 保持原有逻辑不变，携带核心参数                            |
| **策略类型判定**    | 由MA/运营在配置策略时标记，触达系统按标记切换下发逻辑               |
| **参数差异**      | 促实名策略：手机号（必传）+ 模板内容；普通策略：手机号 + 核心参数 + 模板内容 |


### 6.4 参数对比


| 参数       | 普通策略      | 促实名策略               |
| -------- | --------- | ------------------- |
| 手机号      | ✅ 必传      | ✅ 必传                |
| 身份证号     | ✅ 核心参数    | ❌ 不支持（用户未实名）        |
| 客户姓名     | ✅ 核心参数    | ❌ 不支持（用户未实名）        |
| 其他核心参数   | ✅ 按模板配置   | ❌ 不支持               |
| CDP标签占位符 | ✅ 支持（需求3） | ⚠️ 部分支持（仅限非实名依赖的标签） |
| 6位监测参数   | ✅ 支持（需求1） | ✅ 支持                |


### 6.5 业务验收标准


| 验收项          | 标准                                 |
| ------------ | ---------------------------------- |
| **策略类型可配**   | MA/运营配置策略时能标记为"促实名策略"              |
| **参数自动切换**   | 促实名策略下发时自动取手机号外发，不携带核心参数           |
| **普通策略不受影响** | 非促实名策略的下发逻辑保持不变                    |
| **下发成功率**    | 促实名策略因参数缺失导致的下发失败率=0               |
| **模板校验**     | 促实名策略绑定模板时，校验模板是否包含核心参数占位符，有则提示不可用 |


### 6.6 不在本 PRD 范围

- ❌ 促实名策略的业务规则设计（如触达频次、话术策略——由运营/业务方负责）
- ❌ 用户实名状态的判断逻辑（由CDP/客群中心的标签体系提供）
- ❌ 促实名策略的触发条件（由MA策略编排决定）

## 七、跨需求关联

### 7.1 需求间依赖


| 依赖关系          | 说明                                                                       |
| ------------- | ------------------------------------------------------------------------ |
| 需求1 × 需求3     | 短信模板中的6位监测参数（需求1）和标签占位符（需求3）可能共存于同一模板——模板引擎需支持多类型占位符混合                   |
| 需求2 × 需求3     | AI外呼的话术模板也可能需要标签占位——需求3的标签下发能力需覆盖AI外呼渠道，不仅限于短信                           |
| 需求1 × 需求2     | AI外呼场景是否也需要"打开率"类监测？本期先只做短信短链                                            |
| **需求3 × 需求4** | 促实名策略下，CDP标签占位符只能使用非实名依赖的标签（如手机号归属地），不能使用实名依赖的标签（如授信额度）——模板校验需区分标签是否依赖实名 |
| **需求2 × 需求4** | AI外呼场景也可能有促实名策略——外呼话术中不能引用核心参数                                           |
| **需求1 × 需求4** | 促实名策略的短信同样需要短链打开率监测，6位参数不受策略类型影响                                         |
