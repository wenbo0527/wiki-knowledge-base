### 钟离当前短板

| 短板 | 具体表现 |
|------|---------|
| **第4角：代码理解** | 主要擅长新代码生成，理解现有代码能力较弱 |

## 二、代码理解能力的技术实现

### 2.1 核心技术架构

代码理解本质上是**把代码转化为AI可理解的语义表示**：

```
代码 → AST抽象语法树 → 图结构(Call Graph) → 向量嵌入 → 语义检索 → LLM理解
```

### 2.2 关键技术组件

| 组件 | 功能 | 现有工具 |
|------|------|---------|
| **代码解析器** | 生成AST和语法树 | Tree-sitter, LSP |
| **图构建器** | 构建Call Graph, Dependency Graph | code², Sourcegraph |
| **向量索引** | 语义检索代码片段 | ChromaDB, FAISS |
| **RAG引擎** | 检索增强代码生成 | Ranger, Code RAG |
| **上下文管理** | 管理代码窗口大小 | Cursor, Copilot |

## 三、提升方案

### 方案一：代码库索引系统（推荐）

**原理**：为现有代码库建立索引，让Agent能快速检索和理解代码结构。

**实现步骤**：

```
1. 代码解析
   - 使用Tree-sitter解析代码生成AST
   - 提取函数定义、调用关系、类型信息

2. 图结构构建
   - 构建Call Graph（调用图）
   - 构建Dependency Graph（依赖图）
   - 构建Import Graph（导入图）

3. 语义索引
   - 为每个函数/类生成向量嵌入
   - 存储到向量数据库（ChromaDB）

4. 检索增强
   - 用户提问时，先检索相关代码片段
   - 把检索结果注入LLM上下文
```

**开源工具**：

| 工具 | 特点 | 适用场景 |
|------|------|---------|
| **Sourcegraph Cody** | 代码理解+检索增强 | 闭源/大型代码库 |
| **RAGstack** | 代码RAG专用 | 需要RAG的场景 |
| **Beyonder** | 上下文窗口优化 | 长代码文件 |
| **Lemmy** | 代码语义搜索 | 代码库检索 |

### 方案二：CLAUDE.md项目文档（推荐）

**原理**：为每个项目编写CLAUDE.md文档，沉淀代码结构知识。

**文档结构**：

```markdown
# 项目名称

## 技术栈
- 后端：Spring Boot 2.7
- 前端：React 18
- 数据库：PostgreSQL

## 代码结构
```
src/
├── controller/    # API层
├── service/       # 业务逻辑层
├── repository/    # 数据访问层
└── model/         # 实体类
```

## 核心模块说明

### 用户模块 (user/*)
- 功能：用户注册、登录、权限管理
- 关键类：UserController, UserService, UserRepository
- 依赖：Spring Security, JWT

### 订单模块 (order/*)
- 功能：订单创建、支付、取消
- 关键类：OrderController, OrderService, OrderRepository
- 依赖：支付服务、库存服务

## 常见修改模式

### 新增API
1. 在Controller新增接口
2. 在Service实现业务逻辑
3. 在Repository实现数据访问
4. 添加单元测试

### 修改现有功能
1. 先搜索相关模块
2. 了解调用链
3. 评估影响范围
4. 编写测试用例
5. 修改代码

## 项目规范

### 代码风格
- 命名：驼峰命名
- 注释：关键逻辑需要注释
- 分层：Controller → Service → Repository

### Git规范
- 分支：feature/xxx, bugfix/xxx
- Commit：feat: | fix: | docs:
```

### 方案三：代码理解专用Prompts

**原理**：优化Prompt设计，让Agent在理解代码时更加结构化。

**关键Prompt模板**：

```markdown
## 代码理解任务模板

### 1. 结构理解
请分析以下代码的结构：
```
[代码片段]
```

请输出：
1. 代码分层（Controller/Service/Repository等）
2. 各层职责说明
3. 模块间的调用关系

### 2. 逻辑理解
请分析以下函数的业务逻辑：
```
[函数代码]
```

请输出：
1. 函数功能说明
2. 输入输出
3. 关键逻辑步骤
4. 异常处理逻辑

### 3. 影响分析
如果修改[函数A]，请分析对以下模块的影响：
```
[模块列表]
```

请输出：
1. 直接影响模块
2. 间接影响模块
3. 需要回归测试的范围
```
