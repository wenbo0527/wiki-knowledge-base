### 1. 需求概述
- **需求名称**: 元数据管理

- 元数据血缘分析（属于数据发现域）
- 元数据质量检测（属于数据标准域）

### 4. 验收标准
- [ ] 模型创建成功率 > 95%
- [ ] 字段录入完整性 > 90%
- [ ] 上下架流程可追溯
- [ ] 检索响应时间 < 2秒

## 1. 产品概述

### 1.1 目标
元数据管理系统提供企业级元数据的统一建模、采集、存储与检索能力，支持数据资产、要素、资源的上下架管理，构建完整的元数据资产视图。

### 1.2 痛点
1. **元数据分散**：各系统元数据散落，缺乏统一建模和管理入口
2. **采集成本高**：元数据采集依赖人工维护，成本高且容易遗漏
3. **上下架混乱**：资产、要素、资源缺乏统一的上下架管理机制
4. **标签缺失**：元数据缺乏标签体系，检索和分类困难

| 字段 | 内容 |

### 7.5 数据库设计

#### Neo4j Schema

```cypher
// 元数据模型节点
(:MetadataModel {
  id: String,
  name: String,
  type: String,  // 'business' | 'technical'
  version: Integer,
  status: String,  // 'draft' | 'published' | 'deprecated'
  createdAt: DateTime,
  updatedAt: DateTime
})

// 元数据字段节点
(:MetadataField {
  id: String,
  name: String,
  type: String,  // 'STRING' | 'INT' | 'BIGINT' | 'DECIMAL' | 'DATE' | 'DATETIME' | 'JSON' | 'ARRAY'
  required: Boolean,
  defaultValue: String,
  comment: String,
  order: Integer
})

// 标签节点
(:Tag {
  id: String,
  name: String,
  color: String,
  description: String,
  createdAt: DateTime
})

// 关系
(:MetadataModel)-[:HAS_FIELD]->(:MetadataField)
(:MetadataEntity)-[:BELONGS_TO]->(:MetadataModel)
(:MetadataEntity)-[:TAGGED_WITH]->(:Tag)
```

#### MySQL Schema

```sql
-- 标签表
CREATE TABLE `tag` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `name` VARCHAR(50) NOT NULL COMMENT '标签名称',
  `color` VARCHAR(20) NOT NULL COMMENT '标签颜色',
  `description` VARCHAR(200) COMMENT '标签描述',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 上下架记录表
CREATE TABLE `listing_record` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `entity_type` VARCHAR(20) NOT NULL COMMENT '类型: asset/element/resource',
  `entity_id` BIGINT NOT NULL COMMENT '实体ID',
  `action` VARCHAR(10) NOT NULL COMMENT '操作: listing/offline',
  `reason` VARCHAR(200) COMMENT '上下架原因',
  `operator` VARCHAR(50) NOT NULL COMMENT '操作人',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
);
```
