## 三、具体方法论详情

### 1. 模型可解释性方法

**核心**：怎么解释AI决策

**成熟框架**：
| 方法 | 说明 |
|:---|:---|
| **敏感性分析** | 预测对输入变化的敏感程度 |
| **特征重要性** | 哪些特征影响最大 |
| **决策路径** | AI是怎么得出结论的 |

**实践要点**：
- 让业务方理解AI为什么这么做
- 便于发现模型偏见
- 支持审计追溯

**✅ 实践案例：风控模型可解释性**
- 背景：风控模型判断客户风险等级，需要解释
- 解释维度：
  - 特征重要性：收入、负债、历史逾期等
  - 决策路径：规则引擎→模型评分→综合判断
  - 敏感性分析：年龄+1岁，风险变化多少
- 业务价值：
  - 风控人员能理解模型决策
  - 能发现模型的潜在偏见
  - 能支持监管审计

**关键经验**：金融场景必须有可解释性，不只是"黑盒"结果

### 2. 风控机制方法

**核心**：怎么设计刹车系统

**成熟框架**：
```
数据 → 模型 → 输出 → 人工兜底
```

**风控层级**：
| 层级 | 机制 | 说明 |
|:---|:---|:---|
| **预防** | 输入校验 | 过滤明显异常输入 |
| **检测** | 置信度监控 | 低置信度触发告警 |
| **干预** | 人工审核 | 关键决策人工复核 |
| **恢复** | 降级方案 | 服务降级/兜底策略 |

**实践要点**：
- 每个AI功能都要有兜底机制
- 关键场景必须有人工复核
- 设定自动降级阈值

**✅ 实践案例：ChatBI置信度+人工兜底**
| 场景 | 置信度 | 机制 |
|:---|:---:|:---|
| 标准SQL生成 | >90% | 直接返回结果 |
| 复杂查询 | 70%-90% | 显示置信度提示 |
| 模糊语义理解 | 50%-70% | 建议用户确认 |
| 低置信查询 | <50% | 转人工或拒绝 |

**兜底机制**：
- 高风险操作（删除/修改）：必须人工确认
- 低置信输出：显示"仅供参考"
- 系统不可用：降级为预设报表

**关键经验**：不是让AI完全替代人，而是人机协作

### 3. 伦理治理方法

**核心**：怎么保证合规

**成熟框架**：
| 维度 | 说明 |
|:---|:---|
| **无偏见** | 避免歧视和偏见 |
| **无歧义** | 团队对模型理解一致 |
| **透明性** | 能追溯AI决策过程 |
| **隐私保护** | 用户数据安全 |
| **合规审计** | 满足监管要求 |

**实践要点**：
- 建立伦理审查清单
- 定期审计模型偏见
- 满足GDPR等合规要求

**✅ 实践案例：埋点数据治理合规**
- 背景：埋点数据涉及用户隐私，需要合规
- 隐私保护：
  - 敏感字段（手机号、身份证）加密存储
  - 用户授权才能采集行为数据
  - 数据保留期限设置（90天后自动清理）
- 合规审查：
  - 埋点方案必须经过合规团队审批
  - 数据使用必须符合授权范围
  - 定期生成合规报告

**关键经验**：合规不是事后补救，而是前置要求

## 四、风控设计检查清单

```
□ 输入校验机制（过滤异常）
□ 置信度阈值设定（高/中/低）
□ 低置信度告警（自动告警）
□ 人工介入机制（关键操作复核）
□ 降级兜底方案（服务降级）
□ 审计日志记录（操作可追溯）
□ 偏见检测机制（定期检测）
□ 合规审查流程（前置审批）
□ 隐私保护措施（数据脱敏）
□ 合规审计报告（定期生成）
```
