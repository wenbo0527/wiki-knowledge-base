## 一、当前痛点

主流代码文档工具存在三大核心问题：

| 问题 | 说明 |
|:---|:---|
| **理解能力不足** | 无法解析代码间的调用、依赖与结构 |
| **效率低下** | 全量文档生成需几小时，成本高 |
| **更新机制缺陷** | 全量重生成（资源浪费）或表面修改（易漏改） |

## 三、RepoKG仓库知识图谱构建

### 步骤与关系

| 步骤 | 关键操作 |
|:---|:---|
| **AST解析** | 提取函数/类/接口/模块等代码实体 |
| **结构关系抽取** | 识别导入/包含/继承/实现/调用4类关系 |
| **语义增强** | 识别概念实体与语义影响关系 |

### 输出：3类实体 + 7类关系

**实体**：
- 代码实体
- 概念实体（如User、Auth、Cache）
- 文档实体

**关系**：
- 调用、实现、继承、导入、包含、语义影响、描述

## 四、模块聚类：按功能内聚的层次化分组

### 实现流程

- **聚类算法**：基于DeepSeekV3.2的自顶向下递归聚类
- **拆分规则**：顶层K=5，子层K=3、4096token阈值

### 输出

项目 → 模块 → 子模块 → 类/函数的树形结构

---

## 五、增量更新：精准高效的文档同步

### 步骤

| 步骤 | 实现方式 |
|:---|:---|
| **变更检测** | AST对比Git提交差异 |
| **影响传播** | RepoKG双向遍历（下游+上游） |
| **更新顺序** | Kahn算法拓扑排序 |
| **文档再生** | 仅选择性更新受影响片段 |
| **校验机制** | 规则验证 + LLM校验 |

### 性能优势

> 相比全量生成方案，增量更新可减少**70%以上**的计算资源消耗
