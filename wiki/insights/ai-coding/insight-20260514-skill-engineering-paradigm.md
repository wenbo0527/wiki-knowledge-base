## Skill的本质定义

> Skill **不是** Prompt——它是围绕**任务、工具、流程和输出边界**的结构化行为设计。

---

## 核心要素

| 要素 | 说明 |
|:---|:---|
| **任务** | Skill要完成什么 |
| **工具** | Skill可以使用什么 |
| **流程** | Skill如何执行 |
| **输出边界** | Skill的交付物是什么 |

---

## 工程化要点

### 1. 规范标准

| 标准 | 说明 |
|:---|:---|
| **输入规范** | 明确的输入格式和类型 |
| **输出规范** | 明确的输出格式和质量要求 |
| **错误处理** | 异常情况的处理方式 |
| **日志规范** | 执行过程的记录要求 |

### 2. 构建方法论

```
需求分析 → 结构设计 → 工具选型 → 流程编排 → 测试验证
```

### 3. 设计模式

| 模式 | 适用场景 |
|:---|:---|
| **Chain** | 顺序执行的任务 |
| **Parallel** | 并行处理的任务 |
| **Conditional** | 条件分支的任务 |
| **Loop** | 循环迭代的任务 |

---

## 与Prompt的区别

| 维度 | Prompt | Skill |
|:---|:---|:---|
| **定义方式** | 自然语言描述 | 结构化设计 |
| **执行确定性** | 依赖模型理解 | 可预测执行 |
| **复用性** | 难复用 | 可复用 |
| **测试性** | 难测试 | 可测试 |
