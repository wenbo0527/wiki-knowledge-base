---

## 2️⃣ 根因（5 层）

### 2.1 报告模板缺失数据基准日
`etf_hegang_report.py` 只在第一行写日期，**没有标注"数据基准日 + 真实/preset 比例"**——读者无法判断数据新旧。

### 2.2 报告模板缺失数据源标签
`1.1 行业规模判断` 等表格只列"分位"，**没有"数据源"列**——读者无法判断是 API 实时数据还是 preset 兜底。

### 2.3 etf_percentile_today.json 7-14 真空
7-14 之前由 `scripts/etf_percentile_fetcher.py` 写，7-14 重构后脚本归档到 `_deprecated/2026-07-14/`，**没人写这个文件**。7-14 09:12 之后再没更新过。

### 2.4 data_source 字符串歧义
fetcher v2.5 的 `data_source` 字段在真实源路径也带"预设估值"字样（如 `"腾讯备用源(8-4 L-55) + 预设估值"`），**用 `'预设' in ds` 判断会误判腾讯备用源为 preset**。

### 2.5 缺少数据新鲜度 assert
fetcher 自身有 `cache_ttl` 但**没设 24h 阈值告警**——14 天的旧数据对投资决策可能是误导。

---

## 3️⃣ 修复（C + B 组合 · 8-5 08:52 拍板）

### 3.1 C 透明（报告顶部加数据基准日 + 数据源标签 + preset 警示）
```python
# etf_hegang_report.py 修改
- 报告顶部加：📅 数据基准日 + 真实数据比例 + ⛔ preset 警示
- 1.1 行业规模表加 "数据源" 列（🟢 tx / 🟢 sina / 🟢 eastmoney / ⛔ preset / ⚪ ?）
```

### 3.2 B 治本（fetcher 数据新鲜度 assert + 持久化修复）
```python
# etf_hegang_report.py main() 加
- 持久化到 etf_percentile_today.json（修复 7-14 真空）
- 数据新鲜度 assert（fetched_at > 24h 进 stale_warnings）
- 结构对齐 daily_investment_report.read_etf_percentile_json() 预期
```

### 3.3 关键修复：data_source 字符串判断
```python
# ❌ 错误（含"预设"字样的真实源也被判成 preset）
is_fallback = '预设' in ds or '全源失败' in ds

# ✅ 正确（只有 ds 以"全源失败"开头才是 preset）
is_fallback = ds.startswith('全源失败') or '仅用预设' in ds
```
