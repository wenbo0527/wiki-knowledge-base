# Milvus向量数据库在多Agent系统中的一致性控制

---

## 核心问题

**问题现象**：多Agent系统中，Writer Agent写入数据后，Reader Agent立即查询却返回空结果。

**根本原因**：**数据库默认一致性配置**与**多Agent并发读写模式**的不匹配。

---

## 问题分析

| 场景 | 说明 |
|:---|:---|
| **Write后立即Read** | Writer写入 → Reader立即查询 → 空结果 |
| **多Agent并发写** | 多个Writer同时写入 → 冲突/覆盖 |
| **跨Agent读** | 不同Agent看到不同数据 |

---

## 解决方案

### 1. 一致性级别调整

| 级别 | 说明 | 延迟 |
|:---|:---|:---|
| **Strong** | 强一致 | 高 |
| **Session** | 会话一致 | 中 |
| **Eventually** | 最终一致 | 低 |

### 2. 读写分离策略

```
Writer Agent → 写入 → 等待同步 → Reader Agent读取
                    ↓
              确认写入成功
```

### 3. 版本控制

- **时间戳**：区分不同版本
- **乐观锁**：避免覆盖
- **历史记录**：支持回溯

---

## 工程实践

| 实践 | 说明 |
|:---|:---|
| **预检查** | 写入前检查是否存在 |
| **等待机制** | 写入后等待一定时间再读取 |
| **重试逻辑** | 读取失败后自动重试 |
