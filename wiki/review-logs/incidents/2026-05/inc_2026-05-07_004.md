## 问题描述

文博从 Portal Shell 部署的子应用中随机抽取 3 个页面进行抽查，发现两个 URL 返回空白页面：

1. **mkt-app**: `/mkt/interaction` → 页面标题正确，但 body 为空（无内容渲染）
2. **dfd-app**: `/dfd/data-flow` → 页面标题正确，但 body 为空（无内容渲染）

Playwright 自动化测试：
- HTTP 200 ✅
- 控制台无 JS 错误 ✅
- 但 `body.innerText.length = 0`，页面无实际内容

---

## 影响分析

| 影响范围 | 说明 |
|:---|:---|
| **功能影响** | mkt-app `/interaction`、dfd-app `/data-flow` 路由无对应页面组件 |
| **用户体验** | 用户访问这些路径时看到空白页面，不知道是 URL 错误还是系统故障 |
| **数据影响** | 无 |

---

## 根因分析

**直接原因**：这两个路由在源码中根本不存在，是 URL 误输入。

**mkt-app 实际路由清单**（src/router/modules/）：
- `/alert` 系列（management, rules, create, history）
- `/benefit` 系列（dashboard, template, management, package, inventory, statistics, logs）
- `/canvas`, `/call`, `/customer` 系列（tag-system, tag-table, list）
- `/marketing` 系列（alert/benefit/campaign 等）
- 无 `/interaction` 路由

**dfd-app 实际路由清单**（src/router/）：
- `/discovery`, `/data-map`, `/customer360` 等
- 无 `/data-flow` 路由

---

## 解决措施

### 排查过程

| 时间 | 措施 | 结果 |
|:---|:---|:---|
| 09:55 | Playwright 测试两个 URL | HTTP 200，但 bodyLen=0 |
| 09:56 | 检查 nginx alias 配置 | 配置存在且正确 |
| 09:57 | 确认源码路由清单 | 确认路由不存在 |
| 09:58 | 告知文博实际情况 | 确认为 URL 误输入 |

### 解决方案

无需修复系统代码，向文博说明实际可用的路由路径。
