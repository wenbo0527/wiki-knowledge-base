### **🔄 AI可靠性重心转移：从模型/能力到Harness**

过去两年，AI工程的重心经历了根本性转移：2023-2024年行业聚焦"把模型/能力调得更好"，2025年发现**调得再好的模型，搬到生产环境照样会失败**。失败根源不在模型本身，而在包裹模型的**Harness（运行时骨架）**。

**演进核心：从"零件"到"整车"**  
- **Skill Insight（旧）**：以单个能力（skill）为中心，解决"零件好不好"，采用单点评测与优化，仅观测单个Skill输入/输出，进行单能力质量分析。  
- **Agent Insight（新）**：以智能体（agent）为中心，实现端到端与系统级闭环，观测完整轨迹与全链路，评测任务成功率与协作关系，填补Harness盲区，直面生产门槛。

### **📊 Skill Insight与Agent Insight能力对比**

| 维度 | Skill Insight（以skill为中心） | Agent Insight（以Agent为中心，当前已实现） |
| :--- | :--- | :--- |
| **观测** | 单个skill的输入、输出、表现 | 端到端智能体行为：skill调用链、工具调用、规划决策全链路 |
| **分析** | 单能力质量分析 | 跨步骤轨迹分析、协作关系分析 |
| **评测** | 单能力评测 | 任务成功率、轨迹正确性、工具调用正确性等系统级评测 |
| **故障诊断** | —— | 系统级根因定位（规格/协作/验证三类） |
| **优化** | 单能力优化 | 以skill评测为信号，驱动skill的"生成—运行—诊断—优化"闭环 |

### **🚩 转向Agent Insight的必然性**

当AI可靠性瓶颈转移到Harness后，对insight能力提出全新诉求：  
1. **测评能力升级**：从"单个skill好不好"到"整个Agent轨迹好不好"，需采用**骨架感知的评测（scaffold-aware evaluation）**，将控制栈纳入评测系统，并按结构化维度归因（如NeurIPS 2025的MAST分类法：系统设计、协作错位、验证缺失）。  
2. **优化能力升级**：从"人工调单个skill"到"评测信号驱动的闭环"，让评测结果直接驱动skill及骨架的自动改写与再验证。  

**行业痛点数据**：  
- Gartner预测2027年底超40%的Agentic AI项目将被取消  
- CMU的TheAgentCompany基准中最强模型仅自主完成30.3%真实任务  
- MIT调研显示约95%的生成式AI试点无衡量回报  

### **🔍 Agent Insight当前能力与未来演进**

#### **(一) 当前已实现能力**
- **端到端观测**：覆盖skill调用链、工具调用、规划决策全链路  
- **系统级评测**：任务成功率、轨迹正确性等系统级指标  
- **结构化诊断**：按规格/协作/验证三类归因失败  
- **优化闭环**：以skill评测为信号，驱动"生成—运行—诊断—优化"闭环  

#### **(二) 未来演进方向：以评测为底座的闭环链路**
1. **观测（Observation）**  
   - 从离线观测走向**在线/生产监控**，自动沉淀生产环境真实任务数据反哺评测  

2. **评测（Evaluation）**  
   - **粒度升级**：覆盖完整轨迹与多轮会话（单轮任务成功率约58%，多轮降至35%）  
   - **横向对比**：跨模型（GPT/Claude/Gemini等）、跨平台评测，建立选型基准与回归基线  
   - **标准对齐**：数据模型对齐OpenTelemetry GenAI语义约定，实现可观测、可比较、可互通  

3. **诊断（Diagnosis）**  
   - **质量漂移告警**：监控生产环境质量变化而非仅关注延迟  
   - **根因定位与合规**：增加护栏（guardrail）与合规审计，实现"可运作、可管控"  

4. **优化（Optimization）**  
   - **Harness级自动优化**：从skill级扩展到骨架级，采用DSPy生态的GEPA反思式优化（以35倍更少试验次数超越强化学习）  
   - **自进化能力**：将Harness作为搜索空间，实现智能体自动改写自身骨架  

**生产就绪门槛**：需同时满足任务成功率达标、安全合规、轨迹正确性、成本与延迟可控。

### **💡 核心洞察**
- **本质认知切换**：从"能力评估问题"（skill好不好）到"可靠性工程问题"（Agent能否在真实世界干活）  
- **闭环价值**：观测（看清楚）→ 评测（定标准）→ 诊断（找原因）→ 优化（自动改）的持续迭代
