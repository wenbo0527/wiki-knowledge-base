### 🏆 核心背景：ChatBI 三年未解决的行业痛点

ChatBI 也就是文中提到的 **self service data analytics（自助式数据分析）**，是2023年AI应用浪潮中最早落地的场景之一，发展三年后仍未被彻底解决，同时也是企业数据需求中最普遍、最核心的场景。
Anthropic 总结了该场景长期存在的三大核心难点：
1.  **概念与实体模糊**：数据模型中存在数十万甚至数百万个字段，Agent 无法精准匹配用户问题对应的字段，典型如“活跃用户数”的定义没有统一标准，活跃行为判定、是否排除欺诈用户、回溯窗口长度都存在歧义。
2.  **数据过期**：数据源、业务定义、表结构持续迭代，数据资产和Agent的知识逐步过时，容易返回“看似正确实则隐性错误”的结果。
3.  **检索失败**：正确信息实际存在于数据模型中且标注完整，但由于搜索空间过大，Agent 无法定位到有效信息。
除此之外，落地过程中还普遍存在**脏数据**这类原生数据质量问题。
针对这些痛点，Anthropic 提出了**代理式分析技术栈（Agentic Analytics Stack）** 四层系统化工程蓝图，逐层拆解解决问题：

| 技术栈层级 | 核心解决问题 | 落地机制 |
| :--- | :--- | :--- |
| **验证层（Validation）** | 陈旧性与准确性盲区 | 离线评估、对抗性审查、主动纠错 |
| **技能层（Skills）** | 检索失败 | 知识路由、过程化逻辑、参考文档检索 |
| **真实数据源（Sources of Truth）** | 实体模糊 | 语义层、血缘关系、业务上下文映射 |
| **数据基建（Data Foundations）** | 实体模糊 | 规范化数据集、CI/CD 强制执行、元数据共置 |

### 📊 L1 数据基建：通过规范化消除歧义

这一层的核心目标是搭建“歧义漏斗”，让Agent搜索一个概念时，只能找到唯一且受治理的权威答案，彻底解决多表同指标数值不一致的乱象。落地分为四步：
1.  **建立权威数据集**：主动弃用近乎重复的冗余表，衍生汇总表必须通过机械化推导生成，禁止多套替代方案并存，最终实现“一个概念对应一个权威答案”。
2.  **程序替代人工守规矩**：摒弃依赖人工维护数据规范的思路，通过工具强制路由、CI流程卡审查、团队强制约定的方式，用可解释的确定性程序替代不可靠的人工和黑盒Agent，守住数据治理后的规范。
3.  **所有产出共置单一代码库**：将数据建模、语义层、参考文档、看板定义等所有数据相关产出全部存入同一个Monorepo（单一代码库），通过CI检查实现全局感知，一旦修改建模内容会破坏下游看板或指标定义，系统会即时报警，所有修复在同一个PR内闭环。
4.  **元数据作为一流产品对待**：将字段描述、数据粒度（Grain）、血缘关系、模型分级等元数据的维护标准提升到与数据转换同等的严谨程度，为Agent提供精准的查询“导航地图”。

### 📑 L2 真实数据源：Agent的声明式知识库

按照**信任度从高到低、知识复杂度由简练到全面**的漏斗式排序，为Agent提供分层查询依据，避免将所有数据源直接投喂给Agent：
| 数据源层级 | 信任度 | 核心功能 | 关键落地洞察 |
| :--- | :--- | :--- | :--- |
| **语义层** | 极高 | 存储编译完成的指标与维度，Agent被强制优先调用 | 禁止用LLM自动生成指标定义（会重新引入歧义），LLM仅负责生成配套文档，指标定义必须由人类确认 |
| **血缘与转换图** | 高 | 语义层无法覆盖时，Agent通过表引用排名推断上游受治理模型 | 依托前期搭建的清晰血缘链路，将“未知指标”转化为“从指定受治理模型聚合生成”的可执行任务 |
| **查询语料库** | 中 | 存储仪表板与历史SQL | 直接让Agent读取原始查询日志对准确率提升不足1%，正确做法是将语料提炼为结构化、领域化的参考文档和可复用分析模式，写入Skill模块 |
| **业务上下文** | 基础 | 接入企业知识图谱（路线图、决策日志、组织架构）解析环境指代 | 解决“Q2发布会”这类业务专属指代的理解问题，避免Agent仅停留在字面语义，无法感知用户真实意图 |

### ⚙️ L3 技能架构：Agent的过程化知识

Skill 相当于Agent的标准化“操作手册”，是大幅提升查询准确率的核心模块，Anthropic 设计了两套成对运行的Skill：
1.  **知识型Skill（Knowledge Skill）**：作为顶层流量调度员，执行“先语义层→再参考文档→最后尝试原始表”的漏斗逻辑，将百万级字段的搜索空间直接缩小到约30个特定领域的策展参考文件，从根源上避免检索失败。
2.  **经验型Skill（Unbook Skill）**：编码高级分析师的标准工作流，流程为“澄清问题→检索来源→运行查询→循环进入对抗性审查”，同时打包漏斗分析、留存曲线等通用分析模式，避免重复开发。
**核心关键数据**：未引入Skill时，Claude在评测集上的查询准确率仅为21%；引入Skill后整体准确率跃升至95%以上，部分领域可达99%。
同时Skill并非一劳永逸：若不随数据模型迭代，离线准确率会在1个月内从95%跌至65%，解决方式是将Skill文档与转换模型共置于同一代码库，修改数据模型的PR必须同步更新Skill，通过代码审查钩子强制校验，目前Anthropic 90%的数据模型PR都会同步携带Skill改动。

### ✅ L4 在线验证与性能权衡

验证模块分为离线批量评估和在线实时评估两部分，用于监控系统准确率、排查隐性错误：
1.  **离线评估**：通过固定基准事实快照日期防止评测漂移，将评估结果作为遥测数据存入数据仓库（记录Git SHA、耗时、Token数等信息），实现对系统隐性衰退的时间序列监控；同时设置发布门禁，任何领域的离线测试通过率未达到约90%的阈值前，禁止向业务方开放该领域的Agent服务。
2.  **在线评估**：部署独立的Claude子代理执行**对抗性审查**，激进地质疑最终答案中的所有潜在假设，该机制可将准确率提升6%，但也会带来延迟上升72%、Token成本上升32%的代价；配套实现来源标注页脚、数据质量自动检查、自动巡检群聊并生成修复PR的“纠正收割”Agent。
落地前需要明确受众属性：如果受众具备数据准确性辨别能力，可采用人机协同模式由人兜底；如果受众没有数据校验能力，才需要搭建这套完整的高成本系统将整体准确率推至高位。

### 📝 补充细节

Anthropic 给出了轻量化落地的极简路径：从零搭建时，仅需完成“几个权威数据集 + 几十个离线评测样本 + 一个轻量化知识Skill”，就能拿到约80%的准确率收益；文中其余所有复杂的工程建设，都是为了将系统准确率从80%推向90%+的高阶优化项。同时行业普遍认为95%的准确率仍存在落地痛点：定位剩余5%的错误需要付出极高的校验成本，因此现阶段基于LLM的数据分析场景仍需坚持人机协同的思路。
