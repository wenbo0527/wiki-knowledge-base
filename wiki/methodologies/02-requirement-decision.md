## 三、具体方法论详情

### 1. 需求优先级决策方法

**核心**：判断需求该投入/观察/放弃

**成熟框架**：
| 框架 | 维度 | 适用场景 |
|:---|:---|:---|
| **ICE** | Impact/Confidence/Ease | 快速排期 |
| **RICE** | Reach/Impact/Confidence/Effort | 强调用户覆盖 |
| **MoSCoW** | Must/Should/Could/Won't | 敏捷迭代 |
| **Kano** | 基础/期望/兴奋/无差异 | 体验优化 |

**实践要点**：
- 选择合适的优先级模型
- 量化每个维度的评分
- 定期复盘优先级决策

**✅ 实践案例：6域23应用优先级排序**
- 背景：苏银凯基6个产品域，23个应用，需要排优先级
- 方法：MoSCoW + ICE结合
- Must：数据中台（基础，其他应用依赖）
- Should：营销套件（业务增长核心）
- Could：数字风险（风控支撑）
- Won't：暂缓（资源有限）
- 关键经验：优先级不是一次排完，而是持续动态调整

### 2. 能力边界明确方法

**核心**：明确AI能做什么/不能做什么

**成熟框架**：
| 能力等级 | 说明 | 产品设计原则 |
|:---|:---|:---|
| **高置信** | AI能稳定完成 | 作为核心用户路径 |
| **中置信** | AI能完成但需校验 | 设计置信度提示 |
| **低置信** | AI部分完成需人工介入 | 设计人工兜底 |
| **拒绝区** | AI不能做 | 明确拒绝或降级 |

**实践要点**：
- 在设计前明确能力边界
- 设计置信度提示机制
- 制定优雅降级方案

**✅ 实践案例：ChatBI能力边界**
- 高置信场景：标准SQL生成、常见指标查询
- 中置信场景：复杂多表关联、模糊语义理解
- 低置信场景：跨库查询、实时数据
- 拒绝场景：涉及隐私数据、复杂计算
- 产品设计：不同置信度显示不同UI（绿色/黄色/红色提示）

### 3. 需求澄清方法

**核心**：把模糊需求变清晰

**成熟框架**：
- 用户故事地图
- 5W1H分析法
- SMART目标设定

**实践要点**：
- 挖掘真实需求而非表面表述
- 明确业务场景和用户角色
- 定义清晰的成功标准

**✅ 实践案例：跨渠道指标体系需求澄清**
- 原始需求："统一各渠道的数据"
- 背后问题：
  - 业务方A：想知道各渠道的获客成本
  - 业务方B：想知道各渠道的转化率
  - 技术方：各渠道数据口径不一致
- 澄清后：
  - 明确口径定义（什么是"渠道"、什么是"转化"）
  - 统一数据标准
  - 建立指标字典
- 关键经验：需求澄清要挖到"根问题"

### 4. 有效PRD编写方法

**核心**：AI时代的PRD怎么写

**成熟框架**：
- 传统PRD + AI要素
- 用户故事 + AI边界
- 验收标准 + 置信度要求

**AI PRD特有要素**：
```
1. AI能力边界定义
2. 数据需求说明
3. 评估指标体系
4. 兜底机制说明
5. 风险与应对
```

**✅ 实践案例：营销套件PRD**
- 传统部分：产品概述、用户角色、功能列表
- AI特有部分：
  - 画布配置的AI推荐策略（置信度）
  - 触达效果的AI归因分析
  - 兜底机制（AI推荐→人工审核）
- 评估指标：
  - 策略采纳率 > 60%
  - 配置效率提升 80%
  - ROI > 1:3

### 5. 需求该不该做方法

**核心**：五维判断表

**五维判断**：
| 维度 | 判断问题 | 不适合AI的信号 |
|:---|:---|:---|
| **模糊性** | 问题边界是否模糊？ | 规则可写成if-else |
| **规模性** | 处理频次是否足够大？ | 每天不足100次 |
| **容错性** | 输出是否允许误差？ | 要求100%准确 |
| **替代性** | 是否有成熟非AI方案？ | 业界已有低成本工具 |
| **差异化** | AI是否有明显优势？ | 成本高但效果仅微弱提升 |

**实践要点**：
- 将五维判断表作为立项前筛查清单
- 与业务Owner共同完成
- 建立合理预期，避免后期需求反复

**✅ 实践案例：ChatBI立项判断**
| 维度 | 评估 | 结论 |
|:---|:---|:---|
| 模糊性 | 业务人员查数需求多样，难以穷举规则 | ✓ AI适合 |
| 规模性 | 全公司每天数百次查数需求 | ✓ 规模够大 |
| 容错性 | 允许一定误差，支持二次确认 | ✓ AI可用 |
| 替代性 | 传统方式需要提工单等待 | ✓ 无替代方案 |
| 差异化 | AI理解自然语言，显著提升效率 | ✓ 优势明显 |
| **决策** | ✓ 立项开发 | |
