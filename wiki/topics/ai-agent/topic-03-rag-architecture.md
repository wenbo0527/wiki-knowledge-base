### 1.2 每层产品职责

| 层级 | 核心职责 | 产品决策点 | 技术选型 |
|:---|:---|:---|:---|

| **切片分块** | 块大小、重叠度、语义完整 | 块多大？如何保证语义完整？ | 固定/语义/层级切片 |

| **召回** | 多路召回、TopK | 用几路召回？TopK 设多少？ | 关键词+向量混合 |
| **Rerank** | 重排序、评分融合 | 用什么重排模型？ | BGE-reranker |
| **生成** | Prompt 模板、引用标注 | 如何让模型引用召回内容？ | RAG Prompt |

## 二、切片与 Embedding

### 2.1 Chunk 分块策略

| 策略 | 原理 | 优点 | 缺点 | 选型建议 |
|:---|:---|:---|:---|:---|
| **固定切片** | 按字数（512/1024字符）硬切 | 简单、可控、稳定 | 破坏语义完整，可能切断句子 | 简单文档、快速上手 |
| **语义切片** | 按句子/段落语义边界切 | 语义完整 | 计算成本高，规则复杂 | 复杂文档、高质量场景 |
| **层级切片** | 按文档层级结构（标题1/2/3）切 | 保留文档结构 | 需要解析文档结构 | 知识库、目录结构重要 |
| **渐进式切片** | 先语义切，再固定切 | 兼顾效率和完整 | 实现复杂 | 通用场景（推荐） |

#### 块大小经验值

| 语言 | 块大小 | 说明 |
|:---|:---|:---|
| **中文** | 512-1024 字符/块 | 中文 Token 化后约 256-512 Token |
| **英文** | 256-512 Token/块 | 约 200-400 单词 |
| **代码** | 64-128 Token/块 | 保持函数级别完整 |

#### 重叠度影响

| 重叠度 | 效果 | 建议 |
|:---|:---|:---|
| **0%** | 无重叠，可能丢失跨块信息 | 简单场景 |
| **10-20%** | 基本覆盖 | 通用场景（推荐） |
| **30%+** | 冗余增加，成本上升 | 高质量要求 |

### 2.2 Embedding 模型选型

#### 主流 Embedding 模型

| 模型 | 维度 | 中文支持 | 精度 | 速度 | 适用场景 |
|:---|:---|:---|:---|:---|:---|
| **BGE-large-zh** | 1024 | ✅ 优秀 | 高 | 中 | 中文高质量场景 |
| **text-embedding-ada-002** | 1536 | ✅ 良好 | 高 | 快 | OpenAI 用户 |
| **M3E** | 768 | ✅ 优秀 | 中 | 快 | 中文场景 |
| **BGE-base** | 768 | ✅ 优秀 | 中 | 快 | 通用场景 |
| **SGPT** | 768 | ⚠️ 一般 | 中 | 快 | 多语言 |

#### 维度取舍

| 维度 | 精度 | 存储 | 检索速度 | 适用场景 |
|:---|:---|:---|:---|:---|
| **256-512** | 较低 | 小 | 快 | 简单语义、精确匹配 |
| **768-1024** | 平衡 | 中 | 平衡 | 通用场景（推荐） |
| **1536+** | 高 | 大 | 慢 | 复杂语义、精细差异 |

## 三、召回体系

### 3.1 三种召回类型

| 类型 | 原理 | 适用场景 | 优缺点 |
|:---|:---|:---|:---|
| **关键词召回** | BM25/TF-IDF，词频统计 | 专业术语、缩写、精确字段 | 精确但无语义理解 |
| **向量召回** | Embedding + 余弦相似度 | 语义相似、同义词、多语言 | 语义理解但可能「幻觉」 |
| **混合召回** | 两路合并 + RRF + 重排 | 通用场景 | 兼顾精确和语义 |

### 3.2 关键词召回原理

```python
# BM25 算法核心
score = Σ IDF(t) × (tf(t,d) × (k+1)) / (tf(t,d) + k × (1-b + b × |d|/avgdl))

# TF-IDF 变种
score = tf(t,d) × idf(t)
```

**适用场景**：
- 金融代码、法律条文（精确术语）
- 产品编号、日期、数字（精确匹配）
- 用户名、ID 等结构化字段

### 3.3 向量召回原理

```python
# 1. Query 向量化
query_embedding = embedding_model.encode(user_query)

# 2. 余弦相似度计算
similarity = cos(query_embedding, doc_embedding)

# 3. TopK 召回
top_k_docs = argsort(-similarity)[:K]
```

**适用场景**：
- 语义相似但表述不同（"怎么退款" vs "退货流程"）
- 同义词（"电脑" vs "计算机"）
- 多语言（中文问英文答）
- 开放式问答

### 3.4 混合召回与 RRF


#### RRF 公式

```python
# Reciprocal Rank Fusion
def rrf_score(ranks, k=60):
    """k通常为60"""
    return sum(1 / (k + rank) for rank in ranks)

# 多路合并示例
doc_scores = {}
for doc_id in bm25_top50 + vector_top50:
    rank_bm25 = bm25_ranking.get(doc_id, 0)
    rank_vector = vector_ranking.get(doc_id, 0)
    doc_scores[doc_id] = rrf_score([rank_bm25, rank_vector])
```

### 3.5 TopK 设置

| TopK | 召回量 | 准确率 | 性能 | 适用场景 |
|:---|:---|:---|:---|:---|
| **K=1~3** | 极少 | 单一最优 | 最快 | 简单查询、只需最优答案 |
| **K=5~10** | 适中 | 平衡 | 平衡 | 通用场景（推荐） |
| **K=20~50** | 多 | 召回全 | 慢 | 复杂查询、需要多路信息 |
| **K=100+** | 极多 | 几乎必召回 | 最慢 | 评测、召回率优先 |

## 四、重排序 Rerank

### 4.1 为什么需要 Rerank

```
向量相似度 ≠ 语义相关性
```

| 问题 | 原因 |
|:---|:---|
| **维度灾难** | 高维空间距离度量失效 |
| **语义漂移** | 相似度高但实际不相关 |
| **业务权重缺失** | 某些文档天然优先级更高（时效性、权威性） |

**Rerank 核心价值**：
- 引入交叉编码，更精准的相关性判断
- 融合业务规则（时效性↑、权威性↑）
- 支持人工标注反馈调优

### 4.2 Rerank 模型

| 模型 | 说明 | 精度 | 速度 | 适用场景 |
|:---|:---|:---|:---|:---|
| **BGE-reranker-base** | 轻量级重排 | 中 | 快 | 通用场景 |
| **BGE-reranker-large** | 高精度重排 | 高 | 慢 | 高质量要求 |
| **Cohere-rerank** | 云服务 | 高 | 中 | 快速接入 |

### 4.3 架构位置

```
┌─────────────────────────────────────────────────────────────────────┐
│                         召回-重排-生成层级                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   召回层（Recall）     TopK=100-500  ←  粗筛，广召回               │
│         │                                                          │
│         ▼                                                          │
│   重排层（Rerank）    TopN=10-20   ←  精排，语义重排              │
│         │                                                          │
│         ▼                                                          │
│   生成层（Generate）  最终使用=3-5  ←  最终输入大模型               │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.4 可配置化设计

```yaml
rerank:
  enabled: true
  model: "bge-reranker-base"
  top_n: 10
  score_threshold: 0.5
  
  # 业务权重（可配置）
  business_weights:
    recency: 0.2      # 时效性权重
    authority: 0.3      # 权威性权重
    relevance: 0.5      # 相关性权重（rerank模型）
  
  # 过滤规则
  filters:
    min_score: 0.3
    max_docs: 20
```

### 5.3 RAG 效果评估指标

| 指标 | 定义 | 计算方式 | 目标值 | 说明 |
|:---|:---|:---|:---|:---|
| **召回率（Recall）** | 相关文档被召回的比例 | TP/(TP+FN) | >90% | 越高越好 |
| **精准率（Precision）** | 召回内容中相关的比例 | TP/(TP+FP) | >70% | 越高越好 |
| **MRR@K** | 第一个相关文档的排名倒数 | 1/rank | >0.8 | 排名越前越好 |
| **NDCG@K** | 归一化折损累计增益 | DCG/IDCG | >0.8 | 综合排名质量 |
| **问答正确率** | 用户满意度/准确率 | 人工评估 | >80% | 最终业务指标 |
| **拒绝率** | 无法回答需转人工比例 | 拒答数/总数 | <10% | 越低越好 |

#### 评估方法

```python
# 离线评估
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy

results = evaluate(dataset, metrics=[faithfulness, answer_relevancy])

# 在线监控
metrics = {
    "recall@k": recall_at_k(test_set, k=10),
    "precision@k": precision_at_k(test_set, k=10),
    "rejection_rate": num_rejections / total_queries
}
```
