# Wiki健康走查方案 v2.0

> 保障Wiki结构满足MECE原则且合理归类
>
> **版本**: v2.0
> **更新**: 2026-05-13
> **基于**: 四层架构（L1流程/L2方法/L3模板/L4知识）

---

## 一、方案概述

### 1.1 目标

确保Wiki知识库满足：
- **四层架构**：L1流程/L2方法/L3模板/L4知识完整
- **MECE原则**：相互独立、完全穷尽
- **能力驱动**：6大能力框架有清晰的L1-L4分层
- **知识复利**：知识闭环持续积累

### 1.2 走查频率

| 频率 | 时间 | 内容 |
|:---|:---|:---|
| **每日** | 08:00 | 链接健康检查（自动化） |
| **每周** | 周一09:00 | 结构完整性 + L1-L4分层检查 |
| **每月** | 每月1日 | 四层质量评估 + MECE审查 |
| **引入后** | 实时 | 新内容归类验证 |

### 1.3 走查角色

| 角色 | 职责 |
|:---|:---|
| **尼克·弗瑞** | 执行日常走查、记录问题、框架维护 |
| **派蒙** | 协调复杂归类决策、审核方案 |
| **钟离** | 技术专题归类把关 |
| **托尼·斯塔克** | 产品专题归类把关 |

## 二、四层架构检查

### 2.1 L1-L4检查清单

```
□ 6大能力框架是否都有目录结构？
□ 每个能力是否有 L1-流程/L2-方法/L3-模板/L4-知识 四层？
□ 每层的文件是否在正确的子目录？
□ 各层内容是否与层级定义匹配？
```

### 2.2 各层检查标准

| 层级 | 检查要点 | 最低标准 |
|:---|:---|:---|
| **L1 流程** | 四步是否MECE独立完整 | 4步流程清晰 |
| **L2 方法** | 每步是否有方法论 | 有1+方法论 |
| **L3 模板** | 是否有模板工具 | 有模板框架 |
| **L4 知识** | 是否有知识填充 | 有1+案例/实践 |

### 2.3 能力框架目录检查

```
每个能力框架目录结构：
├── README.md              ← 能力总览
├── L1-流程步骤/
│   └── README.md         ← 四步MECE
├── L2-方法论/
│   ├── 方法1.md
│   └── 方法2.md
├── L3-模板工具/
│   ├── 模板1.md
│   └── 模板2.md
└── L4-知识填充/
    ├── 文博案例/
    ├── RSS最佳实践/
    └── 业务知识/
```

## 三、四层质量评估

### 3.1 评估维度

| 层级 | 核心问题 | 评估维度 |
|:---|:---|:---|
| **L1 流程** | 做什么？ | MECE性、完整性、独立性 |
| **L2 方法** | 怎么做？ | 完整性、细化度、适用边界 |
| **L3 模板** | 用什么？ | 完整性、可执行性、示例 |
| **L4 知识** | 填充什么？ | 文博案例、最佳实践、法规/业务/技术 |

### 3.2 评分标准

| 得分 | 说明 |
|:---:|:---|
| 5分 | 完全满足，可作为标杆 |
| 4分 | 基本满足，有少量不足 |
| 3分 | 达到基本要求 |
| 2分 | 有明显缺失 |
| 1分 | 严重缺失 |

### 3.3 综合评分

```
综合得分 = L1×20% + L2×25% + L3×20% + L4×35%
```

| 等级 | 分数 | 说明 |
|:---:|:---:|:---|
| 🏆 **卓越** | 90-100% | 可作为标杆 |
| 🟢 **优秀** | 75-89% | 高质量 |
| 🟡 **良好** | 60-74% | 基本可用 |
| 🟠 **一般** | 40-59% | 需大幅补充 |
| 🔴 **差** | 0-39% | 需要重建 |

## 四、MECE原则检查

### 4.1 能力框架检查

```
□ 6大能力是否有明显重叠？
□ 能力之间的边界是否清晰？
□ 是否有能力缺少L1-L4某一层？
□ L4知识是否按MECE分类（案例/实践/法规/业务/技术）？
```

### 4.2 流程步骤检查

```
□ 每个能力的4步流程是否独立完整？
□ 步骤之间是否有重叠？
□ 是否有步骤缺失？
```

## 五、链接健康检查

### 5.1 链接类型检查

| 链接类型 | 检查频率 | 检查方法 |
|:---|:---|:---|
| **内部Wiki链接** | 每日 | wiki_lint.py |
| **能力间链接** | 每周 | 验证关联 |
| **外部URL** | 每周 | 抽样验证 |
| **L层级链接** | 每周 | 上下层链接 |

### 5.2 常见链接问题

```
□ 死链：目标文件不存在
□ 能力孤岛：能力无跨框架关联
□ L层断裂：L1/L2/L3/L4之间无链接
```

## 六、问题处理流程

### 6.1 问题分级

| 级别 | 标准 | 处理时限 |
|:---:|:---|:---:|
| **P0** | 能力框架缺失L1-L4任一层 | 立即修复 |
| **P1** | 死链导致无法访问 | 24小时内 |
| **P2** | MECE重叠或缺失 | 本周内 |
| **P3** | 优化建议 | 排期处理 |

### 6.2 归类争议处理

```
争议场景：内容应归入能力A还是能力B
    │
    ▼
尼克·弗瑞提出归类建议 + 理由
    │
    ▼
判断是否涉及跨能力
    │
    ▼
如涉及 → 派蒙协调决策
    │
    ▼
记录归类原则到本文档
```
