## 一、基础术语边界

### 1.1 Agent / Workflow / RAG 三者本质区别

| 概念 | 本质 | 核心能力 | 适用场景 | 边界特征 |
|:---|:---|:---|:---|:---|
| **Agent** | 有记忆、会做决策的智能体 | 自主规划、工具调用、反思迭代 | 复杂任务、多步骤、需要自适应 | 闭环、有记忆 |
| **Workflow** | 预设流程的执行器 | 流程编排、节点执行、状态管理 | 固定流程、规则明确、可预测 | 开环、无记忆 |
| **RAG** | 检索增强的问答系统 | 知识召回、上下文增强 | 知识问答、需要最新信息 | 问答闭环 |

**本质区别**：
- **Agent** = 自主决策 + 工具调用 + 反思迭代（有闭环）
- **Workflow** = 预设节点 + 流程编排 + 条件路由（无闭环）
- **RAG** = 检索 + 召回 + 生成（专为问答设计）

**产品设计决策树**：
```
任务是否需要多步骤决策？
├── 否 → 是问答类？
│   ├── 是 → RAG
│   └── 否 → 简单脚本
└── 是 → 是否需要自主决策？
    ├── 是 → Agent
    └── 否 → Workflow
```

### 1.2 Function Calling / Skill / Prompt 三层层级关系

```
层级从高到低：

┌─────────────────────────────────────────┐
│  Function Calling（工具调用层）           │  ← 最底层，原子化能力
│  ├── 定义工具名称、入参、出参           │
│  ├── 约束：类型校验、范围限制           │
│  └── 示例：Bash(file="*.md"), Read()   │
└────────────────┬────────────────────────┘
                 │ 被 Skill 调用
                 ▼
┌─────────────────────────────────────────┐
│  Skill（技能层）                        │  ← 中间层，能力封装
│  ├── 触发条件（何时使用）               │
│  ├── 编排多个 Tools 完成业务能力        │
│  ├── SKILL.md 定义                     │
│  └── 示例：requirement-understanding     │
└────────────────┬────────────────────────┘
                 │ 被 Prompt 触发
                 ▼
┌─────────────────────────────────────────┐
│  Prompt（提示层）                       │  ← 最上层，人机交互
│  ├── 系统提示（人格、规则）             │
│  ├── Few-shot 示例                      │
│  └── 用户输入 → 理解 → 路由            │
└─────────────────────────────────────────┘
```

| 层级 | 职责 | 产品定义点 |
|:---|:---|:---|
| **Prompt** | 人机交互，理解用户意图 | 系统提示、示例、格式要求 |
| **Skill** | 业务能力封装，触发条件 | SKILL.md、描述、工具列表 |
| **Function Calling** | 原子化工具，执行确定性操作 | 工具定义、入参出参约束 |

### 1.3 大模型 / 小模型 / 嵌入式模型 分工与选型

#### 模型谱系

| 类型 | 参数量级 | 代表模型 | 能力 | 成本 | 延迟 |
|:---|:---|:---|:---|:---|:---|
| **超大模型** | 1000B+ | GPT-4、Claude Opus | 复杂推理、多模态、代码生成 | 极高 | 高 |
| **大模型** | 100B-1000B | GPT-3.5、Claude Sonnet | 复杂推理、多轮对话 | 高 | 中 |
| **中模型** | 10B-100B | Llama-70B、Qwen-72B | 中等推理、特定任务 | 中 | 中 |
| **小模型** | 1B-10B | Llama-7B、Qwen-14B | 轻量推理、分类、路由 | 低 | 低 |
| **Embedding** | - | BGE、text-embedding-ada | 向量化、语义编码 | 极低 | 低 |

#### 分工原则

```
┌─────────────────────────────────────────────────────────────┐
│                    分层降本架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  用户输入                                                    │
│      │                                                      │
│      ▼                                                      │
│  ┌──────────────────┐                                      │
│  │ 小模型/Embedding │ → 路由/过滤/意图分类（省钱）        │
│  └────────┬─────────┘                                      │
│           │ 命中                                              │
│           ▼                                                  │
│  ┌──────────────────┐                                      │
│  │ 知识召回层        │ → 向量检索/关键词匹配（精准）        │
│  └────────┬─────────┘                                      │
│           │ 召回文档                                          │
│           ▼                                                  │
│  ┌──────────────────┐                                      │
│  │ 大模型生成层      │ → 总结/生成/回答（质量）            │
│  └──────────────────┘                                      │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

#### 选型决策矩阵

| 场景 | 小模型 | 大模型 | 说明 |
|:---|:---:|:---:|:---|
| 意图分类 | ✅ | ❌ | 简单分类，小模型足够 |
| 知识召回 | ✅ | ❌ | Embedding 即可 |
| 闲聊 | ❌ | ✅ | 需要上下文理解 |
| 复杂推理 | ❌ | ✅ | 需要强推理能力 |
| 代码生成 | ❌ | ✅ | 需要代码理解 |
| 实时翻译 | ✅ | ❌ | 简单任务 |

### 1.4 上下文窗口、Token、会话 Session 标准定义

#### 核心概念

| 概念 | 定义 | 计量单位 | 示例 |
|:---|:---|:---|:---|
| **Token** | 文本最小单元 | 字符数/词数 | 中文1-2字=1Token，英文0.75词=1Token |
| **上下文窗口** | 模型单次处理最大Token数 | Token | Claude 200K，GPT-4 128K |
| **轮次（Turn）** | 一次用户输入+模型输出 | 对话轮数 | 1 Turn = 1问1答 |
| **会话（Session）** | 多轮对话组成的完整上下文 | 多轮 | 一个分析任务的多轮对话 |

#### Token 计算

```python
# 估算公式
中文：1 Token ≈ 1.5-2 个字符
英文：1 Token ≈ 0.75 个单词

# 成本计算
总成本 = (输入Token数 × 输入单价) + (输出Token数 × 输出单价)

# 示例（GPT-4 Turbo）
输入：$0.01/1K Token
输出：$0.03/1K Token
1000 Token对话 ≈ $0.02-0.04
```

#### 上下文窗口透支治理

| 策略 | 说明 | 适用场景 |
|:---|:---|:---|
| **硬截断** | 超出窗口直接截断前面的内容 | 不重要场景 |
| **软压缩** | 先压缩前面的内容再处理 | 重要上下文场景 |
| **拒绝回答** | 超出限制拒绝回答，提示精简问题 | 高风险场景 |
| **摘要续写** | 压缩前文，保留核心信息续写 | 长期任务 |

### 1.5 模型上下文漂移 vs 窗口透支

| 现象 | 本质 | 原因 | 表现 | 治理 |
|:---|:---|:---|:---|:---|
| **上下文漂移** | 核心信息被稀释 | 上下文过长，有效信息密度降低 | 模型忘记关键细节、回答偏离 | 定期压缩/摘要 |
| **窗口透支** | 超出窗口限制 | 上下文 > 最大 Token 数 | 报错/截断/回答不完整 | 截断/压缩/拒绝 |

## 二、部署与交付形态

### 2.1 本地 / 私有 / 私有化 / 离线 严格区分

| 部署方式 | 定义 | 网络要求 | 数据主权 | 运维复杂度 | 适用场景 |
|:---|:---|:---|:---|:---|:---|
| **本地部署** | 在本地机器运行 | 有/无网络均可 | 完全私有 | 低 | 开发测试、个人使用 |
| **私有部署** | 在客户私有服务器 | 必须内网 | 企业完全掌控 | 中 | 企业内网、数据敏感 |
| **私有化部署** | 完全隔离的定制交付 | 物理隔离 | 企业完全掌控 | 高 | 金融、政务、军工 |
| **离线部署** | 完全无网络环境 | 物理隔离 | 最高主权 | 高 | 机密场景、特种行业 |

**关键区别**：
```
本地部署：单机运行，可能依赖网络
私有部署：局域网内运行，数据不出域
私有化部署：一次性交付，完全定制，物理隔离
离线部署：无任何网络，零外部依赖
```

### 2.2 公有云 SaaS / 专属云租户 / 本地机房

| 部署形态 | 合规适用 | 数据位置 | 运维责任方 | 弹性能力 |
|:---|:---|:---|:---|:---|
| **公有云 SaaS** | 通用合规、数据可出境 | 云服务商机房 | 云服务商 | 弹性伸缩 |
| **专属云租户** | 金融等保本地、强监管 | 企业自有或专属云 | 企业+云商共担 | 部分弹性 |
| **本地机房** | 数据不出域、强监管 | 企业机房 | 企业全担 | 无弹性 |

**合规决策**：
```
数据敏感度极高（金融、政务、医疗）
├── 是 → 本地机房 or 专属云租户
└── 否 → 公有云 SaaS

监管要求（如等保三级）
├── 是 → 私有化部署
└── 否 → 根据成本选择
```

### 2.3 模型部署模式

| 部署模式 | 说明 | 性能 | 成本 | 适用 | 隔离性 |
|:---|:---|:---:|:---:|:---|:---|
| **独享实例** | 独占 GPU/CPU 资源 | 稳定高 | 高 | 生产级、高并发 | 完全隔离 |
| **共享调度** | 多任务共享资源池 | 波动 | 低 | 开发测试、低频 | 共享 |
| **本地私有化镜像** | 完整模型镜像本地部署 | 高 | 高（硬件） | 金融、政务 | 完全隔离 |
| **Serverless** | 按调用计费，冷启动 | 一般 | 按量计费 | 波动负载 | 云商隔离 |

**选型决策**：
```
并发需求
├── >100 QPS → 独享实例
├── 10-100 QPS → 共享调度 + 缓存
└── <10 QPS → Serverless

延迟要求
├── <500ms → 独享实例
└── 可接受 >1s → Serverless

成本优先
├── 小规模 → Serverless
└── 大规模 → 独享实例
```
