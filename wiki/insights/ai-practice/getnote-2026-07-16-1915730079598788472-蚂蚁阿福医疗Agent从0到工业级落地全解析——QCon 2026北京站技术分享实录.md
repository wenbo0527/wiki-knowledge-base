### 🏥 医疗Agent的核心痛点与研发范式变革

医疗领域是智能体落地的高门槛场景，容错空间几乎为零，一旦出现致命错误可能引发严重的人身与社会风险。蚂蚁集团医疗健康资深专家郭春晓在QCon 2026北京站的分享中，系统拆解了蚂蚁阿福医疗Agent的全链路工程化实践。

#### 医疗场景的独有挑战

医疗Agent和通用Agent存在本质差异，核心矛盾集中在三点：
1.  **确定性要求与大模型非确定性的冲突**：医疗遵循严格的循证逻辑，所有诊断必须符合指南、教科书的推演链条，要求可解释、可复现、合规的推理过程，而大模型天然的非确定性输出无法直接适配。
2.  **超长周期记忆需求**：用户的慢性病、既往病史可能长达数年甚至数十年，新的诊疗决策必须结合全周期健康数据，大模型原生的长期记忆能力完全无法覆盖该场景。
3.  **强风险合规约束**：医疗数据属于最高等级敏感信息，国内法规明确医疗数据泄露超过50条即可触发刑事责任，同时还需覆盖心理危机干预等高风险场景，蚂蚁阿福已通过高危联动机制实际救助过有自杀倾向的用户。

#### 三代研发范式演进对比

不同技术阶段的研发逻辑存在显著差异，具体对比如下：
| 研发阶段 | 核心驱动模式 | 迭代周期 | 核心关注指标 | 适配场景 |
| :--- | :--- | :--- | :--- | :--- |
| 传统软件研发 | TDD（测试驱动开发），人工QA验证 | 2~4周 | 功能正确性、流程合规性 | 需求完全确定的业务系统 |
| 搜索推荐时代 | 数据+AB实验驱动 | 1~2周 | CTR、CVR、转化率等线上效果指标 | 效果可量化的推荐类场景 |
| Agent时代 | Benchmark+Badcase双驱动 | 按天迭代 | 模型能力、用户留存、体验流畅度 | 大模型主导的智能体场景 |

Agent时代的核心特征是**代码数据化**：传统功能靠硬编码实现，而智能体场景下的能力迭代通过修改Prompt、新增检索策略、补充Badcase数据集完成，最终通过数据训练优化模型，当前行业头部团队已实现Harness模式下10倍级的研发提效。

### 🛠️ 医疗Agent整体技术架构

蚂蚁阿福搭建了五层全链路技术体系，同时配套左右两大支撑体系保障迭代效率与风险可控：
1.  **数据层**：覆盖医疗权威库（指南、专业书籍、权威网页）、标准库（病症药检、医生医院数据）、post-train后训练数据集（复杂搜索问题、多轮问诊数据）。
2.  **AI infra&模型层**：包含LLM、LVM、Agent model基础模型能力，配套Agent RL体系的运行环境、工具环境和奖励服务。
3.  **Agent层**：四大核心模块分别是Agent-RAG（检索增强）、Agent-Mem（长短时记忆）、Agent-迭代范式（评测闭环）、智能体协作（多智能体会诊、研究）。
4.  **应用层**：覆盖智能体编排、用户增长、机构接入、运营后台等业务能力。
5.  **客户端层**：支持LUI交互、H5/原生混合端、GRPC/RTC实时交互等多端形态。
6.  两侧支撑：左侧为迭代效率体系，保障天级迭代速度；右侧为全链路风险防控体系，实现零重大事故的安全运行。

### 📊 EBBD评测驱动研发体系

蚂蚁团队首创了**EBBD（Evaluation And Badcase Driven Development）**评测驱动研发范式，彻底解决医疗场景下无统一验证标准的难题。

#### EBBD四大核心模块

| 模块缩写 | 模块名称 | 核心能力 |
| :--- | :--- | :--- |
| E | Evaluation Benchmark评测体系 | 基于Rubric多要点评测规则，覆盖多正确答案场景，采用自动化评测+人工终审模式，已实现70%场景覆盖，评测耗时从1~2天大幅缩短至小时级 |
| B | Badcase体验优化 | 打通种子用户内测、灰度反馈、用户社群等多渠道，实现Badcase动态分拣、全量核对巡检，已将大模型“复读机”问题发生率从十万分之五降至万分之二 |
| D | Driven流水线 | 构建「评测→定位→修复→验证」的全闭环流程，实现快速迭代，支持天级别的能力交付 |
| D | Development生产化 | 推动评测能力线上化，通过A/B实验与灰度验证，配套全链路监控告警实现持续优化 |

#### Benchmark+Badcase双循环机制

为避免公开Benchmark出现过拟合失效（行业普遍规律是榜单发布2年后就会因数据泄露失去参考价值），蚂蚁搭建了持续迭代的双循环流程：`Benchmark评测→Badcase发现→根因分析→方案优化→效果验证`，通过不断将新发现的Badcase补充进基准数据集，实现模型能力的持续迭代。当前整套流程的评测耗时已从最初的1~2天压缩至小时级。

#### 可靠评测的三大核心原则
1.  **数据集质量优先**：评测样本必须无歧义、具备区分度，能够精准区分不同模型的能力差距，避免出现所有参评模型得分趋同的无效评测集。
2.  **样本量逐步扩容**：从10条、100条样本起步逐步积累，接受小样本阶段的结果波动，优先保障底线能力不退化。
3.  **人机对齐校准**：先完成人类标注的一致性校验，再通过1~2个月的周期将大模型打分偏好与人类专业判断对齐，避免评测方向出现系统性偏差。

### 📝 医疗场景上下文工程实践

医疗对话的单轮信息量远超通用场景，大量图文混合的检查报告、几十页的指南文档极易引发“lost in the middle”问题，国内主流大模型标称128K/256K上下文，实际有效召回率在64K之后就会显著下降，最优可用区间仅为32K~64K。
蚂蚁团队通过三大策略解决该难题：
1.  **结构化+非结构化混合存储**：将20%的核心医疗信息做结构化处理，剩余非结构化内容保留原始形态，兼顾信息准确性与可扩展性。
2.  **智能上下文压缩**：在第1轮对话、第12轮对话，以及上下文长度达到20K时自动触发压缩，全程保留用户原始Query，优先丢弃模型冗余输出。
3.  **渐进式加载策略**：参考阅读论文的逻辑，先向模型推送文档目录，由模型自主判断是否需要加载对应章节的完整内容，大幅降低无效上下文占用。
4.  **主子Agent轻量化协作**：非必要不启用多智能体架构，仅在处理超长文档时将任务委派给子Agent，返回内容索引而非完整原文，避免主上下文被冗余信息污染。

### 🔍 从RAG到Agentic RAG的医疗检索升级

传统单次检索的RAG架构无法适配医疗多跳复杂问题（例如“肝功能不好+发烧，能吃什么药、怎么吃以及怎么报销”），蚂蚁团队将循证医学思想融入检索框架，打造了医疗专属的Agentic RAG体系：
1.  **Stage1 Query理解**：完成意图识别、实体抽取、多跳问题拆解、检索策略路由，将复杂问题拆解为可执行的检索子任务。
2.  **Stage2 循证检索**：定向检索权威指南文献、药品说明书、区域医保政策，保障所有检索来源的专业性与时效性。
3.  **Stage3 证据融合**：对多源检索结果做排序去重、证据等级评估，通过业务规则解决信息冲突，最终生成合规的诊疗回答。

该方案落地后，医疗AQ问答准确率达到业界第一，对应的BRIGHT检索Benchmark取得SOTA成绩，整套框架已完全开源。蚂蚁团队通过知识图谱合成高难度多跳问题，结合强模型（Claude/Gemini/GPT）完成轨迹蒸馏，仅投入6名研发人员耗时3个月就实现了榜单登顶，后续行业头部团队也沿用了该技术路径。

### 🧠 医疗专属记忆架构设计

医疗场景的记忆落地难度远高于通用场景，需要解决多身份识别、信息冲突、隐私合规等一系列难题，蚂蚁阿福搭建了四层记忆架构：
1.  **Layer1 输入与身份识别层**：通过意图+角色+权限引擎，区分当前问诊主体是患者本人还是家属/代理人，为不同身份分配独立记忆空间，实现隐私隔离。
2.  **Layer2 记忆处理层**：通过LLM提取结构化医疗事实，自动检测新旧信息冲突，完成置信度打分，高置信度事实直接入库，低置信度事实触发人工确认流程。
3.  **Layer3 记忆存储层**：分为会话记忆（当前对话临时状态）、病例级记忆（诊断结论、诊疗方案、检查结果）、长期记忆（慢性病史、过敏史、家族病史）三大存储池，配套独立的遗忘策略引擎，通过TTL衰减、合规删除、置信度淘汰机制自动清理过期无效记忆。
4.  **Layer4 检索与应用层**：通过语义检索、身份权限过滤、时效性排序，动态组装上下文生成个性化Agent响应。

蚂蚁团队在医疗记忆上采用“百分百确认才使用”的保守策略，避免像通用大模型那样激进关联用户历史信息，同时通过“遗忘优先”的设计，自动清除过期的临时病症数据，保障记忆的准确性。

### ⚡ 训推性能优化实践

为平衡推理成本与用户体验，蚂蚁团队针对TTFT（首Token耗时）、TPOT（单Token生成耗时）两大核心指标做了全链路优化：
1.  **预计算优化**：充分利用KV Cache缓存历史Prompt，避免重复计算。
2.  **节点分离部署**：将计算密集型的Prefill节点与IO密集型的Decode节点物理分离，Prefill节点搭载高算力卡，Decode节点搭载高HBM显存卡，实现资源错配优化。
3.  **精度压缩**：将Prefill计算从BF16压缩至FP8/INT8，大幅降低计算负载。
4.  **长短请求分流**：将大于32K的长上下文请求分配至专属集群，采用SP序列并行策略处理，避免影响常规请求的响应速度。
5.  **解码加速**：采用Speculative Decoding推测解码方案，通过小模型预测、大模型验证，将生成速度从50token/s提升至120token/s，相关方案已在SpecFog社区开源。

针对Agent RL训练的性能瓶颈，蚂蚁团队通过架构解耦实现了全流程耗时的大幅优化：
| 优化项 | 优化前耗时 | 优化后耗时 |
| :--- | :--- | :--- |
| Rollout阶段 | 1200s | 960s |
| Reward计算 | 600s | 120s |
| Reshard操作 | 800s | 48s |

该团队是全球首个开源FP8训推方案、QAT训练方案的团队，在行业内率先公开了整套Agent RL技术栈，填补了社区的技术空白。
