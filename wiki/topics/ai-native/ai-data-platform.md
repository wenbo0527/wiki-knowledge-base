# 数据资产平台 + AI Agent 综述
## 数字社区产品域 (PD-DFD + PD-DMT) 综合介绍

---

## 一、开篇：核心瓶颈与破局

### 1.1 行业背景

随着企业数字化深入，数据平台建设日趋完善。**传统数据产品的核心功能（数据采集、存储、计算、可视化）已基本完备**。

然而，功能完备并不等于数据真正好用。

### 1.2 核心瓶颈：元数据维护依赖人工

> **当功能不再是瓶颈，维护质量成为了新的瓶颈。**

| 维护对象 | 问题表现 | 根因 |
|:---|:---|:---|
| **字段说明** | 大量字段无注释，或注释不准确 | 开发人员精力有限，无法逐一维护 |
| **口径说明** | 同一指标多个口径，口径不统一 | 缺乏标准定义，业务理解不一致 |
| **版本历史** | 字段变更无记录，影响分析判断 | 缺乏变更追踪机制 |
| **业务映射** | 技术字段无法映射到业务实体 | 开发不懂业务，业务不懂技术 |
| **数据权限** | 数据访问权限不清晰，敏感数据难以管控 | 缺乏统一权限分级体系 |
| **敏感数据** | 敏感字段未脱敏，合规风险高 | 缺乏自动识别和脱敏机制 |
| **合规风控** | 语义检索缺乏风控过滤，合规风险 | 缺乏合规语义校验能力 |

**核心矛盾**：
- 开发人员有限 → 无法承担大量维护工作
- 开发对业务理解不足 → 即使有时间也难以准确维护
- 维护质量差 → 数据难以有效支持业务决策
- 金融合规要求高 → 敏感数据权限、脱敏处理缺失

### 1.3 破局关键：AI Agent 辅助维护

> **AI Agent 的核心价值不是替代人类，而是解决「人工维护做不到、做不好」的元数据质量问题。**

| 传统方式 | AI Agent 增强 |
|:---|:---|
| 开发手动填写字段说明 | AI 根据代码上下文自动生成，开发者审核确认 |
| 业务方口述口径，开发猜测实现 | AI 解读 SQL 逻辑生成口径，业务确认准确性 |
| 人工建立字段-业务映射 | AI 基于命名规范和使用场景智能推荐，业务验证采纳 |
| 变更历史手动记录 | AI 自动追踪变更，生成变更说明 |
| 敏感数据未脱敏 | AI 自动识别敏感字段，触发合规审核 |
| 权限管理粗放 | AI 建立数据权限分级，支撑合规检索 |
| 语义检索无风控 | AI 合规语义校验，过滤敏感信息 |

### 1.4 Human in the Loop：AI辅助，人类决策

> **AI 是辅助工具，人类保持最终决策权。同时，人类还需要主动维护 AI 的学习素材。**

**核心原则**：
```
AI 负责：生成、推荐、补全、分析
人类负责：审核、确认、修订、决策
人类还需：维护知识库、案例库、样例代码库（AI 的学习素材）
```

**人类需要维护的四大知识库**：

| 知识库 | 内容 | 作用 | 维护者 |
|:---|:---|:---|:---|
| **知识库（业务概念）** | 业务术语定义、概念层级、业务实体映射、口径说明、数据标准文档 | AI 理解业务语义、完成业务↔技术对齐的基础 | 业务分析师 + 数据产品 |
| **案例库** | 历史问题解决案例、口径争议处理记录、数据质量修复案例 | AI 学习同类问题的处理方式 | 数据工程师 + 分析师 |
| **样例代码库** | 常用 SQL 模板、数据处理脚本、ETL 任务样例 | AI 生成 SQL 的参考素材，提升生成质量 | 数据开发 |

**Human in the Loop 流程**：
```
┌─────────────────────────────────────────────────────────────────┐
│                人类维护的知识库（业务概念/案例/代码）             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
              AI Agent 利用业务概念知识库学习业务语义
                              ↓
              AI Agent 生成业务↔技术对齐推荐
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                     人类审核与反馈                               │
│   审核结果 → 确认/修订 → 生效 + 反馈补充到知识库                │
└─────────────────────────────────────────────────────────────────┘
```

### 1.5 当前阶段：零起点，无 Agent

> **现状：PD-DFD + PD-DMT 功能建设进行中，AI Agent 能力尚未建设。**

| 现状 | 说明 |
|:---|:---|
| **数据发现 (PD-DFD)** | 已实现基础检索、预览、收藏；语义搜索/AI找数 已规划 |
| **数据管理 (PD-DMT)** | 元数据采集/维护进行中；AI增强能力 未规划 |
| **AI Agent** | **尚未建设**，是下一阶段重点方向 |

**本文目的**：明确 AI Agent 建设方向，规划从「无 Agent」到「Agent 辅助」再到「Agent 增强」的演进路径。

### 1.6 核心价值主张

| 价值关键词 | 内涵 |
|:---|:---|
| **可感知** | AI 辅助维护，让元数据真正完整、准确、可理解 |
| **可推理** | AI 理解业务语义，建立技术到业务的映射 |
| **可合规** | AI 支撑金融数据权限分级、敏感数据脱敏、合规语义校验 |
| **可行动** | AI 辅助分析，人类决策，闭环执行 |

## 二、产品定位：数据资产 + AI Agent 双轮驱动

### 2.1 定位概述

> **数据资产平台是基础，AI Agent 是增强。两者协同，让数据从「能用」到「好用」。**

```
┌─────────────────────────────────────────────────────────────────────┐
│                         数字社区数据平台                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌─────────────────────────────────────────────────────────┐     │
│   │              数据资产层（PD-DFD + PD-DMT）               │     │
│   │  ┌──────────────┐    ┌──────────────┐                   │     │
│   │  │ PD-DFD      │    │ PD-DMT      │                   │     │
│   │  │ 数据发现     │    │ 数据管理     │                   │     │
│   │  │ 找数据       │    │ 管数据       │                   │     │
│   │  └──────────────┘    └──────────────┘                   │     │
│   └─────────────────────────────────────────────────────────┘     │
│                              ↓                                      │
│   ┌─────────────────────────────────────────────────────────┐     │
│   │              AI Agent 层（待建设）                       │     │
│   │  ┌──────────────┐    ┌──────────────┐                   │     │
│   │  │ 智能找数     │    │ 智能补全     │                   │     │
│   │  │ NL2SQL      │    │ 口径解读     │                   │     │
│   │  └──────────────┘    └──────────────┘                   │     │
│   └─────────────────────────────────────────────────────────┘     │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 两大产品域定位

| 产品域 | 定位 | 核心职责 |
|:---|:---|:---|
| **PD-DFD 数据发现** | 找数据、看数据 | 多维度检索、数据预览、血缘关系、资产目录 |
| **PD-DMT 数据管理** | 管数据、用数据 | 元数据管理、数据标准、数据服务、数据质量 |

### 2.3 AI Agent 定位

> **AI Agent 是数据资产的「智能增强层」，核心是解决元数据维护的人工瓶颈。**

| 能力层级 | 名称 | 说明 |
|:---|:---|:---|
| **L1** | 基础交互层 | 搜索、导航、预览(当前能力) |
| **L2** | 资产感知层 | 表/字段发现、血缘追溯、质量感知 |
| **L3** | 语义理解层 | 利用业务概念知识库对齐业务↔技术语言 |
| **L4** | 智能分析层 | 归因分析、预测分析、异常检测 |
| **L5** | 自主行动层 | 自动补全、自动修复（远期目标） |

**注**：当前所有 AI Agent 能力均为 **L1 起步**，L2-L5 是演进方向。

## 三、核心架构：五层架构 + AI Agent 嵌入

### 3.1 五层架构

| 层级 | 名称 | 核心功能 | 对应产品 |
|:---:|:---|:---|:---|
| **L1** | 数据源层 | 原始数据接入（CDC、批量、实时） | 外部系统 |
| **L2** | 数据存储层 | 数据持久化（OLAP、OLTP、文件） | ClickHouse、MySQL |
| **L3** | 数据目录层 | 元数据管理、血缘、质量、标准 | **PD-DMT（元数据核心层）** |
| **L4** | 数据服务层 | 能力封装（API、SDK、编排） | **PD-DMT（服务层）** |
| **L5** | 数据应用层 | 用户交互（门户、ChatBI、工具） | **PD-DFD（应用层）** |

### 3.2 架构图

```
┌─────────────────────────────────────────────────────────────────────┐

│  └──────────────────────────────────────────────────────────────┘  │
│                              ↓                                      │
│  L3 目录层（元数据核心层）                                          │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  PD-DMT 元数据管理 + AI Agent 智能增强                        │  │
│  │  ┌─────────────────┐  ┌─────────────────────────────────┐  │  │

│  └──────────────────────────────────────────────────────────────┘  │

```

### 3.3 AI Agent 在架构中的位置

> **AI Agent 嵌入 L3 目录层，核心解决元数据维护的人工瓶颈。**

**AI Agent 依赖的四大知识库**（需人类提前维护）：
| 知识库 | 内容 | AI 作用 |
|:---|:---|:---|
| **知识库（业务概念）** | 业务术语、概念层级、业务实体映射、口径说明、数据标准 | AI 理解业务语义、完成业务↔技术对齐的基础 |
| **案例库** | 历史问题解决、口径争议处理、质量修复案例 | AI 学习同类问题的处理方式 |
| **样例代码库** | SQL 模板、数据处理脚本、ETL 样例 | AI 生成 SQL 的参考素材 |

| AI Agent 能力 | 嵌入位置 | 解决的问题 |
|:---|:---|:---|
| **智能补全** | L3 元数据管理 | 开发人员精力有限，无法逐一维护字段注释 |
| **口径解读** | L3 标准管理 | 口径不统一，业务理解不一致 |
| **业务↔技术对齐** | L3 业务概念知识库 | 开发不懂业务，业务不懂技术；AI 利用业务概念知识库完成对齐 |
| **变更追踪** | L3 版本管理 | 变更历史无记录，影响分析判断 |

### 3.4 与 Databricks Data Agent 架构对比

| 维度 | Databricks | 我们的架构 |
|:---|:---|:---|
| **数据层** | Delta Lake + Vector Search | ClickHouse + Neo4j |
| **元数据层** | Unity Catalog 原生管理 | PD-DMT 元数据管理 |
| **AI Agent 框架** | Mosaic AI + LangGraph | 待建设 |
| **治理方式** | Unity AI Gateway | API 网关 + 权限控制 |
| **评估体系** | MLflow + AI Judges | 待建设 |

**借鉴点**：
- 将向量检索能力引入，实现语义搜索
- 封装常用操作为可治理函数
- 建立查询质量和解释质量评估机制

## 四、核心能力：六维能力体系（解决元数据维护问题）

### 4.1 能力总览

> **六维能力围绕「解决元数据维护人工瓶颈」展开，AI 是增强手段，Human in the Loop 是核心原则。**

| 维度 | 核心能力 | 当前状态 | AI 增强方向 |
|:---|:---|:---|:---|
| **感知** | 找数据、看数据 | 🟢 已实现 | +语义搜索、智能推荐 |
| **推理** | 理解业务语义 | 🟡 部分实现 | +口径解读、业务↔技术对齐 |
| **行动** | 自助使用数据 | 🟡 部分实现 | +NL2SQL、自动补全 |
| **反思** | 质量评估改进 | ⏸️ 已规划 | +异常检测、归因分析 |
| **记忆** | 知识沉淀追踪 | 🟡 部分实现 | +版本自动追踪 |
| **治理** | 金融合规风控 | 🟡 部分实现 | +权限分级、敏感脱敏、合规校验 |
| **协作** | 跨系统协同 | ⏸️ 已规划 | +多Agent协同 |

### 4.2 感知层：智能发现元数据

**当前能力**：
- 关键词精确检索
- 标签筛选
- 血缘关系查看（已规划）

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **语义搜索** | 自然语言理解，无需精确关键词 | AI 推荐结果，人类判断相关性 |
| **智能推荐** | 基于使用历史推荐相关表/字段 | AI 推荐理由，人类确认采纳 |
| **字段热度** | 智能识别高频使用字段 | AI 标记异常，人类分析原因 |

### 4.3 推理层：理解业务语义

**当前能力**：
- 字段注释（静态）
- 血缘关系图（已规划）

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **口径解读** | AI 解读 SQL 逻辑，生成自然语言口径说明 | AI 生成口径，人类（业务）确认准确性 |
| **业务↔技术对齐** | AI 利用业务概念知识库，建立技术字段到业务实体的映射关系 | AI 推荐映射，人类（业务）验证正确性 |
| **血缘推理** | AI 基于命名规范和使用场景推断血缘 | AI 推断血缘，人类确认采纳 |

### 4.4 行动层：自助使用数据

**当前能力**：
- 数据预览（前 N 条）
- 权限申请

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **NL2SQL** | 自然语言转 SQL，查询数据库 | AI 生成 SQL，人类审核后执行 |
| **智能补全** | AI 自动补全字段注释、标签、描述 | AI 推荐内容，人类确认采纳 |
| **指标生成** | AI 基于字段组合生成指标定义 | AI 生成指标，人类（业务）确认口径 |

### 4.5 反思层：质量评估改进

**当前能力**：
- 数据质量规则配置（部分实现）

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **异常检测** | AI 自动发现数据异常（突增/突降/缺失） | AI 告警，人类判断是否处理 |
| **归因分析** | AI 分析异常原因，给出建议 | AI 推断原因，人类确认并执行 |
| **质量评分** | AI 评估资产健康度 | AI 评分，人类审核调整权重 |

### 4.6 记忆层：知识沉淀追踪

**当前能力**：
- 版本管理（静态记录）
- 收藏功能

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **变更追踪** | AI 自动追踪表/字段变更，生成变更说明 | AI 记录变更，人类确认版本 |
| **历史回溯** | AI 还原历史某时刻的元数据状态 | AI 推断历史，人类确认准确性 |
| **知识积累** | AI 沉淀问答记录 + 从人类维护的知识库/案例库/样例代码库中学习，持续优化 | AI 学习成长，人类纠正错误+补充素材 |

### 4.7 协作层：跨系统协同

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **多Agent协同** | 数据Agent + 营销Agent + 风控Agent 协同 | 人类定义协作规则，审核跨Agent结果 |
| **跨系统映射** | AI 建立不同系统间实体的映射关系 | AI 推荐映射，人类确认 |

### 4.8 治理层：金融合规风控

> **金融行业对数据权限、脱敏、合规检索有高要求。AI Agent 需内嵌合规风控能力。**

**AI 增强方向**：

| 能力 | 说明 | Human in the Loop |
|:---|:---|:---|
| **数据权限分级** | AI 自动识别数据敏感等级，支撑分级授权 | AI 推荐权限等级，人类审批 |
| **敏感数据脱敏** | AI 自动识别敏感字段，触发脱敏处理 | AI 标记脱敏规则，人类确认 |

#### 5.2.5 业务概念知识库（Business Concept）

> **业务概念知识库是 AI Agent 完成「业务↔技术对齐」的核心基础。**

**定位**：业务概念知识库是**人类维护**的知识库，定义业务术语、概念层级、业务实体映射，供 AI Agent 学习使用。

**核心价值**：解决「开发不懂业务，业务不懂技术」的核心矛盾。

| 知识库内容 | 说明 | AI Agent 作用 |
|:---|:---|:---|
| **概念定义** | 业务术语、概念层级、业务实体定义 | AI 理解业务语义 |
| **概念映射** | 字段/指标 → 业务概念的映射关系 | AI 完成业务↔技术对齐 |
| **概念层级** | 业务概念的层级树（父/子概念） | AI 理解业务上下文 |
| **概念版本** | 概念变更历史记录 | AI 追踪业务演进 |

**AI Agent 利用方式**：
```
用户：「查询我行存款情况」
    ↓
AI Agent 利用业务概念知识库：
  - 识别「存款」= 业务概念
  - 映射到字段：balance_amt, deposit_type
  - 生成准确的口径说明
    ↓
人类（业务）确认映射正确性
```

**维护者**：业务分析师 + 数据产品（Human in the Loop）

## 六、落地路径：数据成熟度前置 + 四阶段演进

### 6.1 前置条件：数据成熟度评估

> **AI Agent 效果依赖元数据质量。元数据质量不达标，AI Agent 效果等于零。**

#### 数据成熟度五维评估

| 维度 | L1(初始) | L2(探索) | L3(规范) | L4(优化) | L5(自适应) |
|:---|:---|:---|:---|:---|:---|
| **元数据** | 无 | 人工维护 | 自动采集 | 智能补充 | 实时同步 |
| **质量** | 无监控 | 人工检查 | 规则监控 | 自动预警 | 自动修复 |
| **口径** | 不统一 | 部分统一 | 标准定义 | 自动校验 | 智能解释 |
| **血缘** | 无 | 人工梳理 | 工具构建 | 智能推断 | 实时追踪 |
| **服务** | 手动API | 标准化API | 托管服务 | 自动扩缩容 | 零运维 |
| **知识库** | 无 | 人工维护 | 工具辅助 | 智能补充 | 自动学习 |
| **业务概念** | 无 | 人工定义概念 | 概念↔字段映射 | 智能推断映射 | 自动对齐 |
| **数据权限** | 无 | 人工授权 | 权限分级 | 智能识别 | 自动授权 |
| **敏感脱敏** | 无 | 手动脱敏 | 规则脱敏 | 自动识别 | 智能脱敏 |
| **合规校验** | 无 | 人工检查 | 规则校验 | 自动校验 | 智能拦截 |

#### 阶段-成熟度对照

| 阶段 | 最低成熟度要求 |
|:---|:---|
| **阶段一（增强搜索）** | 元数据 L2，质量 L2，权限 L2 |
| **阶段二（智能查询）** | 元数据 L3、口径 L3、血缘 L3、业务概念 L2，敏感脱敏 L2 |
| **阶段三（主动分析）** | 质量 L4、口径 L4、业务概念 L3，权限 L3，合规 L2 |
| **阶段四（自主行动）** | 全部达到 L4+ |
