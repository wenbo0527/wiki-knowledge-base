### **🤖 Claude Code核心应用场景（背景）**

**选择动因**
- **从ChatGPT到Claude**：因Claude在写作辅助方面表现更优（尽管差距正在缩小）。
- **工程能力升级**：因项目需接入生产环境，从AWS管理控制台转向VS Code开发，发现Claude Code可在终端直接集成，实现"结对编程"模式。
- **数据自主权**：担忧第三方工具（如Trello）的数据锁定问题，转向自建系统。

### **📋 任务管理系统：从Trello到自定义工作流**

#### **(一) 核心痛点与解决方案**
- **原有痛点**：Trello数据导出困难、搜索功能弱、界面操作繁琐（需14步创建任务）。
- **新系统架构**：
  - **载体**：Obsidian（Markdown文件管理）+ Claude Code（自动化处理）
  - **核心文件结构**：
    - `tasks/`：存储任务文件（含YAML frontmatter：类型、截止日期、标签）
    - `ideas/`：长期想法存档
    - `bugs/`：问题跟踪

#### **(二) 关键功能实现**
- **Slash命令**：自定义`/today`命令，每日生成任务摘要：
  - 检查Trello团队协作内容（过渡期）
  - 汇总当日到期任务、逾期任务、进行中的想法
  - 生成研究摘要待办事项
- **自动化标签**：Claude根据任务内容自动生成标签，避免手动分类负担
- **快速任务创建**：自然语言输入直接生成结构化任务文件，无需界面操作

| 对比维度 | 传统工具（Trello） | Claude+Obsidian系统 |
| :------- | :----------------- | :------------------ |
| **数据控制权** | 第三方平台锁定 | 本地Markdown文件 |
| **操作效率** | 多步骤GUI操作 | 自然语言即时创建 |
| **搜索能力** | 基础文本搜索 | 上下文理解+多维度关联 |
| **自动化程度** | 无 | 标签生成/任务汇总/跨文件关联 |

### **🔬 学术研究自动化工作流**

#### **(一) 系统架构**
- **信息源**：arXiv（每日）+ Google Scholar（每周）
- **技术实现**：Python脚本（Cron任务调度）+ Claude Code
- **文件结构**：
  - `research/[topic]/sources/`：存储PDF论文
  - `research/[topic]/notes/`：Claude生成的结构化摘要

#### **(二) 工作流程**
1. **每日搜索**：基于自定义关键词自动检索学术论文
2. **人工筛选**：5-10分钟/天浏览摘要，下载相关PDF
3. **自动摘要**：Claude生成包含**研究方法、效应量**等专业维度的详细总结
4. **知识应用**：通过摘要快速识别研究质量，如发现某论文"使用不可靠的购买意向测量方法"

### **🧠 上下文管理系统：LLM的"外部大脑"**

#### **(一) 核心原则**
- **最小化上下文**：避免无关信息干扰，采用"小文件+索引"模式
- **动态加载**：根据任务类型（业务/个人）自动调用相关上下文文件

#### **(二) 关键上下文文件**
- **写作风格指南**：包含博客/书籍写作差异、标题策略、禁用表达等
- **业务档案**：产品详情、营销渠道、受众画像、品牌规范
- **个人档案**：偏好设置、常用短语、沟通风格

#### **(三) 维护方法**
- **会话结束反思**：每次交互后询问Claude："今日需记录哪些新信息？"
- **迭代优化**：通过持续反馈调整上下文文件内容

### **✍️ 写作辅助应用**
- **主要角色**：**评论者而非创作者**，90%内容仍为原创
- **具体功能**：
  - 事实核查：验证写作中的论断
  - 钩子优化：增强文章开头吸引力
  - 风格校正：基于自定义指南提供针对性反馈
  - 拼写纠错：适配"美甲打字困难"等场景
