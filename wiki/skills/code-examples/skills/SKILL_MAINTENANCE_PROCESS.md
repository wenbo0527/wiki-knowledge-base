# 🔄 Skill持续维护机制

> **建立时间**: 2026-04-30
> **维护者**: 尼克·弗瑞 🕵️
> **协调者**: 派蒙 🤝

---

## 一、核心目标

**建立有效的Skill维护机制，让大家越来越好**

| 目标 | 说明 |
|------|------|
| **保持精简** | 只保留真正有用的Skill |
| **持续优化** | 定期评估，及时改进 |
| **避免重复** | 功能重复时合并，而非堆积 |

---

## 二、评估维度

### 2.1 四维评价模型

| 维度 | 问题 | 权重 |
|:---|:---|:---:|
| **能自动化** | 这个Skill能自动执行吗？ | 25% |
| **有人使用** | 最近30天被调用过几次？ | 25% |
| **功能独特** | 有其他Skill替代吗？ | 25% |
| **持续评估** | 能定期复审优化吗？ | 25% |

### 2.2 mgechev最佳实践

| 原则 | 说明 |
|:---|:---|
| SKILL.md < 500行 | 保持精简 |
| 渐进式披露 | 案例移至references/ |
| 触发词优化 | Use when + Don't use for |
| scripts/确定性 | 重复操作脚本化 |

---

## 三、评估节奏

### 3.1 每日

| 动作 | 执行 | 输出 |
|------|------|------|
| Skill调用记录 | 自动(系统) | skill-usage.log |

### 3.2 每周

| 日期 | 动作 | 执行人 |
|------|------|--------|
| 每周一 09:00 | 异常检查 | 派蒙 |

**异常检查清单**:
- [ ] 有零调用的Skill吗？（连续7天）
- [ ] 有高频失败的Skill吗？（失败率>50%）
- [ ] 有触发词误匹配的记录吗？

### 3.3 每月

| 日期 | 动作 | 执行人 | 输出 |
|------|------|--------|------|
| 每月最后周一 | 四维评分复审 | 尼克 | SKILL_SCORING_REPORT.md |

**月度复审检查清单**:
- [ ] 所有SKILL.md是否<500行
- [ ] references/scripts是否需要更新
- [ ] 触发词是否需要优化（正例+反例）
- [ ] 是否有可合并的重复Skill
- [ ] 是否有废弃Signal的Skill

### 3.4 每季度

| 日期 | 动作 | 执行人 | 输出 |
|------|------|--------|------|
| 季度末周 | 去留决策 | 派蒙+文博 | 决策报告 |

**季度决策清单**:
- [ ] 有哪些Skill需要废弃？
- [ ] 有哪些Skill需要合并？
- [ ] 有哪些新Skill需要创建？
- [ ] Skill评分标准是否需要调整？

## 四、状态流转

### 4.1 状态定义

| 状态 | 标识 | 说明 |
|------|------|------|
| **活跃** | 🟢 | 持续使用，定期更新 |
| **待改进** | 🟡 | 低于80分，需要优化 |
| **待处理** | 🔴 | 连续3个月无调用或严重问题 |

### 4.2 流转规则

```
🟢活跃 ───(3个月无调用)───→ 🟡待改进
   │                           │
   │                      (优化后达标)
   │                           │
   │←────────────(继续使用)─────┘
   │
   │──(完全重复/无价值)──→ 🔴待处理
   │                           │
   │                      (派蒙+文博决策)
   │                           │
   │←────────(保留/废弃)────────┘
```

---

## 五、优化行动

### 5.1 立即行动标准

满足以下任一条件，立即优化：

| 条件 | 行动 |
|------|------|
| SKILL.md > 500行 | 精简到500行内 |
| 无触发词优化 | 添加"Use when"+"Don't use for" |
| 无references/ | 创建references/目录，移入案例 |

### 5.2 合并标准

满足以下条件，考虑合并：

| 条件 | 合并方案 |
|------|----------|
| 功能完全重复 | 合并到评分更高的Skill |
| 是另一个Skill的子流程 | 合并到主流程Skill |
| 只是触发词不同 | 合并，保留不同触发词 |

### 5.3 废弃标准

满足以下条件，考虑废弃：

| 条件 | 废弃方案 |
|------|----------|
| 连续3个月零调用 | 归档到archived/ |
| 功能完全被其他Skill覆盖 | 归档 |
| 内容太薄（<50行）且价值低 | 归档或合并 |

## 六、归档管理

### 6.1 归档位置

```
wiki/code-examples/skills/archived/
├── tony-zhongli-collaboration-SKILL.md
├── git-workflow-SKILL.md
└── ...
```

### 6.2 归档命名

```
{skill-name}-SKILL.md
```

### 6.3 归档记录

每次归档需要记录：
- 归档日期
- 归档原因
- 合并到哪个Skill（如果有）
