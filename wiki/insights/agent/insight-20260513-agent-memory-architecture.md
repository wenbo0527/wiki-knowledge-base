## 一、核心问题

### 关键命题
> 过去的信息凭什么继续影响未来？

### 工程痛点
- 旧的、错的、过期的经验会隐性误导Agent决策，且不会显式报错
- 从上下文操作权 → 长周期Agent → 最终聚焦于Memory的治理难题

---

## 二、核心结论速览

| 核心观点 | 具体内容 |
|:---|:---|
| **Memory的本质** | 跨会话持续存在、可更新审计、影响未来决策的结构化历史 |
| **三大核心链路** | 写入（分配未来影响力）、管理（冲突/衰减/遗忘）、读取（转成当前约束） |
| **关键记忆类型** | 任务记忆、环境记忆、自我记忆、用户偏好 |
| **安全风险** | Memory可写即成为持久化攻击面 |
| **落地原则** | 先区分信息生命周期，人能读、Agent能改、系统能审计的工作区文件是Coding Agent的首选 |

## 三、走出Memory认知误区

### 易混淆概念对比

| 概念 | 定义 | 与Memory的区别 |
|:---|:---|:---|
| **上下文窗口** | 当前推理的临时工作集 | 短期、临时，不承担长期存储 |
| **Session** | 管理当前会话连续性 | 仅覆盖单会话，需提炼后才进入Memory |
| **Profile** | 用户低维快照 | 静态视图，缺乏作用域和条件信息 |
| **Policy** | 外部规则（权限/安全/合规） | 不可被Memory改写，仅可引用 |

### Memory的准确定义

> **结构化历史**：跨会话持续存在、可被更新和审计，并且会影响未来决策的信息集合。

核心在于**治理哪些过去能继续影响未来决策**。

---

## 四、Agent Memory的控制闭环

### 写入：给过去分配未来影响力

**核心原则**：写入即预算分配，需明确信息的未来决策权重。

**关键元信息**：
- 内容、类型（事件/声明/推断）
- 来源（用户/工具/Agent）
- 作用域（项目/用户/团队）
- 置信度、时间、状态

**写入规则**：
| 信息类型 | 存储方式 |
|:---|:---|
| 用户声明 | 按assertion存 |
| 工具观察 | 按event存 |
| Agent归纳 | 按belief存 |
| 未验证原因 | 需标记"未确认" |

### 管理：决定哪些信息继续有效

| 挑战 | 处理方式 |
|:---|:---|
| **冲突处理** | 保留上下文差异，按作用域分流 |
| **衰减机制** | 按时间/使用频率降低权重，支持选择性遗忘 |
| **安全治理** | 区分read-only/read-write存储，关键记忆需人工review |

### 读取：把历史转成当前约束

**突破点**：从"语义相似检索"升级为"任务上下文驱动"。

**关键约束**：
- 团队规则（如"禁止改数据库表"）
- 历史事故（如"退款幂等问题"）
- 环境限制（如"CI对慢测试敏感"）

## 五、Memory架构路线对比

| 路线 | 代表方案 | 强项 | 风险点 |
|:---|:---|:---|:---|
| **core memory** | Letta | 稳定低延迟，每轮可见 | 容量过大会污染上下文 |
| **向量存储** | Mem0 | 容量大，语义召回快 | 旧事实误召回，来源不清 |
| **时间图谱** | Zep/Graphiti | 擅长实体关系与演化 | 维护复杂，抽取质量要求高 |
| **文件系统** | Clawdbot（Markdown） | 可读可审计，版本化 | 关系查询能力弱 |
| **自管理** | 模型自主整理 | 随模型能力进化 | 弱模型可能错误管理记忆 |

## 六、Coding Agent的落地实践

### 四层记忆架构

| 层级 | 内容 | 说明 |
|:---|:---|:---|
| **当前工作集** | 上下文窗口 | 当前文件/计划/报错，短期准确即可 |
| **工作区文件** | 版本化文件 | AGENTS.md、GOAL.md、PROGRESS.md、DECISIONS.md |
| **Memory Store** | 长期记忆库 | 跨会话经验/用户偏好/失败路径 |
| **事件日志** | 事实流水 | 工具调用/测试结果/回滚记录 |

### 信息分类存储示例

| 信息类型 | 存储位置 | 管理策略 |
|:---|:---|:---|
| 项目长期规则 | `AGENTS.md` | 版本化，需code review |
| 用户长期偏好 | Memory Store | 可修正，带作用域 |
| 已确认架构决策 | `DECISIONS.md` | 不可随意修改 |
| 某次失败日志 | 事件日志 | 可追溯，关联任务 |

## 七、最小可用Memory设计

1. **规则文件化**：项目规则写入`AGENTS.md`并纳入版本管理
2. **任务状态证据化**：长任务需记录目标、进度、决策、验证记录
3. **记忆类型化**：区分用户声明/环境观察/Agent推断，均带作用域
4. **共享记忆只读化**：外部输入默认写入草稿区，需确认后进入长期记忆
5. **可观测性**：支持浏览/搜索/编辑/删除记忆，关键操作可追溯
6. **错误反馈闭环**：发现记忆误导时，需修正记忆的作用域/有效期
7. **全面评估**：除召回率外，需测试更新/遗忘/拒答能力

## 九、认知更新

### 旧认知
- Memory = 聊天记录或数据库
- Memory越多越好

### 新认知
- Memory是治理过去影响未来的机制
- 需要区分生命周期和信息类型
- 可审计性比容量更重要
